# TradingView 작업 화면 재조사와 설계 근거

조사일: **2026-10-22**. 대상: Bitcoin Cycle Atlas의 상단, 좌측, 중앙 차트, 우측, 하단. 이 문서는 공식 자료에서 확인한 사실과 v1.5에 적용한 설계·검수 조건을 기록한다. 실제 브라우저 결과와 아직 Pending인 공개 실행은 [검증 기록](FIVE_REGION_VERIFICATION.md)에서 구분한다. 이 설계 문서 자체를 배포 성공의 증거로 사용하지 않는다.

## 조사 범위와 자료의 구분

TradingView Help Center는 실제 Supercharts 제품의 메뉴와 사용자 동작을 확인하는 데 사용했다. Pine Script 릴리스 노트는 패널 위치가 바뀐 시점을 확인하는 데 사용했다. Advanced Charts와 Lightweight Charts 문서는 범례·축·십자선의 동작 원리를 확인하는 보조 자료다. 라이브러리의 모든 옵션이 현재 Supercharts의 같은 위치에 있다는 뜻은 아니다. 공식 문서의 제품 구성은 계정, 화면 크기, 업데이트에 따라 달라질 수 있으므로 과거 스크린샷의 위치를 그대로 고정하지 않는다.

이번 설계는 자체 SVG 차트에 필요한 공간 규칙을 적용한다. TradingView 라이브러리 도입, 상표 복제, 실시간 시세 연결을 의미하지 않는다. 기존 금융 모형의 입력과 가정에 관한 판단은 [MODEL_SCOPE.md](MODEL_SCOPE.md)를 따른다. 화면이 전문적인 차트 도구처럼 보이는 것과 미래 예측의 정확도는 별개의 문제다.

상단의 **일별·주별은 데이터 표시 간격**, 하단의 **기간 버튼은 화면에 보이는 시간 범위**다. 같은 숫자나 아이콘으로 두 기능을 혼동하게 만들지 않는다. 제공하지 않는 분봉, 시간봉, 다른 자산의 검색 기능을 암시하는 버튼은 넣지 않는다. 비가격 그래프에서는 적용되는 제어만 보이게 한다.

### 하단 패널에 관한 최신 변경

2025년 8월 공식 릴리스 노트는 Pine Editor를 하단에서 우측 패널로 단계적으로 옮긴다고 설명한다. 기본은 우측 overlay이며, 넓은 화면에서는 차트 너비를 줄여 함께 보는 split view를 제공한다. 이어 2026년 9월에는 스크립트의 표를 하단 별도 탭으로 옮겨 표시하는 기능이 추가되었다. 따라서 TradingView의 하단 확장 패널 전체가 사라졌다고 해석하면 안 된다. [9]

Atlas는 사용자가 요청한 한 화면 구성과 우측 상세 방식을 따라, 하단에는 시간·눈금 조작만 둔다. 자료의 근거 상세와 모델 설명은 우측에 모으고, 리서치·원자료 목록은 별도 표 페이지로 유지한다. 이는 현재 TradingView에 있는 모든 하단 탭을 재현하는 선택이 아니라, 비트코인 사이클 분석에 필요한 역할을 선택한 것이다.

## 이전 화면에서 해결할 문제

개편 전 기준은 v1.4.0의 [화면](https://github.com/twoimo/bitcoin-cycle-atlas/blob/v1.4.0/dist/index.html), [화면 연결](https://github.com/twoimo/bitcoin-cycle-atlas/blob/v1.4.0/dist/viewport-workspace.js), [차트](https://github.com/twoimo/bitcoin-cycle-atlas/blob/v1.4.0/dist/atlas-price-chart.js), [패널 스타일](https://github.com/twoimo/bitcoin-cycle-atlas/blob/v1.4.0/dist/chart-details-panel.css)이다. 당시 우측 상세 패널은 있었지만, 정보·모델·갱신·설정 진입점이 상단에 섞여 있었다. 좌측은 주요 페이지 이동에 쓰여 차트 위에서 무엇을 조작하는지 드러나지 않았고, 표시 간격과 시간 범위를 바꾸려면 설정을 열어야 했다.

이 구조에서는 아이콘 수가 적어도 사용자가 기능을 찾는 위치를 예측하기 어렵다. 개편에서는 같은 역할을 한 방향에 모으고, 활성 도구와 선택된 패널이 눈에 보이도록 한다. 설명 문단을 늘려 사용법을 가르치기보다, 사용자가 누른 도구의 결과가 차트와 가까운 곳에서 즉시 나타나게 한다.

중앙의 십자선과 상세 값도 같은 선택 상태를 공유해야 한다. 마우스가 가리키는 날짜와 패널의 고정 날짜가 다르면 고정 여부를 분명히 표시한다. 패널을 닫은 상태에서 호버만으로 패널이 자동으로 열리게 하지 않는다. 확대·이동·패널 전환은 이미 선택한 날짜를 뜻하지 않게 바꾸지 않아야 한다.

## 설계 선택과 구현 조건

### 차트와 데이터 읽기

범례는 차트 좌상단에 짧게 유지한다. 보유 자료는 일별 PriceUSD이므로 관측 날짜, 가격, 변화와 표시 간격을 보여 준다. 없는 시가·고가·저가·거래량으로 캔들을 만들지 않는다. 미래를 선택하면 같은 위치에 **가정**을 표시한다. 가격축 라벨과 시간축 라벨은 같은 데이터 지점에서 계산한다. 데이터 지점에 붙는 십자선은 임의의 화면 좌표를 실제 관측값으로 오해하는 일을 줄이는 데 적합하다. [3][6]

관측은 실선, 미래 예시는 점선으로 구분하고 음영의 의미는 레이어와 모델 패널에서 확인하게 한다. 고점·저점 후보와 D-day는 차트 안에 두되, 전체 후보 기간과 산출 근거는 우측으로 연다. 색 하나만으로 실제·가정을 구별하지 않는다. 세로축을 로그에서 선형으로 바꾸면 눈금과 선의 좌표를 함께 바꾸며, 선택 가격 자체는 바꾸지 않는다.

두 지점 측정은 시작·끝 날짜의 차이, 가격 차이, 변화율을 계산한다. 미래 구간을 포함한 측정에는 가정값을 포함했다는 구분이 필요하다. 측정 도구를 선택한 상태와 이동 도구를 선택한 상태가 명확해야 하며, 드래그가 의도하지 않은 값 선택이나 패널 열기로 이어지지 않아야 한다. 측정 삭제와 보기 초기화의 효과도 구분한다.

### 우측 레일과 상세

같은 아이콘을 다시 누르면 닫고, 다른 아이콘을 누르면 기존 패널의 내용만 바꾼다. 한 번에 하나의 상세만 열며 중앙 모달을 추가하지 않는다. 900px보다 넓으면 차트가 패널 너비만큼 줄어들고, 900px 이하에서는 우측 overlay를 사용한다. 도킹 기본 폭은 320px이며 경계 조절은 280–420px 안에서 차트 최소 480px을 남기도록 제한한다. 겹침 상태에서는 main과 좌측 도구를 비활성화하고 Tab을 패널·우측 레일 안에서 순환시킨다. 이 방식은 차트를 가리지 않고 도구를 함께 쓰는 split view의 목적을 차용한 것이다. [8]

레이어에는 미래 범위, 고저점, 낙폭, 국면, 되돌림 표시를 모은다. 이는 차트 요소를 표시·숨김으로 관리하는 Object tree의 역할을 단순화한 것이다. [7] 체크 상태는 패널을 바꾸거나 다시 열어도 유지하고, 현재 그래프와 무관한 항목을 조작 가능하게 남기지 않는다. 데이터와 리서치를 볼 때도 차트로 돌아가는 경로가 같은 위치에 있어야 한다.

아이콘에는 한국어 접근성 이름과 툴팁을 두고, 열림 상태와 선택 상태를 프로그램으로 전달한다. Escape와 닫기 버튼은 같은 결과를 내야 하며, 닫은 뒤 포커스는 진입 버튼 또는 차트로 복원한다. 작은 화면에서도 닫기 버튼과 마지막 조작이 잘리지 않아야 한다.

### 하단과 갱신 상태

기간과 날짜 이동은 실제 표시 범위를 바꿔야 한다. 가격축은 현재 화면에 보이는 값을 기준으로 자동 조절한다. 하단 ‘자동’은 이 상태를 설명하는 텍스트이며 누르는 버튼이 아니다. 별도의 맞춤 아이콘은 기본 표시 기간을 복원하며, 설정의 ‘처음 화면’은 표시 설정 전반을 초기화한다. 차트 도구의 확대·이동·초기화는 공식 설정 안내에서도 별개의 탐색 기능으로 다뤄진다. [10]

차트의 날짜 기준은 UTC로 유지한다. 자동 갱신 시각은 KST로 표시하되 관측일과 구분한다. 갱신 작업이 오늘 수행됐다고 오늘의 가격이 관측되었다고 표시하지 않는다. 긴 갱신 설명은 우측 상세에서 확인하고, 기본 화면에는 시각과 상태만 남긴다.

## 제외할 기능

매수·매도, 호가, 브로커 연결, 주문·잔고, 실시간 거래 알림, Pine 코드 편집, 다중 자산 관심목록은 이번 범위에 넣지 않는다. 이 서비스에 연결된 데이터나 동작이 없는 버튼은 전문성을 더하지 못하고 실제 거래 기능으로 오해될 수 있다. 표시용 아이콘만 만드는 것도 피한다. 추가 지표를 그릴 때에는 입력 자료와 계산이 먼저 존재해야 한다.
