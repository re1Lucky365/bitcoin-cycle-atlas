## 2. 재무 시나리오에서 고친 문제

기존 확대 조건을 2050년까지 계산하면 MSTR 보유량은 약 **32.25m BTC**, BMNR 보유량은 약 **401.29m ETH**가 됐다. MSTR 결과는 BTC 최종 공급량을 넘는다. BMNR 결과는 경영진의 공급 5% 전략을 고려하지 않은 무제한 축적 결과였다. 같은 입력으로 재현한 수치와 공식 출처의 직접 확인 범위는 [재무 복구 검토](TREASURY_RECOVERY_RESEARCH.md)에 있다.

수정은 코인 수량뿐 아니라 신주 발행·순조달·현금의 관계에 적용했다.

- MSTR의 보유량에 BTC 최종 공급량 **21m**을 느슨한 산술 경계로 둔다. 현재 유통량·매수 가능 물량·시장 충격을 추정한 상한은 아니다.
- BMNR은 회사가 보고한 **122.1m ETH × 5% = 6.105m ETH**를 고정 보유 조건으로 둔다. 미래 ETH 공급량 예측이나 프로토콜 상한은 아니다. 경영진 전략을 앱이 고정 수량으로 구현한 가정이다.
- 마지막 매입의 신주 수·순조달액을 보유 여력에 맞춰 함께 줄인다. 초과 코인만 삭제하거나 계획 조달액을 그대로 남기지 않는다.
- 상한을 넘는 스테이킹 보상은 앱의 비용 조건으로 현금화한다. 이 동작은 회사의 확약이 아니라 모델 정책 가정이다.
- 잘못된 날짜·중복 주가 세션·주식과 코인 종류의 불일치·산술 overflow와 음수 금융비용이 되는 조정을 거부한다.

공시 사실, 회사 보고 수치, 경영진 전망과 모델 가정을 구분한다. 최신 코인 보유량만 과거 보통주 수·선순위 청구권에 섞어 현재 NAV를 계산하지 않는다. MSTR의 2026-06-30, BMNR의 2026-05-31 재무 기준과 명시된 후속 조정을 유지한다.

**공급 경계를 지킨 계산도 투자 가능성을 입증하지 않는다.** 수정 후 MSTR 2050 확대 조건은 약 $252tn의 누적 순발행 조달을 요구한다. 시장 규모·흡수력·프리미엄 지속성에 대한 제약을 별도로 추정하지 않은 민감도다. [전체 수식과 입력](TREASURY_MODEL.md), [공식 출처·반례·전후 결과](TREASURY_RECOVERY_RESEARCH.md)를 함께 읽어야 한다.

## 3. BTC 검증에서 고친 문제

긴 평가 기간을 추가하면 짧은 기간에 사용할 수 있던 과거 경로까지 사라져, 기존 90일 평가가 누락되거나 오차가 바뀌는 반례를 재현했다. 이제 기간별로 사용할 수 있는 과거 경로를 독립적으로 고르고, 실제 사용한 기준 연도와 마지막 자료 날짜를 각 결과에 남긴다.

날짜 변환이 지원 범위 밖 확장 연도의 앞 10자를 반환하던 문제도 수정했다. 모델 입력을 기준일로 거르기 전에 모든 행의 날짜를 검사하며, 잘못된 날짜나 배열의 빈 슬롯을 조용히 버리지 않는다. 정상적인 미래 관측은 고정 기준일 학습에 사용하지 않는다.

정상 고정 입력에서 상세·장기 모델의 출력은 기준 함수 본문과 깊은 동등 비교가 일치했다. 이 비교는 수정된 입력 경계가 기존 정상 경로를 바꾸지 않았는지를 확인한 것이며, 별도 과거 배포물 전체 실행이나 미래 적중률 검증은 아니다. 실패 반례·검사 방식·숫자 해석은 [BTC 복구 검증](BTC_RECOVERY_VERIFICATION.md)에 남겼다.

## 4. 미래 차트와 근거 읽기

MSTR·BMNR의 계산일 사이로 확대했을 때 화면 안에 월별 계산점이 없다는 이유로 미래선까지 사라지는 경로를 수정했다. 계산점 사이에 표시용 경계점을 만들고 **조건부 가정·보간**으로 구분한다. 표시 축에 따른 보간은 새로운 재무 계산, 실제 체결 또는 미래 OHLC가 아니다.

주봉의 시작일을 미래 시나리오의 기준일로 혼동하지 않도록, 모델의 실제 `asOf`와 시작 가격을 연결 기준으로 사용한다. 잘못된 날짜·중복·역순·유효하지 않은 가격 범위는 차트 자료 경계에서 검사한다. 선·캔들 선택에서도 실제 관측 OHLC와 조건부 미래선의 의미를 분리한다.

근거 읽기 링크의 원문 모드는 주식 화면을 처음 여는 경우에도 전달한다. 요약과 원문 전환으로 종목·검색·분류 조건을 잃지 않도록 한다.

로그축은 양수와 0 사이를 연결하거나 양수 가격으로 대체하지 않는다. 선택 조건의 가격이 0 경계를 지나는 구간은 연결을 생략하고 선형축 안내를 표시한다. 범위 하한만 0 경계를 지날 때에는 중간 하한을 `null`로 남기고 그 구간의 음영을 생략한다. 이를 실제 0 도달 시점으로 앞당겨 표시하지 않는다. 계산값이 모두 0인 구간은 0 값을 유지하고 잔여가치 소진 경고를 표시한다. 차트 관련 4개 파일의 36개 회귀 검사와 독립 코드 검토로 확인했다.

## 5. 이번 복구에서 새로 선정한 허용 원문

공식 EIP-1559와 EIP-3675의 고정 커밋에서 원문 Markdown 전체와 해당 판본의 CC0 라이선스를 읽고 보존했다. **이전 실패 대화의 정확한 두 원문을 회수했다는 뜻은 아니다.** 이 두 자료를 이번 복구에서 선정했음을 [원문 리더 기록](RESEARCH_SOURCE_READER.md)에 명시했다.

원문 두 개는 **43,901바이트**, CC0 라이선스는 **7,048바이트**다. 원본 Git blob SHA, SHA-256, 파일 크기와 UTF-8 왕복 변환을 대조했다. 요약과 원문은 별도 파일·명세·다운로드로 관리한다. 허용 원문이 있는 요약에는 그 파일과 라이선스·해시 링크를 제공하며, 다른 외부 글은 원문 미보관 상태를 유지한다.

단일 Markdown 파일 전체에는 머리말·본문·표·코드 텍스트·저작권 고지가 들어 있다. 연결 문서·웹 화면·영상·이미지까지 복제한 것은 아니다. 원문을 일반 텍스트로 표시하므로 포함 코드·HTML·Markdown이 실행되지 않는다. 출처와 모델 연결, 가격 보장으로 해석할 수 없는 이유는 [보존 안내](RESEARCH_PRESERVATION.md)와 각 연구 글에서 확인한다.

독립 수지 계산은 [별도 재현 스크립트](../scripts/verify-treasury-conservation.mjs)로 MSTR·BMNR의 세 조건을 2050년까지 계산하고 코인·현금·신주 순조달의 수지를 다시 구성했다. 1,694개 활성 단계에는 발행 410단계, 초과 보상 매각 532단계가 포함된다. 저장 결과의 `sourceHashes` 3개와 `inputHashes` 4개가 검산 대상을 식별한다. 최대 절대 차이는 코인 `3.725290298461914e-9`, 현금 `$0.0078125`, 보상 현금 `$0.0000036954879760742188`, 발행 순조달 `$0.079345703125`였다. 허용 오차는 `1e-7 + 64 × Number.EPSILON × 산술 규모`이며 누적 잔액 차감의 규모도 반영한다. 소스·입력이 바뀌면 결과 JSON을 재생성해야 한다.

형식 검사의 첫 도구 다운로드는 Node DNS 오류로 실패했다. 같은 공식 URL에서 환경의 정상 프록시 경로를 쓰는 `curl`로 받은 TLC 1.7.4의 고정 SHA-256을 확인한 뒤 검사를 실행했다. 의도적으로 소유권 가드를 제거한 모형은 예상한 불변식 위반으로, 실제 코드 변이는 예상한 stale-update 단언 실패로 거부됐다. 도구 오류를 통과나 반례로 세지 않았다. [검사 코드](../scripts/verify-market-state.mjs)와 [모형의 범위](formal-state/README.md)를 제공한다.

같은 생성 결과에는 **정식 요약 490개·ID 연결 494개·요약 본문 899,503바이트**, 재무 출처 55개·사건 43개가 있다. 독립 연결 검사에서 주장 대조 70건, 미래 경로·표시의 `sourceId` 참조 10,641건, 재무 출처·사건과 두 허용 원문의 요약·다운로드 연결이 모두 해결됨을 확인했다. 참조 건수는 독립 출처 개수를 뜻하지 않는다. 원문 두 개와 CC0 라이선스는 앞 절의 별도 명세로 관리한다. 단일 HTML의 91개 모듈 수를 테스트 파일 수와 혼동하지 않는다.

독립 수지 계산의 확인 범위와 원문 리더의 Node 검사를 실제 브라우저 실행으로 표현하지 않는다. 실제 페이지, 단일 HTML 오프라인 열람과 릴리스 자산은 같은 소스 커밋을 대상으로 확인해야 한다. 공개 배포·릴리스 상태는 해당 [Actions](https://github.com/twoimo/bitcoin-cycle-atlas/actions)와 [릴리스](https://github.com/twoimo/bitcoin-cycle-atlas/releases)의 실제 결과를 따른다.

## 7. 병렬 수행과 재개 가능성

[`pstack`](https://github.com/cursor/plugins/tree/main/pstack)의 세션 재개·병렬 분담·입력 경계·재현 후 수정·실물 검증 지침을 읽고 적용했다. 재무 모델, BTC 계산, 원문 리더와 통합 차트의 파일 소유권을 나누고 생성·통합·원격 쓰기는 조정 담당자가 처리한다.

기본 지정 모델인 Grok·Opus 대신 이 세션에서 제공된 **GPT-6 Astra 협업 에이전트**를 사용했다. Cursor 전용 `Task`, Grok, Claude Opus, Bugbot 실행을 주장하지 않는다. 과거 자기보고, 협업 검토, 이번 직접 실행과 최종 배포 증거를 같은 수준으로 취급하지 않는다.

저장소에는 모델·리더 변경, 회귀 반례, 입력·출처 명세와 재현 명령을 함께 남긴다. 다른 세션이 이어받을 때는 최신 원격 브랜치·PR·태그를 먼저 조회하고 같은 수정이나 릴리스를 중복 게시하지 않는다.


## 8. 게시 직전 자동 관측 갱신 보존

원격 브랜치를 만들기 직전 `main`을 다시 읽어 자동 갱신 커밋 [`7012cff5c908c1b8db7f94ec36a3b9476fbc9e44`](https://github.com/twoimo/bitcoin-cycle-atlas/commit/7012cff5c908c1b8db7f94ec36a3b9476fbc9e44)을 확인했다. 처음 확인한 기준 커밋 이후 2026-10-24 11:02:19 UTC에 추가된 관측 갱신이다. 아직 복구 커밋·브랜치·PR을 원격에 만들지 않은 상태에서 새 기준 위로 변경을 옮겼다.

MSTR·BMNR의 관측 OHLC와 코인 기준 가격은 그대로였으며, 수집·검증 메타데이터와 BMNR 코인 관측의 수집 시각이 갱신됐다. BTC·ETH 분봉 관측과 거래량 검증 자료의 갱신도 보존했다. 충돌한 재무 카탈로그는 두 연구 입력과 최신 관측에서 다시 생성했다. 검산 결과의 소스·입력 해시도 다시 기록했다.

독립 비교에서 기존 여섯 재무 조건의 숫자 항목 14,336개가 새 결과와 정확히 같았다. MSTR 세 결과는 전체가 같았고, BMNR 세 결과는 `coinAnchor.retrievedAt`만 달랐다. 새 기준에서도 89개 테스트 파일, 연구·정적·사건·사이클·성능·형식 검사, 단일 HTML 생성·검증을 다시 통과했다. 최종 단일 HTML은 41,915,758바이트이며 91개 모듈과 5,942개 일별 가격 관측을 포함한다.

파일 내용은 개별 Git blob으로 보낸 뒤 반환 해시를 로컬과 대조한다. 트리 요청은 본문을 넣지 않은 22개 경로·해시 묶음으로 분리하며 각 중간 트리도 로컬 Git 트리와 비교한다. 원격 브랜치·PR·릴리스의 완료 여부는 이 문서의 계획 대신 실제 조회 결과로 판단한다.
