# 이더리움 역사 사건: 출처와 차트 표시

검토 기준일: **2026-10-24**. 구현 버전: **v1.17.0**. 확장 작업 시작 기준: `28afffc7973725442463a2907e8ba56bfb0ce8c1`.

사용자 요청에 따라 ETHUSD의 실제 가격 차트에 역사 사건 지표를 추가한다. 프로토콜·생태계 사건에 정책·정치·금융·지정학적 맥락을 보강한다. 사건의 날짜·설명·근거와 실제 완료 일봉의 주변 가격 기록을 표시하며, 수학적 가격 모델, 가격 효과 점수, 매매 신호, 미래 사건 또는 미래 가격은 생성하지 않는다. 기존 BTC의 출처·적응형 라벨 배치 방식을 공유한다.

## 조사 기록과 원본성

- [프로토콜 조사](research/ethereum-protocol-history-2026-10-24.md): Ethereum 공식 기술 연대표, 당대 EF 공지, 업그레이드 규격, 완료 후 회고, 실제 블록을 대조한다.
- [보안·시장·생태계 조사](research/ethereum-market-security-2026-10-24.md): EF 보안 공지, SEC 원문, 개발사 사후 보고서, 독립 보안 연구자의 계약 분석, 거래소 상장 기록을 대조한다.
- [초기 역사·프로토콜·네트워크 보안 보강](research/ethereum-protocol-supplement-2026-10-24.md): 2014년 판매, 초기 DoS 대응, 난이도 폭탄 연기, 클라이언트 장애와 최종 확정 지연을 확인한다.
- [관세·미중 무역분쟁 조사](research/ethereum-tariffs-2026-10-24.md): 2018–2020년 무역분쟁, 2025–2026년 관세 발표·시행·유예·합의·법원 판단과 당시 시장 맥락을 대조한다.
- [통화·정치·규제 정책 조사](research/ethereum-policy-2026-10-24.md): 중앙은행, 정부, 법원, 규제기관 원문과 동시대 보도·공식 후속 기록을 대조한다.
- [시장·신용·보안·생태계·지정학 조사](research/ethereum-context-2026-10-24.md): 서비스 운영자, 법원·기관 기록, 직접 온체인 분석과 동시대 보도를 대조한다.
- `research-data/ethereum-{protocol,market,protocol-supplement,tariff,policy,context}-events.json`: 여섯 사건별 검토 입력. 출처 제목·URL·발행자·역할·지원하는 주장, 날짜 정밀도·근거·한계를 보존한다.
- `research-data/ethereum-protocol-block-receipts.json`: 공개 Blockscout API에서 받은 높이·해시·부모 해시·시각 등의 선택 필드. 노드 전체를 독립 재실행한 합의 검증은 아니다.
- `npm run build:eth-events`: 여섯 검토 기록을 읽어 `dist/ethereum-events.js`를 생성한다. `npm run verify:eth-events`는 검토 입력과 배포 카탈로그의 차이를 검출하며 CI·Pages 배포의 필수 검사다. `ETHEREUM_EVENTS`는 중첩 출처까지 동결하며 검색·범위 필터는 이를 변경하지 않는다.

같은 문서의 재배포나 동일 조직의 두 글을 외부의 독립 증거 두 개로 세지 않는다. 예를 들어 Uniswap v1·v2의 정확한 일자는 창시자 회고·당일 공지에 의존하고, 다른 공식 문서는 연월을 보강한다. 해당 한계는 차트의 사건 상세에도 표시한다. 모든 사건은 최소 두 개의 출처 문서를 가지지만, 그 숫자가 독립된 기관의 수나 확률적 신뢰도를 뜻하지 않는다.

이 목록은 2014년부터 검토일까지 출처를 확인한 주요 사건의 편집 목록이며 자동 뉴스 피드나 모든 사건의 완전한 열거는 아니다. 생태계 사건은 원문을 확인할 수 있는 공개·거래 이정표 중심이며 전체 DeFi·NFT·L2 프로젝트를 대표하는 순위가 아니다. 가격 하락 사건에 한정하지 않고 금리 완화, 무역 합의·관세 유예, 규제 해제, 업그레이드와 서비스 공개도 포함한다.

같은 정책을 다루는 BTC 관세 사건 네 건은 `commonEventId`로 연결하며 생성 시 원래 정책 날짜가 일치하는지 검사한다. BTC의 설명·수익률을 ETH로 복사하지 않으며 ETH 화면의 실행 모듈은 BTC 사건·가격 모델을 가져오지 않는다.

## 날짜와 시각

`source-calendar-day`는 원문이 사용한 사건일·공개일·미국 거래일이다. 시각이 없는 날짜를 UTC 자정의 발생 시각으로 바꾸지 않는다. UTC 가격축의 같은 달력 날짜에 표시하되, 분·시간봉에는 표식을 놓지 않는다.

`block-timestamp`는 실제 블록 응답으로 확인한 헤더 시각이다. 업그레이드의 예정 epoch 시각, 마지막 PoW 블록, 첫 적용 블록의 시각은 구분한다. 대표적으로 다음 차이를 기록했다.

- **머지:** 2022-09-15의 마지막 PoW 블록 15,537,393은 06:42:42 UTC, 첫 PoS 실행 블록 15,537,394는 06:42:59 UTC다. 공식 연대표에 첫 PoS 블록 번호와 함께 표시된 전자의 시각을 그대로 복사하지 않는다.
- **샤펠라:** 예정 epoch 시각 2023-04-12 22:27:35 UTC와 첫 실행 블록 17,034,870의 22:27:59 UTC를 구분한다.
- **푸사카:** 예정 epoch 시각 2025-12-03 21:49:11 UTC와 첫 실행 블록 23,935,694의 21:49:23 UTC를 구분한다.
- **Frontier:** 제네시스 블록의 헤더 timestamp 0은 출시일을 나타내는 시계가 아니다. 2015-07-30 출시일은 당일 공지에 근거한다.
- **ETF/ETP:** SEC의 2024-05-23 거래소 규칙 변경 승인과 2024-07-23 실제 거래 개시를 별개 사건으로 유지한다.
- **DAO/Parity:** DAO 공격일과 하드포크일, Parity 7월 유출과 11월 라이브러리 동결을 각각 분리한다.
- **추가 실행 블록:** Muir Glacier는 2020-01-02, Arrow Glacier는 2021-12-09, Gray Glacier는 2022-06-30 실제 블록 기록을 사용한다. 사전 공지의 예상 달력 날짜를 완료일로 복사하지 않는다.
- **관세:** 발표·집행·보복·유예·합의·판결·판결 효력 정지는 별개 행위다. 공지 당일 미래 부과를 예고한 것은 발표 사건이며, 그 예고가 그대로 실행됐다고 간주하지 않는다.
- **보안·신용:** Ronin의 2022-03-23 공격과 03-29 공개, Celsius의 06-12 출금 중단과 07-13 Chapter 11 신청, 3AC의 06-27 청산 명령과 06-29 보도를 구분한다.

정확한 발표 시각을 원문에서 확인한 경우에만 `facts.announcementUtc`를 별도로 보존한다. 예를 들어 2025-10-10의 추가 100% 관세 게시물은 미국 태평양 일광절약시간 13:50, 즉 20:50 UTC다. 이는 실제 블록 헤더 시각과 다른 자료이며, 원문에 시각이 없는 사건에 자정 값을 생성하지 않는다. 한국 비상계엄의 한국 현지 12월 3일 선포·12월 4일 해제처럼 UTC 날짜가 겹치는 사례는 현지 순서를 상세에 설명한다.

## 정책·시장 해석과 가격 기록

정책 사건은 가능한 경우 **정책·결정**, **당시 시장 해석**, **후속 변화**를 분리해 기록한다. 법령·기관 원문은 발표된 조치와 법적 단계 확인에 사용하며, 기관이 주장한 정당성이나 정치인의 타국 비난을 검증된 사실로 채택하지 않는다. 당시 시장 보도는 위험회피·유동성·청산 등 제시된 맥락을 확인하는 자료다. 거시·지정학적 사건이 있었다는 사실만으로 ETH 등락의 단독 원인을 판정하지 않는다.

상세의 **주변 가격 기록**은 저장된 Coinbase Exchange `ETH-USD` 완료 UTC 일봉만 사용한다. 날짜가 D인 사건에서 D−1의 종가를 공통 기준으로 삼고, 1일 구간은 D, 3일 구간은 D+2, 7일 구간은 D+6의 종가와 비교한다. 계산은 `(구간 마지막 종가 / 사건 전일 종가 − 1) × 100`이며 기준 날짜·종가와 마지막 날짜·종가를 함께 표시한다.

이는 사건 날짜를 포함한 달력 구간의 단순 관측 변화다. 발표 직전·직후의 수익률, 누적 초과수익률, 통계적 사건 연구 또는 특정 정책만의 가격 효과가 아니다. 현지 달력 날짜로 기록된 사건은 UTC 일봉과 완전히 같은 24시간을 뜻하지 않을 수 있다. 거래소 장중 저가, 원화 거래소 변동, 언론의 ‘금요일 이후’ 수익률을 이 UTC 종가 비교에 대입하지 않는다.

계산은 기준 봉부터 마지막 봉까지 모든 날짜의 완료 일봉이 존재할 때만 수행한다. 자료 시작 전 사건, 기준 종가 누락, 중간의 빠진 일봉, 아직 완료되지 않은 구간은 `—`와 이유를 표시한다. 예를 들어 실제 수집본에서 없는 2016-05-21·22 일봉을 주변 날짜로 대체하거나 보간하지 않는다. 가격 예측·가상 캔들·인과 점수는 생성하지 않는다.

검토 당시 Glamsterdam의 메인넷 활성화일은 확정되지 않았다. 2026-10-16 EF 공지의 메인넷 일정은 TBD이며, 2026-10-22 후속 공지는 Hoodi 테스트넷 일정의 연기를 확인한다. 따라서 예정된 Glamsterdam·Hegotá를 완료된 메인넷 역사로 넣지 않는다. 근거: [10월 16일 공지](https://blog.ethereum.org/2026/10/16/glamsterdam-hoodi-announcement), [10월 22일 연기 공지](https://blog.ethereum.org/2026/10/22/glamsterdam-hoodi-delay), [공식 로드맵](https://ethereum.org/roadmap/).

## 차트와 읽기 흐름

역사 표식은 기본으로 켜지며 상단 역사 아이콘에서 끌 수 있다. 목록·상세 창은 처음에는 닫혀 있다. 분류는 프로토콜·보안 사건·시장·금융·생태계·정책·거시·규제·제도·지정학의 일곱 가지이며 색은 매수·매도나 호재·악재 점수가 아니다.

일봉·주봉에서 표식의 가로 위치는 사건의 달력 날짜다. 세로 위치는 주변 완료 봉 종가에 연결하기 위한 배치 기준이며 사건 순간 가격이나 그 사건의 가격 효과가 아니다. 가격 자료 시작 전·마지막 완료 봉 이후·현재 화면 밖의 표식은 그리지 않는다. 주봉에서도 사건을 월요일로 옮기지 않는다. 빈 가격 구간에 OHLC를 보간하지 않는다.

넓은 범위에서는 기존 BTC의 라벨 충돌 회피와 표시 우선순위를 재사용한다. 이름이 생략돼도 범위 안의 표식은 남으며 선택하면 원문을 볼 수 있다. 중요도는 라벨 표시 순서일 뿐 정량적 시장 중요도가 아니다.

상단 아이콘 → 검색·분류·목록 연도 → 사건 → 날짜 기준·교차 확인·원문을 읽는다. 기본 목록은 최근순이며 오래된순으로 바꿀 수 있다. 목록 연도와 정렬은 차트 범위를 바꾸지 않으며, 분류는 목록과 차트 표식 모두에 적용한다. `차트에서 보기`는 실제 일봉 약 181일 구간으로 이동한다. 가격 이력 시작 전 사건에는 해당 버튼을 비활성화하고 이유를 표시한다. 분·시간봉에서 이 버튼을 누르면 일봉으로 전환한다. 모바일은 목록과 상세를 한 화면씩 보여 주고 목록 복귀 버튼을 제공한다.

표시 켜기·끄기와 분류는 `eth-events=off`, `eth-event-category=...`로 ETH URL에만 기록한다. BTC로 바꿀 때 해당 종목 전용 상태는 유지하지 않는다. 역사 자료는 내장 모듈이므로 사건 목록 열기·검색에는 새로운 외부 요청이 필요하지 않다. 원문 링크를 열 때만 해당 외부 사이트로 이동한다.

## 검증 경계

자동 검사는 사건 ID·날짜·순서·출처·블록 기록 일치, 검토 입력과 배포 카탈로그 일치, 미래 사건 배제, 검색·연도·분류·정렬·불변성, 관측 가격 범위, 1·3·7일 비교와 누락 구간 처리, 선·캔들 원본 값 보존, 표식 조작, 확대된 실제 사건 목록의 좁은 화면 라벨 축약, 분·시간봉 숨김, 입력·원문 링크 이스케이프를 확인한다. 이는 사료 전체의 완전성이나 출처 링크의 영구 가용성을 보장하는 검사는 아니다.

화면 검수는 별도로 배포된 HTTPS 페이지에서 실시한다. 좁은 브라우저 프레임에서의 반응형 배치는 실물 휴대전화의 터치 성능 측정과 구분한다.

2026-10-24 v1.17.0 로컬 검증에서는 전체 **83개 테스트 파일**, ETH 사건 카탈로그·상세·주변 가격·렌더링 검사 **38개**, 검토 입력 일치 검사, 정적 자원 검사(파일 120개·참조 236개), 단일 HTML 빌드·자원 검사, 기존 BTC 보정 기록·차트 성능 검사를 통과했다. 기존 요청 상태의 제한된 형식 검증과 오류 주입 대조 검사도 통과했다. 형식 검증은 데이터 요청 상태의 한정된 모델에 대한 것으로, 역사 자료의 진실성이나 전체 프로그램의 정확성을 증명하지 않는다.

출처 제목의 `from 'reciprocal' tariffs`를 모듈 가져오기 구문으로 오인하던 정적 검사도 수정했다. 문자열·주석·정규식 본문을 코드와 구분하여 실제 리터럴 import/export 경로만 기존 경로 검사에 전달한다. 새 회귀 사례 8개로 정상 상대 경로와 잘못된 bare·루트·범위 이탈·누락 경로를 확인했다. 기존 배포 코드의 실제 모듈 경로 목록은 유지됐고 가짜 `reciprocal` 한 항목만 제거됐다.
