# 차트 성능: 점근적 분석과 재현 가능한 측정

검토일: **2026-10-22 KST**. 비교 기준은 `8d2db055bf6a609893740f6e9d5f44122baa64cc`다. 이 커밋의 실제 가격·거래량·기존 미래 모형을 고정하고 렌더러만 교체했다. 새 사이클 보정의 효과를 속도 개선에 섞지 않는다.

## 측정한 병목

기존 차트는 화면에 90일만 보여도 전체 가격, 전체 거래량, 전체 미래 거래량을 매번 훑었다. 특히 매번 8,837개의 미래 날짜 조회표와 전체 가격 인덱스를 재생성했다. 고밀도 일봉에서는 캔들·거래량마다 별도 SVG 노드와 제목을 만들었고, 숫자 하나를 표시할 때마다 `Intl.NumberFormat`을 새로 만들었다. 자 도구의 끝점을 옮길 때에는 전체 가격 배열을 다시 매핑했다.

아래 결과는 **Node의 SVG 경계 대체 객체를 사용한 JavaScript 계산·문자열 생성 시간**이다. 브라우저 DOM 파싱, 스타일, 레이아웃, 페인트, 네트워크, 사용자 입력부터 화면 표시까지의 지연을 측정한 수치가 아니다. 실제 브라우저 검수는 별도 기록한다.

조건은 Node 24.19.0, 1280×720, 각 경우 2회 준비 실행 뒤 7회 측정, 표의 순서대로 실행이다. 중앙값을 비교하며 작은 표본으로 p95나 전 장치 성능을 주장하지 않는다. 두 실행의 입력 해시는 동일하다.

## 점근적 분석

- (N): 보관하는 전체 가격점 수.
- (V): 현재 보이는 가격점 수.
- (C, P, S): 전체 캔들·미래 거래량·상태 자료 수. 아래 첨자 `v`는 그중 현재 보이는 수다.
- (W): 플롯의 가로 픽셀 수.
- (K): 한 경로에서 보존할 값의 종류 수. 가격은 1개, 거래량 범위는 3개다.

| 대상 | 기존 비용 | 변경 후 비용 | 보존한 의미 |
|---|---|---|---|
| 가격 창 선택 | 전체 `filter`, (O(N)) | 이진 탐색 두 번+보이는 구간 복사, (O(\log N+V)) | 양 끝 포함, 실제 날짜의 빈 구간 유지 |
| 캔들·거래량·상태 창 | 각 전체 배열 순회 | 각 (O(\log C+C_v)), (O(\log P+P_v)), (O(\log S+S_v)) | 현재 창 밖 자료를 임시 조회표로 복제하지 않음 |
| 미래 주봉 수량 조회 | 모든 주를 7개 날짜로 확장해 매번 저장 | 정렬된 완료 주에서 (O(\log P)) 탐색 | 월~일의 원래 주, 누락·부분 주의 부재 유지 |
| 자 도구 끝점 이동 | 전체 가격 매핑 (O(N)) 뒤 탐색 | 두 끝점 이진 탐색 (O(\log N)), 최대 2행 변환 | 같은 원래 날짜·가격·방향 있는 변화량 |
| 선·범위 경로의 출력 점 | (O(V)) 점 직렬화 | 극값 검사 (O(VK)), 출력은 최대 (O(WK)) | 픽셀마다 첫점·끝점·각 값의 최소·최대 보존 |
| 고밀도 캔들·거래량 DOM | (O(C_v+V)) 개별 노드 | 같은 색의 SVG 경로로 묶어 일정한 노드 수 | 모든 원래 OHLC·거래량 도형과 조회 자료 보존 |
| 숫자 포매터 생성 | 값마다 새 객체 | 사용하는 자릿수별 재사용 | 같은 locale·반올림 표현 |
| 동일 점의 반복 호버 | 같은 텍스트·속성을 반복 갱신 | 선택 점이 바뀔 때만 갱신 | 이동한 실제 점의 값을 그대로 읽음 |

전체 자료를 한 화면에 보이면 (V=N)이다. 그때 모든 극값을 검사하고 모든 캔들 도형을 만드는 작업은 여전히 선형이다. 전체 렌더를 상수 시간으로 바꿨다고 주장하지 않는다. 데이터 보관 메모리도 여전히 (O(N+C+P+S))이며, 원자료를 버려 성능을 높이지 않았다. 조회표 생성의 절약 대신 개별 가격·주봉 조회에는 작은 로그 비용이 생긴다.

고밀도 도형은 수량을 합하거나 가격을 평균한 새 캔들이 아니다. 각 원래 직사각형·윅을 같은 색의 경로 하위 도형으로 직렬화한다. 좌표는 0.01px 단위이며, 겹치는 반투명 도형을 경로로 함께 칠하는 방식은 개별 노드의 중첩 표현과 미세하게 다를 수 있다. 실제 값·출처·날짜·자 도구·내보내기의 입력은 원자료다. 확대하면 개별 캔들·거래량 노드와 제목으로 돌아간다.

달력 캐시는 UTC 날짜 문자열의 불변 해석만 저장하고 32,768항목으로 제한한다. 가격이나 모델 결과를 `asOf`만으로 캐시하지 않는다. `dateWindow`는 정렬된 입력 계약을 사용하며 새로운 배열/수정 자료를 다시 읽으므로 같은 종료일의 데이터 수정도 반영한다.

역사 사건의 이름 배치도 이름을 실제로 추가한 경우에만 순위를 다시 계산한다. 표시 예산이 찬 뒤에는 남은 사건의 점과 미리보기만 만든다. 모든 사건 점과 선택 우선순위는 유지한다. 이 보완을 전체 라벨 배치의 선형 시간 증명으로 확대하지 않는다. 충돌 검사는 사건 수와 보이는 이름 수에 의존한다.

## 정확성·복잡도 회귀 검사

`tests/chart-performance.test.mjs`의 10개 검사는 다음 반례를 다룬다.

1. 전체 자료가 1,024→16,384→131,072행으로 커져도 고정 9행 창을 찾는 읽기 수가 로그 예산을 넘지 않는다.
2. 주간 거래량 조회가 실제 완료 주를 반환하고 빠진 주를 채우지 않는다.
3. 작은 폭의 가격·범위 스파이크가 픽셀 축약 후에도 남는다.
4. 캔들이 덮는 구간을 건너 종가 선을 연결하지 않는다.
5. 65,536행의 90일 창과 자 도구 포인터 이동이 전체 소스를 순회하지 않는다.
6. 4,096개 캔들·거래량의 고밀도 표시 뒤에도 첫점·중간점·끝점의 정확한 OHLC·수량을 선택한다.
7. 미래 거래량의 중앙 수량과 위·아래 범위에서 좁은 극값을 잃지 않는다.
8. 사이클 색 띠는 완료된 인과적 관측만 사용하고, 빈 날짜와 미래 날짜를 칠하지 않으며 도형도 관측 경계에서 멈춘다.
9. 미래 값의 선택 정보는 관측에서 구한 보정 후보와 모형에 실제 적용한 값을 구분한다. 근거리 기준을 적용할 수 없으면 0일·미적용 사유를 표시한다.
10. 18px 상단 여백의 작은 화면에서도 가격·보조 띠·거래량 영역의 순서와 높이를 보존한다.

기존 오버레이 검사 24개와 내비게이션 검사 20개도 직접 실행해 통과했다. 추가 내비게이션 반례는 인디케이터 창의 일반 텍스트 위에서 휠·드래그할 때 배경 차트가 움직이지 않는지 확인한다.

CI에서는 호스트 속도에 민감한 ms 한계 대신 다음 명령을 사용한다.

```sh
node scripts/verify-chart-performance.mjs --output build/chart-performance-verification.json
```

검증은 그 실행에 있는 실제 스냅샷을 사용한다. 현재 결과는 실제 캔들 5,544개·거래량 도형 5,544개, SVG 91요소(사건·범위 등을 끈 검사 조건, 예산 120 미만), 세 원래 날짜의 OHLC·수량 완전 일치다. 동일 9행 창의 원소 읽기는 전체 1,024/16,384/131,072행에서 각각 **29/37/43회**였다. 처음 받은 날짜를 고정해 다음 날 자동 갱신을 깨뜨리는 조건은 넣지 않았다.

## 재현 방법

측정 스크립트는 입력 모형과 렌더러 경로를 분리한다. 새 모델로 다른 가격 경로가 만들어지는 것을 렌더 최적화의 효과로 계산하지 않는다.

```sh
mkdir -p /tmp/btc-perf-baseline
git archive 8d2db055bf6a609893740f6e9d5f44122baa64cc dist package.json | tar -x -C /tmp/btc-perf-baseline

node scripts/benchmark-chart-render.mjs \
  --input-root /tmp/btc-perf-baseline \
  --renderer-root /tmp/btc-perf-baseline \
  --revision 8d2db055bf6a609893740f6e9d5f44122baa64cc \
  --output /tmp/chart-before.json

node scripts/benchmark-chart-render.mjs \
  --input-root /tmp/btc-perf-baseline \
  --revision current-renderer \
  --output /tmp/chart-after.json
```

두 JSON의 `inputSha256`이 같은지 먼저 확인한다. 각 실행의 호스트 부하·JIT·메모리 회수에 따라 ms 값은 달라진다. 파일 해시, 원소 읽기 수, 보존한 극값, 생성 노드 수는 시간의 흔들림과 별도로 검증한다.

## 남아 있는 비용과 검증 범위

고정 입력의 초기 가격 모형 생성은 약 **699 ms**, 거래량 모형·경로 생성은 약 **230 ms**였다. 이 값은 위 렌더링 표에서 제외했다. 모델이 바뀌거나 자료가 새로 오면 다시 계산해야 하며, 렌더러 최적화만으로 초기 전체 로딩 지연이 위 배수만큼 줄었다고 주장할 수 없다.

이번 검사는 실제 모바일 장치 성능, 브라우저 paint/메모리 압박, 장기간 탭 유지의 힙 추세를 대신하지 않는다. 실제 차트 조작과 인디케이터 창의 화면 검수는 릴리스 담당자가 공개 배포에서 별도로 확인한다.
