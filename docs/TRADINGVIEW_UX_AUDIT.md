# TradingView 기능 비교와 작업 화면 개선

검토일: 2026-10-23 KST. 구현 비교 기준: [`908486efa4b7218bf21ab87a717354df9291e606`](https://github.com/twoimo/bitcoin-cycle-atlas/tree/908486efa4b7218bf21ab87a717354df9291e606). 이 기준에는 v1.10.5의 수학·상태전이·첫 화면 개선과 이후 자료 갱신이 포함된다.

TradingView의 공식 사용법과 실제 공개 화면을 기능별로 비교하고, Bitcoin Cycle Atlas에서 사용 빈도가 높은 조작과 설정 복원을 개선한다. 이 문서는 TradingView 전체 기능을 구현했다는 뜻이 아니다. BTC 관측 자료와 조건부 연구 경로를 다루는 기존 범위를 유지하며, 새 조작에서도 관측·누락·가정의 구분을 유지한다.

## 1. 조사와 비교 방법

공식 도움말에 설명된 동작, 브라우저에서 확인한 동작, 소스에서 확인한 Atlas의 동작을 구분한다. 문서로만 확인한 기능을 실제 기기에서 시험한 것으로 기록하지 않는다. 화면 모양을 복제하는 대신 어떤 작업을 얼마나 쉽게 완료할 수 있는지 비교한다.

pstack의 `swarm`, `tdd`, `blast-radius` 절차에 따라 차트 상호작용, 지표·패널, 공식 기능 조사를 병렬로 나누고 통합 변경을 교차 검토한다. 작업자들은 같은 계열의 실행 환경을 사용하며, 서로 다른 모델 제공자의 합의로 표현하지 않는다. 이전 [수학·상태 감사](MATH_STATE_AUDIT.md)와 [첫 화면 공개 조건](INITIAL_LOADING.md)은 이번 UI 변경의 회귀 검사 대상이다.

### 실제 화면에서 확인한 범위

TradingView 공개 차트에서 시간 간격과 즐겨찾기, 차트 유형, 지표 검색·분류, 설정의 Symbol 및 Scales and lines 탭, 레이아웃의 저장·자동 저장·공유·CSV 항목, 스냅샷의 PNG·복사·링크 항목을 열어 확인했다. Ctrl/⌘+K 검색에서 로그 눈금 명령과 Alt+L 안내도 확인했다. 참고 사이트의 사용자 설정을 저장하거나 변경하지 않았다. 이 관찰은 메뉴와 사용 흐름의 확인이며 브로커 연결·주문·서버 알림의 기능 시험은 아니다.

TradingView의 모바일 길게 누르기 동작은 공식 문서로 확인했으며, 이 조사에서 실제 모바일 TradingView 화면을 조작한 것으로 기록하지 않는다. Atlas 공개 사이트에서는 비교 시작 시 v1.10.5 로드를 확인했다. 새 구현의 배포 후 화면 검증은 아래 검증 기록과 별도로 구분한다.

## 3. 저장·공유의 정확성 계약

기존 URL은 간격·가정·눈금·지표 같은 설정을 기록하지만, 드래그·휠로 바꾼 실제 범위나 가격 단위를 모두 기록하지 않는다. URL 문자열만 저장한 뒤 “같은 화면”이라고 표시하면 실제 복원 결과가 달라진다. 이번 구현은 다음 조건으로 검토한다.

1. **현재 설정과 현재 표시 범위를 함께 읽는다.** 일별·주별 날짜 범위와 분·시간봉 Unix 초 범위를 구분한다. 분봉 범위는 해당 봉 간격 격자에 맞아야 한다.
2. **저장 자료는 실행 명령이 아니다.** 버전이 있는 구조에서 지원한 필드만 읽고, 외부 URL·HTML·스크립트는 실행하지 않는다. 저장한 이름은 텍스트로 표시한다.
3. **공유 링크의 명시적 값이 우선한다.** 다른 사람의 링크를 열었는데 이 기기의 이전 설정이 덮어쓰지 않게 한다. 아무 저장도 없는 첫 방문은 기존 4년 기본 보기로 시작한다.
4. **현재 자료의 범위를 존중한다.** 저장 뒤 자료가 갱신되거나 조회 가능 범위가 줄어들면 유효 범위에 맞춘다. 복원할 수 없는 봉을 생성하거나 누락을 채우지 않는다.
5. **한 작업으로 적용한다.** 여러 필드가 반쯤 적용된 중간 상태를 공개하지 않는다. 늦게 도착한 이전 간격의 응답이 새 화면을 덮어쓰지 않도록 기존 시장 자료 소유권 제어를 유지한다.
6. **실패를 성공이라고 표시하지 않는다.** 브라우저 저장소 거부·손상·용량 제한, 클립보드 쓰기 실패는 실제 결과에 맞게 알린다. 실패해도 차트는 계속 사용할 수 있어야 한다.
7. **보존 범위를 정확히 설명한다.** 브라우저에 저장한 화면은 계정 간 동기화가 아니다. 선택 봉·진행 중 측정·열린 패널처럼 포함하지 않는 일시 상태가 있다면 기능 설명에서 구분한다.

이 계약은 TradingView의 저장 구현을 재현했다는 주장이 아니라 Atlas의 자체 데이터·UI 상태에 적용하는 조건이다.

## 4. 지표와 가격 읽기의 정확성 계약

지표의 “차트에 추가됨”, “레이어가 보임”, “값 목록 전체 표시”, “현재 화면에서 접기”, “접었을 때의 대표값”은 서로 다른 상태다. 즐겨찾기도 표시 여부와 독립이다. 대표 지표를 바꾸거나 즐겨찾기를 제거했다고 차트의 계산이나 레이어가 사라지면 안 된다.

추가 요청에 따라 데스크톱·모바일의 지표 행을 기본 펼침으로 통일했다. `표시` 분류를 제외한 추가 지표를 거래량 우선 순서로 나열하고 이름·값 또는 자료 상태·눈·삭제 조작을 제공한다. 가격·OHLC, 출처, 범례 설정은 관리 창에 유지하며 차트의 원래 표시와 중복하지 않는다. 숨긴 지표 행은 복원 조작을 남긴다. 일별 전용 항목은 분봉에서 `1D · 1W에서 표시`라고 알리며, 값이 없다고 0이나 다른 날짜의 값을 넣지 않는다.

목록 높이는 제한하고 내부 스크롤을 제공한다. 화면 폭에 따른 자동 대표 1개 제한과 나머지 값의 갱신 생략은 제거한다. 직접 접기는 현재 화면에만 적용하며 URL·템플릿·작업 화면의 추가·숨김 설정을 바꾸지 않는다. 기존 `indicator-list=closed`는 목록 전체 숨김으로 유지한다. `접었을 때 대표 지표`는 저장·공유할 수 있지만 실제 접기 여부는 저장하지 않는다. 분석 창의 독립된 축과 선택 상태도 보존한다.

지표 묶음은 멤버십·숨김·값 목록 전체 표시 여부·대표 지표 상태를 한 번에 적용한다. 이름 있는 사용자 조합을 브라우저에 최대 8개 보관하며, 같은 이름에는 “덮어쓰기”를 표시한다. 적용 시 차트의 지표 구성이 바뀐다는 점을 안내하고 가격 자료의 간격·가정·범위를 유지한다. 현재 화면의 접기 여부는 템플릿에 넣지 않는다. 별도의 적용 취소 이력이나 내장 지표 묶음을 제공한다고 표시하지 않는다.

십자선의 포인터 가격은 선택 봉의 종가와 다를 수 있다. 축에는 포인터가 가리키는 가격을, OHLC 줄에는 해당 봉의 실제 관측을 표시한다. 포인터를 선 밖으로 움직였다는 이유로 관측 가격이 바뀌면 안 된다. 로그 축과 선형 축의 역변환 및 최근 관측값 100 단위를 각각 확인한다. 최근 가격 표식은 관측 마지막 값과 미래 가정의 마지막 값을 혼동하지 않아야 한다.

## 5. CSV의 정확성 계약

- 내보내는 행은 현재 시간 범위에 속하는 실제 관측이다. 누락일이나 미래 시나리오를 관측 행으로 채우지 않는다.
- 일별·주별 화면의 메뉴는 **일별 가격 CSV**로 표시한다. 선·캔들 표시 선택과 관계없이 Coin Metrics의 원본 일말 가격을 내보낸다. Bitstamp 캔들과 그 이전의 Coin Metrics 선이 섞인 전체 그림을 단일 거래소 OHLC라고 내보내지 않는다.
- 분·시간봉 화면의 메뉴는 **완료 OHLC CSV**로 표시한다. 현재 조회된 실제 Coinbase 봉의 시가·고가·저가·종가와 BTC 거래량을 내보낸다. 아직 조회하지 않은 과거 봉까지 포함한 완전한 거래소 이력이라는 뜻은 아니다.
- 선의 픽셀 표본화나 화면 폭에 따른 간소화는 원관측 CSV의 행 수를 줄이는 근거가 아니다.
- 시간·가격·거래량의 의미를 열 이름과 출처로 구분한다. 일말 가격과 거래소 OHLC, 달러 가격과 지수값을 섞지 않는다.
- CSV는 차트의 가격축 표시 단위와 관계없이 USD 원가격이다. `chart_date_utc`와 `candle_open_utc`를 구분하며, 지수값을 USD 가격으로 기록하지 않는다.
- 분봉에서는 아직 완료되지 않은 봉이나 읽지 않은 과거 봉을 포함했다고 표시하지 않는다.
- 선택 기간에 실제 관측이 없으면 빈 상태를 알린다. 이전 기간의 CSV를 대신 저장하지 않는다.

### 기본 펼침 지표 목록의 독립 교차 검토

후속 코드에서는 차트 그리기 완료 이벤트에서 지표 값을 같은 선택 시점으로 즉시 맞추도록 변경했다. 일반 포인터 이동은 기존처럼 프레임당 한 번 처리한다. [첫 프레임 회귀](../tests/indicator-frame.test.mjs)의 **7개 named tests**를 독립 재실행해 통과했고, 전체 앱을 실행한 별도 검사에서도 시장 국면·낙폭·4년 비교 추가 후 첫 완료 프레임에 맞는 값을 확인했다. 가격 자료·금융 모형 계산·시장 요청 제어기는 이 수정의 대상이 아니다.

작은 화면의 후속 코드에서는 측정한 플롯 높이에 맞춰 분석 영역을 확보하고, 공간이 부족하면 열린 분석 창을 지표 목록 위에 배치한다. 지표의 추가·숨김·직접 접기 상태는 바꾸지 않는다. 분석 내용은 하나의 바깥 영역에서 스크롤하고 제목·숨기기·삭제 버튼은 고정한다. 키보드로 지표 목록에 접근하면 그 목록을 위로 올리며, 분석 창을 숨기거나 삭제한 뒤에는 같은 상태 이벤트로 갱신된 보이는 조작 요소로 초점을 돌린다. 열린 대화상자나 사용자가 옮긴 초점은 유지한다. [포커스 회귀](../tests/analysis-focus.test.mjs) **4개**와 실제 DOM 상호작용 **3개**를 독립 재실행해 통과했다. 플롯 높이 483px에서 분석 영역 330px, 287px에서 271px라는 값은 현재 CSS 계산에 따른 예상치이며, 공개 브라우저에서 다시 측정할 대상이다.

변경한 UI 모듈과 그 진입 경로, 두 CSS 파일에만 캐시 구분값을 적용했다. 시장 요청 제어기의 SHA-256은 검증된 `dce96066268bb4e5ff0f5b81fe182904d6cb7d711172886872de3d387b6b7bee`와 일치한다. 이 후속 UI 변경을 새로운 형식 증명으로 취급하지 않는다.

**후속 보정의 최종 로컬 게이트:** 전체 자동 검사 **364개 통과, 실패·건너뜀 0개**(실행 시간 6,217ms), 정적 파일 **80개·참조 142개** 검사를 통과했다. 2026-10-21까지 **5,940개 관측**을 사용하는 사이클 산출물과 그 원자료 해시는 변하지 않았다. Node 성능 예산은 SVG **94/120개**, 날짜 범위 읽기 **43/47회**이며, 단일 HTML은 **56개 모듈·5,940개 관측·9,577,137 bytes**로 빌드한 뒤 정적 검사를 통과했다. 위 353개와 이전 단일 HTML 크기는 최초 공개 버전의 기록으로 보존하며, 부분 집합인 집중 회귀를 전체 검사 수에 다시 더하지 않는다.

이 절은 커밋 전 로컬 검증과 기존 `e1b35a6` 공개 검수를 구분한다. 후속 배포의 브라우저 검수 결과는 해당 변경 PR에 추가 기록한다. 이 브라우저 검수는 물리 휴대전화의 터치 지연·FPS 측정이 아니며, 전체 TradingView 기능과의 동등성도 주장하지 않는다.
