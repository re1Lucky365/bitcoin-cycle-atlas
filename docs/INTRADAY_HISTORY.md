# 분봉·시간봉의 과거 자료 확장

검증일: 2026-10-22 UTC. 실제 API 확인 기록: [INTRADAY_HISTORY_LIVE_VERIFICATION.json](INTRADAY_HISTORY_LIVE_VERIFICATION.json).

## 수정한 원인

기존 화면은 처음 읽은 180개 완료 봉의 첫 시각과 마지막 시각을 이동·축소의 전체 경계로 사용했다. 네트워크가 정상이어도 그 경계를 넘을 수 없었으며, 더 과거의 봉을 요청하는 기능도 없었다.

이제 화면 범위와 메모리에 받은 자료 범위를 분리한다. 분봉·시간봉에서 축소하거나 왼쪽으로 이동하면 새로 보이는 시간 구간을 같은 봉 간격으로 요청하고, 검증을 통과한 실제 OHLCV만 합친다. 선 차트와 캔들 차트가 같은 자료와 시간 범위를 사용한다. 기본 범위로 돌아가면 최근 저장·조회 구간을 다시 보여준다.

## 원문과 구현의 대응

| Coinbase 공식 규칙 | 구현 |
| --- | --- |
| 한 요청에 최대 300개 source candle | 한 과거 페이지를 최대 288개 source candle로 제한한다. |
| 긴 시간 범위는 start/end를 바꿔 여러 번 요청 | 표시 범위에서 아직 확인하지 않은 구간만 역순으로 나눈다. |
| 허용 간격 60·300·900·3600·21600·86400초 | 1m·5m·15m·1h는 원래 봉, 30m는 15m 두 개, 4h는 1h 네 개를 UTC 경계에서 합친다. 모든 원래 봉이 있을 때만 상위 봉을 만든다. |
| 응답에는 start보다 앞선 봉이 포함될 수 있음 | 매 페이지를 반개구간 `[start, end)`로 검증·필터링하고 시각 기준으로 중복을 제거한다. |
| 체결이 없는 구간은 미발행이며 과거 자료가 불완전할 수 있음 | 빈 페이지도 조회 완료 범위로 기억한다. 가격을 보간하거나 0 거래량 봉을 만들지 않는다. 선은 실제 시간 공백에서 끊어진다. |
| 공개 API는 IP별 초당 10회, 429로 제한 알림 | 동시에 한 요청만 수행하고 과거 페이지 사이에 최소 250ms를 둔다. 429·오류에서 기존 자료를 유지하고 요청을 중단한다. |

## 요청·메모리·화면 제한

- 화면 하나에 최대 **6,000개 봉 간격**을 표시한다. 1분봉 약 4.2일, 4시간봉 약 2.7년이다. 이는 한 화면의 확대 범위와 네트워크 부하를 제한하는 값이다. 왼쪽으로 이동하면 이전 기간을 계속 요청할 수 있다.
- 간격별로 현재 화면 주변 최대 12,000개 봉 간격과 초기 최근 180개 봉을 유지한다. 저장된 메모리 범위 밖으로 다시 이동하면 필요한 구간을 재조회한다. 180개가 전체 과거 자료의 경계가 되지 않는다.
- 같은 간격에서 연속 확대·이동하면 진행 중인 요청을 중복 생성하거나 매번 중단하지 않는다. 다음 요청의 목표 범위를 마지막 사용자 화면으로 바꾼다. 다른 간격 선택, 새로고침, 기본 범위로 복귀하면 오래된 요청을 중단할 수 있다.
- 늦게 도착한 취소 요청은 자료나 화면을 바꿀 수 없다. 완료된 빈 구간은 재요청 루프를 만들지 않는다. 실패 후 30초 동안 자동 재요청을 막으며, 사용자가 새로고침하여 다시 시작할 수 있다. 각 요청은 15초 제한을 갖는다.
- 4h의 완전히 새로운 6,000개 구간은 최대 84개의 원본 페이지가 필요하다. 요청 간격만 약 21초이며 실제로는 네트워크 지연이 더해진다. 도착한 페이지부터 순차 표시하고, 다른 구간으로 이동하면 다음 페이지 목표를 바꾸며, 간격 변경·기본 범위 복귀는 조회를 중단한다.
- 아직 조회하지 않은 구간과 확인된 체결 공백을 구분한다. 서로 떨어진 캐시 구간 사이의 미조회 시간을 ‘거래 없는 봉’으로 집계하지 않는다.
- 과거 자료는 페이지 조회 시각을 각 봉에 기록한다. 기존 저장본의 수집 시각을 새 조회 시각으로 바꾸지 않는다. 선택 상세는 해당 봉의 실제 수집 시각을 사용한다.
- 탐색 하한 2009-01-03은 앱의 비트코인 시간축 경계일 뿐 Coinbase가 그때부터 거래 자료를 제공한다는 주장이 아니다. 제공하지 않는 기간은 빈 구간으로 남는다.

## 모바일을 포함한 렌더링 비용

전체 캐시를 매 프레임 필터링하는 대신 이진 탐색 후 화면에 들어오는 부분만 잘라낸다. 원자료가 N개, 화면에 보이는 봉이 V개일 때 선택 구간 추출 비용은 **O(log N + V)**이다.

밀집한 캔들은 각각의 실제 고가·저가 선과 몸통을 네 개 SVG 경로로 묶는다. 거래량은 두 개 경로로 묶는다. 날짜별 OHLCV 원자료는 유지되며 선택·측정은 원래 자료를 읽는다. 캔들을 임의의 새로운 시간 봉으로 바꾸지 않는다. 선 차트는 각 픽셀의 첫 값·마지막 값·최솟값·최댓값을 보존하며, 원래 시간 공백을 넘어서 연결하지 않는다. 포인터 읽기는 화면 프레임당 한 번으로 합친다.

`tests/intraday-rendering.test.mjs`는 360px·390px·1280px에서 6,000개 OHLCV 테스트 자료를 그릴 때 SVG 요소가 120개 미만인지, 거래량 막대 모양이 모두 유지되는지, 처음·중간·마지막의 정확한 OHLCV를 선택할 수 있는지 검사한다. 131,072행 중 9행을 보는 시험에서는 원배열 접근이 70회 미만이다. 이는 구조·복잡도 시험이며 실제 휴대전화의 화면 그리기 시간이나 입력 지연 측정은 아니다.
