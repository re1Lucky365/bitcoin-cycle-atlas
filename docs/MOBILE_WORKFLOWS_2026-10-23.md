## 1. 비교 기준과 증거의 구분

[원본 모바일 조사](research/tradingview-mobile-2026-10-23/README.md)는 **a71cdc3765fc7913dc0d9c57c94365619a4bcb0b · v1.12.1**의 고정 기록이다. Android 14 에뮬레이터·Chrome 113에서 관찰한 25개 시나리오, 56장 캡처, 수신 PNG·CSV와 공식 문서 8개를 그대로 보존한다. 원본은 실물 Galaxy나 TradingView 네이티브 앱 검증이 아니며, 그때 받은 파일을 새 버전의 내보내기 성공 증거로 재사용하지 않는다.

이번에 사용자가 직접 지정한 변경은 D-day UI 제거, 모바일 가격·여섯 색 범례 숨김, 좌상단 이름·값 목록 간소화, 거래량 기본 숨김, 주요 사건·기간·축·상태의 한 줄 통합이다. 원본 조사에서 제안한 방향과 현재 사용자 요구가 다른 경우 현재 요구를 반영한다.

## 3. 현재 화면에서 달라진 사용법

### 가격·출처·범례

D-day 카드·값 목록 항목·진입점을 제거했다. 옛 공유 링크, 작업 화면, 지표 템플릿에 남은 해당 항목도 정규화 과정에서 제외한다. [상태와 호환 처리](../dist/indicator-state.js)

데스크톱 우측 상단의 가격 범례는 크기가 고정된 SVG로 **관측 가격선**, **관측 캔들**, **미래 가정**, **가정 범위**, **고점·저점**의 도형을 구분한다. 일·주 캔들 모드에서 완료 거래소 봉과 Coin Metrics 가격선이 함께 보이면 두 관측 범례를 함께 표시한다. 표시 여부는 차트 형식 버튼만으로 추측하지 않고 현재 실제 렌더링한 종류를 따른다. 값 읽기는 **관측 종가**와 **봉 종가**를 구분하며 실시간 현재가로 부르지 않는다. [범례와 출처 문구](../dist/price-legend.js), [연결](../dist/lab-view.js)

가격·여섯 색 범례 묶음은 **CSS viewport 폭≤620px**, 또는 **폭≤950px이면서 높이≤500px**에서 숨긴다. 좁은 화면에서 범례를 숨겼다고 색 원·기간선·가격/OHLC·자료 출처의 개별 설정을 변경하지 않는다. 넓은 화면으로 돌아오면 저장된 범례 표시 상태를 다시 따른다. 가격 그래프 하단의 사이클 기간선 배치는 유지한다.

**저장 스냅샷 예:** 2026-10-22 Coin Metrics 일말 가격은 81,257.0175825248 USD, 같은 날짜 Bitstamp 종가는 81,315.35 USD다. Coin Metrics 대비 약 0.07179% 차이는 서로 다른 출처의 값이며 숫자 오류로 단정하지 않는다. 이 스냅샷에서 마지막 완료 Bitstamp 주봉은 2026-10-12~18, 종가 82,001.58 USD다. 10-19~22는 완료 주봉을 만들지 않고 Coin Metrics 일말 관측선을 사용한다. 일말 관측 종료일과 완료 주봉 종료일을 별도로 표시한다. 이는 현재가 안내가 아닌 **해당 저장 자료의 예**다. [Coin Metrics 저장본](../dist/data/btc-daily.json), [Bitstamp 저장본](../dist/data/btc-volume.json), [집계 규칙](VOLUME_METHOD.md)

### 값 목록·거래량·집중 보기

좌상단 지표 목록은 이름·값 한 줄을 중심으로 내용에 맞는 폭을 쓰고, 긴 값은 줄임표와 전체 설명을 함께 제공한다. 작은 화면의 행은 28px, 마우스를 쓰는 넓은 화면의 조밀한 행은 24px를 기준으로 하며, 터치에서는 설정·눈·삭제에 직접 접근한다. 전체 접기는 모든 이름·값 행을 접되 가격·OHLC와 차트 도형을 유지한다. 한 지표만 있어도 접을 수 있다.

새 접속과 초기화에서는 거래량이 **추가됨·숨김** 상태로 시작한다. 눈 아이콘으로 다시 켤 수 있고, 저장한 작업 화면·링크·템플릿이 명시적으로 표시를 선택했다면 그 상태를 유지한다. 값 숨김, 지표 숨김, 목록 접기, 연구 창 최소화는 서로 다른 조작이다.

좁거나 짧은 화면에서는 목록의 **높이 → 작게·보통·넓게**를 고른다. 목록 내용과 실제 남은 높이 이내에서 스크롤 영역을 조절한다. 모바일 **정보와 설정 → 차트 집중 보기**는 읽기 정보·값 목록·연구 창을 일시 감춘다. **정보 다시 표시**로 돌아오며, 추가·숨김·접힘·창 높이를 덮어쓰지 않는다. 집중 보기와 목록 높이 선택은 현재 화면의 편의 설정이며 공유 URL에 새 저장 상태를 추가하지 않는다.

### 연구 창·하단 도구·내보내기

연구 창은 기존 가격 SVG 높이 안에서 목록과 별도의 스크롤 영역을 사용한다. 두 개 이상이면 상단의 **연구 창** 선택과 **이동**으로 제목·복원 조작에 접근한다. 이동 때문에 숨겨진 창을 켜거나 접힌 창을 임의로 펼치지 않는다. 최소화는 제목을 남기고, 눈은 표시만 숨기고, ×는 추가 목록에서 제거한다. 최대화·복원·순서·경계 높이 조절과 각 연구의 독립 축은 유지한다.

하단은 **44px 한 줄**이며 모바일 safe-area 여백은 별도다. ≤620px에서는 기간 선택 메뉴·달력·사건·로그/Auto·더보기를 사용한다. 사건은 차트 위쪽으로 펼치는 팝오버이며, 검색·전체 목록·거래량 출처도 제공한다. 더보기에서 현재 표시 기간·UTC·갱신·기본 범위 복원을 읽거나 실행한다. 추가 목록을 열어 별도 하단 행을 만들지 않는다. [하단 도구](../dist/chart-bottom-bar.js), [사건 목록](../dist/history-journal.js), [CSS](../dist/chart-bottom-bar.css)

모바일 **차트 내보내기**는 PNG·SVG·CSV와 범위를 명시적으로 고르는 기존 대화상자를 연다. **작업 화면·공유**는 저장·공유 탭으로 직접 연결한다. 내보내기의 관측/조건부 자료, 원 USD, UTC, 실제 조회·저장 범위, 독립 연구 축 계약은 [v1.13 내보내기 설명](RESEARCH_WORKFLOWS_2026-10-23.md#7-내보내기와-자료-정체성)을 유지한다.

## 4. 공간 배분과 상태 보존 계약

`mountCompactChartLayout({plot})`은 실제 가격 영역의 폭·높이와 읽기 영역·출처·범례의 표시 높이를 측정한다. 실제 plot 폭≤850px 또는 높이≤420px이면 제한된 목록과 연구 창 영역을 계산한다. 폭≥600px·높이≤420px에서 목록과 연구 창을 함께 펼친 경우 가로 공간을 나누어 사용한다. 이는 기기 종류 추정이 아닌 현재 차트 크기에 따른 배치다.

| 조작 | 변경하는 것 | 유지하는 것 |
|---|---|---|
| 목록 화살표·이름/값 펼치기 | 저장 가능한 전체 접힘 상태 | 가격·OHLC, 지표 도형·추가 상태 |
| 목록 높이 선택 | 현재 화면의 목록 스크롤 높이 상한 | 저장된 지표 상태·연구 창 높이 |
| 지표 눈·값 표시 설정 | 해당 도형 또는 값의 표시 | 다른 지표의 상태 |
| 연구 창 최소화·최대화·높이·순서 | 기존 지표 상태와 창 배치 | 주 가격의 크기·연구의 독립 축 |
| 차트 집중 보기 | 화면 정보의 일시 가림 | URL·템플릿·추가·숨김·접힘·창 높이 |
| viewport 변경 | 공간 재측정·반응형 표시 | 사용자의 명시적 접힘·숨김 선택 |

ResizeObserver와 HUD·지표·집중 보기 이벤트를 묶어 배치를 갱신한다. 집중 모드에서 숨겨져 0이 된 크기로 기존 배치를 덮어쓰지 않고 복원 후 다시 측정한다. 연구 창 선택은 현재 보이는 창과 순서를 따르며, 스크롤·키보드 초점으로 접힌 제목에 접근한다. [배치 구현](../dist/compact-chart-layout.js), [연구 창 구현](../dist/analysis-dock.js)

## 5. 제스처 회귀 20개가 확인하는 것

[새 회귀 파일](../tests/mobile-gestures.test.mjs)은 다음 입력 순서를 합성한다. 실제 손가락 하드웨어·브라우저 제스처 엔진을 실행한 결과와 구분한다.

- 일·주·시간 화면의 480px 드래그가 재렌더링을 거쳐도 마지막 pointerup 좌표까지 반영되는지, 방향 전환 후 기준이 흔들리지 않는지, 변경 기록이 한 조작으로 묶이는지.
- 십자선 터치의 가로 이동은 미세한 세로 흔들림에도 Auto를 유지하고, H 이동은 의도한 두 축 이동으로 전환하는지.
- 마우스·터치의 가격축/시간축 드래그가 다른 축을 바꾸지 않고 최종 위치까지 반영되는지.
- 길게 누르기·한 손가락 이동·pinch의 전환, 세 번째 접촉과 남은 접촉, 포인터 ID 재사용이 별도 잘못된 이동을 만들지 않는지.
- 네이티브 contextmenu·명시적 빠른 메뉴·측정·차트 밖 스크롤·축 조작이 추적 상태와 충돌하지 않는지.
- 간격 전환, 취소, 초점 상실, resize, 문서 숨김, capture loss가 대기 중이거나 진행 중인 추적을 정리하는지.

20개는 새 회귀 파일의 케이스 수다. 관련 부분 집합과 전체 검증을 중복해서 합산하지 않으며, v1.14 최종 전체 합계는 §8에 한 번만 기록한다. 프레임률·터치 지연·배터리·실제 동시 다중 터치 성능을 이 검사에서 산출하지 않는다.
