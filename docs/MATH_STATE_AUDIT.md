# 수학·논리·상태전이 심층 감사

검토일: 2026-10-23 KST. 기준 소스: [`e15ae31a4223d127244b6d630ae4b7c910f653ef`](https://github.com/twoimo/bitcoin-cycle-atlas/tree/e15ae31a4223d127244b6d630ae4b7c910f653ef).

**재현 가능한 10개 결함군을 수정했다.** 수치 오차로 생기는 가짜 전환, 누락 자료를 근거로 한 잘못된 수익률·피보나치 성과, 사용자 지정 백테스트의 입력·기간·메타데이터 오류, 차트가 누락 구간을 연결하는 문제를 다룬다. 요청 취소·저장본 응답의 경쟁 상태는 별도 형식 모형과 실제 제어기 테스트로 검증했다. 그 영역에서는 기존 소유권 검사가 정상이며, 발견되지 않은 동시성 버그를 수정한 것으로 기록하지 않는다.

## 1. 범위와 방법

계산·데이터, 예측·평가, 비동기 상태전이를 세 작업으로 병렬 검토하고, 다른 작업자가 변경 내용을 다시 대조했다. 차트와 문서·통합 검증은 별도로 수행했다. 독립 교차 검토에서 단기 평가 기간 오류를 추가로 재현했으며, 누락 구간 분리 후 한 점짜리 구간이 보이지 않는 후속 문제도 수정했다.

사용한 절차는 [pstack의 고정 소스 `eb4db2b`](https://github.com/cursor/plugins/tree/eb4db2b55b2b7dec3d9282754cddf0a56bf4ff10/pstack)의 `swarm`, `tdd`, `blast-radius`, `create-formal-verification-skill`, `statechart`다. 이 실행 환경에서 사용할 수 있는 동일 계열 작업자들로 병렬화했으며, 서로 다른 제공자·모델의 합의라고 주장하지 않는다. 실제 내보낸 함수에 반례를 넣어 수정 전 실패를 확인한 다음, 동작을 고치고 호출부·기본 결과를 다시 검사했다.

## 2. 확인한 결함과 변경

### D1. 일정한 가격에서 이동평균 전환이 생김

수정 전에는 가격 100이 1,000일 동안 같아도 상승·하락·상승 전환 세 개가 생성됐다. 평생 누적합 두 개를 빼서 이동평균을 구하는 과정의 상쇄 오차와 정확한 부동소수점 비교가 원인이었다. 한 확인일의 평균은 `99.99999999999862`였다. 0.1과 60,000의 일정한 가격에서도 재현됐다.

현재 창의 보상 합산으로 바꾸고 창 길이마다 합을 다시 계산한다. 전체 작업량은 여전히 분할상환 `O(n)`이다. 기하평균은 로그 영역에서, 산술평균은 가격 영역에서 크기에 비례하는 `64 × Number.EPSILON` 허용오차로 수치적 동률을 처리한다. 이는 시장 신호의 경제적 임계값이 아니다. 일정한 가격은 중립으로 남고, 하루 `1e-8`의 작은 상대 변화가 지속되는 추세는 정상 확인된다. [코드](../dist/cycle-timing.js) · [반례 테스트](../tests/cycle-timing.test.mjs)

### D2. 누락일 뒤의 피보나치 접촉을 첫 접촉으로 확정함

100→200의 확정 스윙에서 50% 되돌림은 150이다. 관측값이 178, **누락**, 149, 158이면 수정 전에는 149를 첫 접촉으로 보고 반등 성공으로 집계했다. 누락일에 먼저 접촉하거나 실패했을 가능성이 있으므로 그 결론은 성립하지 않는다. 극값과 확정일 사이의 누락도 같은 문제였다.

극값부터 확정일까지, 확정일부터 첫 접촉까지 실제 표본 간격이 이어지는지 확인한다. 검색 중 누락이 있으면 기존 `search-censored` 상태로 남기고 완료 성공률 분모에 넣지 않는다. 이미 관측된 확정 전 접촉은 기존 제외 규칙을 유지한다. 일별·주별 경로는 각자의 1일·7일 간격을 사용한다. [코드·테스트](../tests/market-structure.test.mjs) · [해석](MARKET_STRUCTURE_METHOD.md)

### D3. 여러 달의 변화를 한 달 수익률·낙폭으로 표시함

1월 31일 200, 2월 관측 없음, 3월 내내 100인 자료에서 수정 전의 3월 수익률과 최대 낙폭은 모두 −50%였다. 1월 말 가격으로 3월 경계 가격을 대신할 수는 없다.

기간 시작 직전의 연속된 일말 가격만 수익률과 초기 낙폭의 기준으로 사용한다. 예시의 3월 수익률은 `null`, 관측된 3월 내 최대 낙폭은 0%가 된다. 마지막 과거 가격과 날짜는 출처 정보로 보존하고 `priorCloseContiguous: false`로 표시한다. 역사적 최고가 대비 낙폭은 정의가 다르므로 −50%를 유지한다. 내부 누락이 있는 관측 경로의 낙폭 크기는 같은 완전 경로의 낙폭 크기에 대한 하한이며, 실제 전체 경로의 정확한 최대 낙폭은 아니다. [코드](../dist/market-structure.js) · [표시 설명](../dist/atlas-analysis.js)

### F1. 잘못된 사용자 지정 평가 조건이 점수에 들어감

같은 기준일을 두 번 넣으면 서로 다른 기준일 두 개로 집계했다. `days: 0`은 현재 가격을 자기 자신과 비교하여 오차 0%를 만들었다. 같은 horizon ID로 30일과 60일을 지정하면 서로 다른 평가가 같은 요약에 섞였다.

기준일·ID·동일 단위 기간의 중복, 0·음수·소수 기간, 일수와 개월수를 동시에 지정한 조건을 계산 전에 거부한다. 표본 수·seed·블록 길이도 사전 검증한다. 유효한 사용자 지정 기준일에 기본 9개 날짜의 실험 설명을 붙이지 않는다. 기간이 서로 겹친다는 이유로 독립 표본이 되는 것은 아니며, 그 한계는 유지한다. [평가 구현](../dist/detailed-forecast.js) · [회귀 테스트](../tests/detailed-forecast.test.mjs)

### F2. 미래 관측이 없는 구간을 평가 사례로 셈

기준일 `2026-10-20`, 관측 한계 `2024-12-31`을 지정하면 수정 전에는 후속 관측 0개인데 사례 1개·실제 최대 낙폭 0으로 반환했다.

정확한 기준일 관측과 그 이후의 관측 가능한 평가 구간이 있어야 계산한다. 불가능한 기준일은 사유와 함께 `excluded`에 남기며 점수·회차 수에서 제외한다. 빈 평가를 손실이 없었던 사례로 해석하지 않는다. [회귀 테스트](../tests/detailed-forecast.test.mjs)

### F3. 실제 평가한 날짜와 포함 여부 설명이 다름

역사 유사 경로 평가는 실제 2026년 결과를 채점해도 `currentCycleIncluded: false`였다. 상세 평가는 반대로 한계일만 2026년으로 지정하면, 실제 관측 평가가 2021년에 끝나는 경우에도 2025·2026년이 포함됐다고 표시했다.

실제로 채점한 종점·일별 관측 날짜에서 포함 여부를 계산한다. 사용자 지정 평가의 사례 수와 제약 설명을 맞추고, 730일을 실제 채점한 경우에는 “730일 미평가” 문구를 제거한다. 기본 평가의 과거 구간 제한은 유지한다. [analogue 구현](../dist/forecast-engine.js) · [상세 구현](../dist/detailed-forecast.js)

### F4. 한쪽만 입력한 가격 범위가 기준 가격을 벗어남

`price: 100, low: 110` 또는 `price: 100, high: 90`을 허용하여 하한·기준 가격·상한의 순서가 뒤집혔다. 두 범위가 함께 들어왔을 때만 검사했기 때문이다.

생략된 경계는 기준 가격으로 해석한 뒤 항상 `low ≤ price ≤ high`를 확인한다. 유효한 한쪽 경계는 계속 지원한다. 여기의 기준 가격은 통계적 중앙값이라는 주장이 아니다. [구현·반례 테스트](../tests/forecast-engine.test.mjs)

### F5. 최종 값은 유한한데 중간 곱셈이 넘침

정상 자료의 가격 단위를 `1e150`배 하면 입력과 최종 유사 경로 값은 유한하지만 `current * source / base`의 중간 곱셈이 오버플로했다.

`current * (source / base)`로 바꿔 무차원 가격 비율을 먼저 구한다. 실생활 BTC 달러 가격에서 발생한 장애를 주장하는 사례가 아니라, 단위 변경 성질의 수치 경계 반례다. 모든 배정밀도 극단값·극단 비율에 대한 안전성 증명은 아니다. [구현·비례성 테스트](../tests/forecast-engine.test.mjs)

### F6. 유효한 30일 평가가 불필요한 36개월 계산 때문에 제외됨

`2020-01-01`의 30일 평가를 요청해도 항상 36개월 경로를 생성했다. 그 긴 기간이 다음 저점 기준을 넘어가면 지원 가능한 30일 평가까지 제외됐다. 같은 기준일에서 `2020-01-31`까지 직접 생성하면 31개 점이 정상 반환되는 것으로 재현했다.

요청한 종점 중 가장 먼 날짜까지 표시·평가 경로를 생성하고, 일별 포함률·최대 낙폭의 비교 구간도 그 기간과 관측 가능한 구간의 교집합으로 맞춘다. 내부 잔차는 같은 bridge 종점까지 생성한다. 기본 설정은 여전히 36개월이다. 입력 상한은 엔진 범위인 1,120일 또는 36개월이며, 그 안에서도 남은 조건부 시계를 넘으면 구체적 사유로 제외한다.

이번 평가기의 같은 기준선·조건부 종점·seed에서는 표시 기간을 줄여도 개별 bridge 경로의 겹치는 접두 구간은 같다. 대표 경로 선택은 표시 구간의 낙폭·중앙값 거리로 순위를 매기므로 선택되는 경로는 달라질 수 있다. 직접 경로 생성 시 별도 시점 보정이 적용·미적용 사이에서 바뀌어 기준선이나 종점이 달라지는 경우까지 동일성을 주장하지 않는다. [회귀 테스트](../tests/detailed-forecast.test.mjs)

### V1. 관측되지 않은 날짜를 차트가 이어 그림

일별·주별 가격선과 낙폭선이 누락일을 가로질러 연결됐으며, 같은 국면의 띠도 공백을 합쳤다. 주별 표본화 후에만 누락을 검사하면 화요일 같은 비표본 요일의 누락이 숨겨졌다.

원래 일별 행을 먼저 연속 구간으로 나눈 후 주별·픽셀 표본화를 수행한다. 국면 띠도 실제 표본 간격이 이어질 때만 합친다. 캔들 때문에 가격선을 생략하는 조건과 낙폭의 원관측은 분리했다. 한 점짜리 구간은 선으로 연결하지 않고 점으로 표시하여 사라지지 않게 했다. [구현](../dist/atlas-price-chart.js) · [일·주·국면·고립점 회귀 테스트](../tests/chart-performance.test.mjs)

## 3. 증명 가능한 성질과 가정을 구분함

상세 모형의 식은 다음과 같다. `B`는 가정한 기준 가격, `R`은 재표본 잔차의 누적합, `T`는 조건부 종점이다.

\[
\log P^*(t)=\log B(t)+R(t)-\frac{t}{T}R(T).
\]

| 주장 | 타당한 범위 | 이번 검토의 결론 |
|---|---|---|
| 현재 가격과 연결됨 | `R(0)=0`, 기준선 시작값이 실제 가격일 때 | 실수 산술에서 항등식. 실제 코드는 첫 관측 가격을 직접 보존하며 테스트로 확인 |
| 종점 잔차가 0임 | `t=T`에서 `R(T)−R(T)=0` | 모형이 강제한 항등식. 종점을 실제 표시 구간에 넣은 별도 테스트도 통과. 예측 정확성의 증거가 아님 |
| 가격이 양수임 | 유한한 실수 로그가격의 지수함수 | 배정밀도 구현에서는 표현 범위 제한이 있음. 0·비유한 결과는 오류로 처리 |
| 가격 단위 변경에 비례함 | 모든 가격·기준값을 같은 양의 비율로 변경하고 같은 경로를 사용할 때 | 실수 성질과 수치 테스트를 구분. F5의 불필요한 중간 오버플로를 제거 |
| 변동성 배율에 선형임 | 같은 추출 블록에서 로그 잔차의 배율 | 가격 자체가 선형이 되는 성질이 아님. 기존 경로 기반 검사가 이 구분을 유지 |
| 미래 행을 바꿔도 과거 예측은 같음 | 기준일까지의 접두 자료로 학습하고 동일 설정을 쓸 때 | 미래 입력을 바꾸는 인과성 회귀 테스트로 점검. 연구 설계 전체가 사전 등록됐다는 뜻은 아님 |
| 경로 추가 시 기존 경로를 재현함 | 경로 인덱스별로 분리한 결정적 의사난수 스트림 | 통계적 독립성의 증명으로 표현한 문구를 고침. 대표 경로·분위수는 표본 수에 따라 변함 |
| 발행량을 정확히 계산함 | 정수 사토시의 블록 보조금 규칙 | 테스트가 블록 경계·최종 보조금을 다룸. 날짜→블록 높이의 144블록/일 환산은 별도 근사 |
| 범위가 미래 80% 확률구간임 | 실측 자료에 대한 별도 보정·검증이 필요 | 입증되지 않음. 상세 경로 분위와 장기 경제 시나리오 범위를 구분하고 확률 보정 전임을 유지 |
| 4년 주기·D-day가 시장 법칙임 | 공급 일정만으로는 가격·전환 날짜가 도출되지 않음 | 입증되지 않음. 시간 상수와 조건부 대표 경로의 출력으로 설명 |

특히 실수 산술에서 증명되는 식을 JavaScript의 모든 수치 입력·분기에서 정확히 같다는 명제로 확대하지 않았다. 유한한 회귀 테스트도 그 전역 증명을 대신하지 않는다. [수정한 수학 설명](DETAILED_FORECAST_METHOD.md#7-모형-안에서-증명되는-성질)

## 4. 상태전이와 형식 검증

검증한 불변식은 **취소되거나 새 요청으로 대체된 요청이 표시 자료를 덮어쓰지 않는다**는 `NoStaleDisplay`다. 가격·수익률·예측 신뢰도에 대한 불변식이 아니다.

정확히는 성공적으로 게시된 자료의 요청 세대를 추적한다. 모든 오류 알림·콜백 발생 여부를 이 불변식으로 증명한 것은 아니며, 해당 동작은 실제 제어기의 회귀 테스트로 별도 확인한다.

실제 코드의 네트워크 응답과 저장본 fallback에서 각 `await` 이후 다음 중단 전까지의 동기 실행 구간을 원자적 전이로 대응시켰다. 취소해도 응답이 늦게 도착할 수 있는 실행을 남겼다. 검증 범위는 **요청 세대 3개, 간격 캐시 2개**이며 성공·실패·취소·대체의 순서를 탐색한다.

| 검사 | 결과 | 의미 |
|---|---|---|
| 정상 TLA+ 모형, TLC 1.7.4 | 5,955개 생성 상태, 2,081개 고유 상태, 대기 0, 위반 없음 | 지정한 유한 범위를 완료 |
| 저장 응답의 소유권 검사만 제거한 모형 | 151개 생성·109개 고유 상태에서 예상 불변식 위반, 대기 79 | 반례를 찾고 조기 종료한 음성 대조. 전체 탐색 완료 수치가 아님 |
| 실제 제어기·조회·소유권 테스트 | 30개 통과 | 실제 JavaScript의 지연·역순·취소 예제를 확인 |
| 임시 복사본의 실제 소유권 검사 제거 | 예상 stale replace/notify 단언 실패 | 모형의 반례가 무관한 장난감에만 존재하는지 확인하는 음성 대조 |

정상 코드를 일부러 망가뜨린 결과는 **현재 제품에서 발견한 버그가 아니다**. 기존 소유권 검사를 계속 보존할 이유를 실행 가능한 반례로 남긴 것이다. 정상·변이 모형, 코드 대응표, 상태도 PNG와 Mermaid, 재현 순서는 [형식 검증 문서](formal-state/README.md)에 있다.

요청 세대 제한을 넘는 전체 프로그램, 페이지네이션의 모든 상태, 시간 제한·재시도 정책, 브라우저 렌더링, 언젠가 반드시 완료한다는 활성 속성은 이 TLA+ 검증에 포함되지 않는다. 프로젝트의 `.agents/skills/verify-market-state/`에 향후 변경 시 대응표·검사·음성 대조를 함께 갱신하는 재사용 스킬을 추가했다.

## 5. 기존 결과의 보존과 통합 검증

기준 SHA의 원본 모듈과 수정 모듈을 같은 의존 파일·입력으로 직접 실행하여 비교했다.

- 저장된 일별 자료의 시장 구조 결과 전체가 `deepEqual`이다.
- 온라인 추세 신호의 날짜·방향 등은 모두 같고, 이동평균 수치의 마지막 자리만 달라질 수 있다.
- 기본 64개 표본의 상세 백테스트 전체가 `deepEqual`이다. 기존 9개 기준일·3개 거시 회차를 유지한다.
- 기본 유사 경로 예측의 최대 상대 차이는 연산 순서에 의한 `1.1487038798048276e-16`이다.
- 기존 연구 결과 JSON과 검증 요약을 새로운 수치에 맞춰 다시 쓰지 않았다. 기본 결과를 바꾸는 수정이 아니므로 재생성이 필요하지 않았다.

초기 로딩 개선까지 통합한 v1.10.5 테스트는 **316개 통과, 실패·취소·건너뜀 0개**다. 그중 계산·자료 10개 파일의 별도 실행에서는 72개 Node 테스트와 기존 최상위 단언이, 예측 관련 4개 파일에서는 57개 테스트가 통과했다. 이 부분집합의 수를 전체 테스트 수에 더하지 않는다. [첫 진입 레이아웃과 실패 복구](INITIAL_LOADING.md)의 실제 부팅 컨트롤러 검사 4개도 전체에 포함된다.

| 최종 로컬 검사 | 결과 |
|---|---|
| 전체 Node 회귀 검사 | 316개 통과, 실패·취소·건너뜀 0 |
| 일별 보정 산출물 | 2026-10-21까지 5,940개 관측, −52일, 완료 참조 3개와 일치 |
| 차트 복잡도·SVG 예산 | 통과, 실제 전체 캔들 경계의 SVG 요소 94개 / 예산 120개 |
| 형식 검증·음성 대조 | 현재 모형 완료, 변이 반례, 실제 코드 30개 및 소스 변이 단언 확인 |
| 정적 경로 | 76개 파일·132개 참조 통과 |
| 단일 HTML | 53개 모듈·5,940개 관측·8,999,689 bytes 생성 및 정적 검사 통과 |

위 SVG 예산은 Node 렌더링 경계의 결정적 구조 검사이며, 브라우저 paint나 입력 지연 측정이 아니다.

재현 명령은 다음과 같다. Node 24 이상과 형식 검증용 Java 11 이상이 필요하다. 기본 자료 검사는 오프라인이며 TLC 최초 설치에만 공식 배포 파일을 내려받는다. SHA-256을 고정하고 다른 파일은 거부한다.

```sh
npm test
npm run verify:cycle
npm run verify:performance
npm run verify:formal
npm run verify:static
npm run build:standalone
node scripts/verify-static.mjs --standalone build/Bitcoin_Cycles_Comparison.html
```

CI·Pages·정기 자료 갱신·릴리스 작업에 형식 검증 단계를 추가했다. 정상 모형 통과만으로 끝내지 않고, 모형과 실제 코드의 음성 대조가 기대한 이유로 실패하는지도 검사한다. 각 실행의 실제 완료 여부는 해당 커밋의 GitHub Actions 결과에서 확인한다.

## 6. 남아 있는 해석상의 한계

이번 수정은 구현·표시·평가의 정합성을 높인다. 적은 거시 회차, 겹치는 결과 창, 사후에 고른 구조·기준일, 제공자별 가격 차이, 조건부 종점과 경제 시나리오의 선택이 주는 한계는 남는다. 9개의 기준일을 9개의 독립 시장 사이클로, 모의 표본 128개를 실제 독립 실험 128개로 세지 않는다.

장기 모형의 `median`은 문서상 기준 가치평가 시나리오이며 실제 미래 가격분포의 통계적 중앙값이라는 증거가 없다. 장기 경제 가정의 폭과 상세 모형의 경로 분위 범위도 서로 다른 개념이다. 난수 seed 고정, 상태 모형의 안전성, 과거 점수의 재현성 가운데 어느 것도 미래 시장의 정확성을 증명하지 않는다.

모든 가능한 JavaScript 숫자·API 변경·사용자 입력·브라우저 조합에 오류가 없다는 전역 증명은 수행하지 않았다. 새 반례가 생기면 해당 입력의 실패 테스트, 수식과 소스 대응, 영향받는 표시·평가 문구를 함께 갱신한다.
