# v1.10.5 · 첫 진입 레이아웃과 스켈레톤

## 원인과 변경

기존 HTML에는 이전 패널·탭 구조가 있었고, 애플리케이션의 모듈을 모두 읽은 뒤 차트·상단 도구·좌우 레일을 최종 위치로 옮겼다. 이 사이에 이전 구조나 계산 중 문구가 잠깐 드러날 수 있었다. 초기 데이터 조회 실패 안내도 숨겨진 이전 비교 화면 안에 들어가 기본 화면에서 복구 버튼을 볼 수 없었다.

이제 [`index.html`](../dist/index.html) 자체에 작은 핵심 스타일과 정적인 초기 레이아웃이 들어 있다. 외부 스타일과 모듈이 준비되는 동안 상단·좌우 도구·차트·하단 영역의 자리를 잡아 두고, 짧은 막대와 준비 중 문구만 표시한다. 가격선이나 가격 수치를 모사하지 않는다. 모바일에서는 실제 화면과 같은 620px 경계에서 좌우 레일을 숨기고 안전 여백과 상·하단 높이를 반영한다.

실제 작업 화면은 `display:none` 대신 `visibility:hidden`으로 유지한다. 차트와 표가 화면 크기를 계산할 수 있으면서도 사용자에게 미완성 구조가 보이지 않는다. 준비 전에는 `inert`와 `aria-hidden`을 적용하여 키보드·보조기술로 아직 동작하지 않는 컨트롤에 진입하지 않게 한다. 초기 문서의 스크롤도 잠가 이전 긴 문서의 스크롤바가 나타나지 않게 했다.

## 공개 조건과 실패 복구

[`app.js`](../dist/app.js)는 검증된 초기 데이터와 **사용자가 요청한 페이지의 실제 렌더링 완료**를 모두 기다린다. 통합·비교 차트는 [`lab-view.js`](../dist/lab-view.js), 리서치 표는 [`evidence-view.js`](../dist/evidence-view.js)가 자신의 완료를 알린다. 원자료는 표를 그린 뒤 완료한다. `DOMContentLoaded`나 `load` 이벤트만으로 스켈레톤을 제거하지 않는다.

완료하면 같은 화면 갱신에서 스켈레톤을 숨기고 실제 화면을 사용할 수 있게 한다. 최소 대기 시간을 추가하지 않았다. 초기 일말 자료 요청은 최대 15초 후 실패로 처리하며, 이는 모든 모듈 다운로드나 전체 계산 시간의 상한이라는 뜻은 아니다.

초기 실행·모듈·스타일시트·자료 오류가 발생하면 같은 틀 안에서 오류 안내와 **다시 불러오기** 버튼을 보여 준다. 이미지·favicon·preload 같은 비필수 리소스 실패는 앱 전체의 시작 실패로 처리하지 않는다. 준비 완료 뒤의 일반 오류가 스켈레톤을 다시 띄우거나, 실패 뒤 늦게 도착한 완료 이벤트가 깨진 페이지를 노출하지 않게 한다.

동작 줄이기 설정에서는 스켈레톤 애니메이션을 끈다. JavaScript가 꺼져 있으면 별도의 정적인 안내를 보여 준다.

## 검증

[`boot-shell.test.mjs`](../tests/boot-shell.test.mjs)는 실제 HTML의 초기 컨트롤러를 실행한다. 수정 전에는 초기 컨트롤러가 없어 실패했고, 비필수 리소스를 치명적 오류로 처리하는 경우도 별도 반례로 확인했다. 현재 네 가지 테스트가 다음 동작을 검사한다.

- 데이터·렌더링을 기다리는 동안 문서 로드 이벤트가 와도 준비 상태를 유지한다.
- 실제 준비가 끝나면 한 번만 공개하고 이후 오류가 스켈레톤을 되살리지 않는다.
- 초기 실패는 접근 가능한 오류 안내로 바뀌며 다시 불러오기 버튼이 동작한다.
- 비필수 리소스 실패는 통과시키고 모듈·스타일시트 실패는 복구 화면에 연결한다.

별도로 실제 `app.js`와 그 모듈을 DOM 환경에서 실행했다. 일말 데이터 응답을 보류하고 예약된 프레임을 실행해도 완료 이벤트는 0회였다. 응답을 제공하면 기본 차트·원자료·리서치·이전 비교 화면 각각에서 실제 SVG나 표가 생성된 뒤 완료 이벤트가 한 번 발생했다. 초기 HTTP 503은 공개 없이 오류 상태로 끝났다. 이는 초기화 동작 검사이며 브라우저 paint나 물리 휴대전화 성능 측정은 아니다.

버전 URL을 `v1.10.5`로 함께 올려 새 HTML과 완료 신호를 보내지 않는 이전 캐시 모듈이 섞이지 않게 했다. 단일 HTML 내보내기도 같은 스켈레톤·완료 조건을 포함한다. 전체 회귀·정적·단일 파일 검사는 [감사 기록](MATH_STATE_AUDIT.md)에 연결한다.

## 화면 확인

[`mobile-preview.html`](../dist/mobile-preview.html)의 화면 크기와 표시 상태를 바꾸면 실제 페이지 또는 일시 정지한 초기 로딩·실패 모양을 확인할 수 있다. 미리보기는 원래 `index.html`에서 초기 화면을 읽으며, 모양을 별도로 복제하지 않는다. 정지한 미리보기의 대기 시간은 실제 사이트의 로딩 속도가 아니다.
