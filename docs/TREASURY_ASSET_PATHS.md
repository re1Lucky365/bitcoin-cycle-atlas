# MSTR·BMNR 기초자산 경로의 방법과 경계

작성·검토일: **2026-10-24**. 구현: [treasury-asset-paths.js](../dist/treasury-asset-paths.js). 재무 변환과 범위 해석은 [TREASURY_PATH_MODEL.md](TREASURY_PATH_MODEL.md), 기존 공시 기반 재무 항등식과 목표 연결 방법은 [TREASURY_MODEL.md](TREASURY_MODEL.md)를 함께 읽는다.

이 모듈은 BTC 또는 ETH의 **조건별 일별 가격 경로**를 만든다. 보유 코인, 주식 수, 발행, 비용, 상환, 스테이킹과 프리미엄을 적용하는 재무 엔진은 별도다. 기본 자산 연동 모드에서는 이 경로를 재무 엔진에 그대로 전달한다. 기존 목표 연결 모드는 목표 사이를 로그 보간하는 민감도 비교로 남으며, 두 방법의 결과를 동일한 계산으로 해석하지 않는다.

세 조건 `stress`, `base`, `bull`은 경제·재무 전제의 비교다. 각 조건에는 하나의 일관된 대표 경로가 있으며 조건별 확률, 확률 분위수 또는 예측 정확도를 부여하지 않는다. 세 조건의 최솟값·최댓값으로 만든 표시 범위도 가능한 손실의 전부를 포함하는 경계가 아니다.

## 1. 공개 계약

```js
import { buildTreasuryAssetPaths } from '../dist/treasury-asset-paths.js';

const assetPaths = buildTreasuryAssetPaths({
  symbol: 'MSTR',               // 'MSTR' 또는 'BMNR'
  btcHistory,                  // MSTR: { prices: [[date, price], ...] }
  ethHistory,                  // BMNR: Coinbase archive, 파싱된 candles 또는 일별 배열
  asOf: '2026-10-23',           // 실제 주식 관측의 마지막 세션 날짜
  endYear: 2035,                // 기본 2035, 허용 2027–2050
  seed: 20261022,               // 기본 seed, 부호 없는 32비트 정수
});
```

반환값은 `asset`, `asOf`, `endDate`, `scenarios`, `metadata`, `warnings`를 포함한다. 각 조건은 다음 계약을 갖는다.

| 필드 | 의미 |
| --- | --- |
| `id`, `asset`, `asOf`, `endDate` | 조건, 기초자산, 관측 기준일, 요청한 종료일 |
| `path` | `{date, price, baselinePrice, kind, sourceIds}`의 일별 배열 |
| `method` | BTC 공통 엔진 또는 ETH Merge 이후 블록 방식 |
| `sourceIds` | 연구 읽기 화면의 출처 식별자 |
| `anchors` | 출처 또는 앱 가정에 따른 기준선 가격 조건. 대표 가격의 강제 도착점이 아님 |
| `training` | 관측 범위, `maxSourceDate`, 연구 기준일 및 방법별 추출 정보 |
| `metadata`, `warnings` | seed, 모형 가정, 확률·OHLC 주장 없음 등의 해석 경계 |

첫 점은 정확한 `asOf`의 관측 코인 가격이며 `kind='observed-anchor'`다. 그 뒤부터 지정한 연말까지 하루도 건너뛰지 않는 UTC 날짜를 반환하고 `kind='conditional-asset-path'`로 표시한다. 재무 엔진은 이 시작 가격과 자체 정규화에 사용한 코인 가격이 일치하는지 확인한다. 맞추기 위한 자동 재조정은 하지 않는다.

`path`에는 `open`, `high`, `low`, `close`가 없다. 모의 일별 가격만으로 실제 장중 OHLC를 알 수 없다. 미래 차트 봉을 별도로 구성할 때도 실제 관측 봉과 모의 범위의 정의를 구분해야 한다.

## 2. MSTR: BTC 화면의 실제 엔진 재사용

[buildLongHorizonForecast](../dist/long-horizon-forecast.js)를 조건마다 직접 호출한다. BTC 엔진의 원본 로직을 이 모듈에 복제하거나 MSTR용으로 다시 그리지 않는다.

| MSTR 조건 | BTC 엔진 조건 | 사용 방식 |
| --- | --- | --- |
| `stress` | `stress` | 같은 관측·seed의 BTC 경로 |
| `base` | `base` | 같은 관측·seed의 BTC 경로 |
| `bull` | `accelerated` | 같은 관측·seed의 BTC 경로 |

`date`, `price`, `baselinePrice`는 원본 엔진 결과 중 요청한 종료일까지의 값을 그대로 쓴다. 별도의 세일러 목표에 가격을 맞추지 않는다. 기존 목표 연결 비교 모드에 보존된 경영진 목표와, 이 모드의 공통 BTC 경로는 서로 다른 조건이다.

BTC 엔진의 [장기 근거 입력](../dist/long-horizon-evidence.js), 초기 구간 경로, 가치평가 기준선, 감쇠하는 주기 요소와 대표 잔차 처리는 그대로 유지한다. 장기 경로는 조건당 표본 하나다. 엔진의 초기 구간 추정에 사용하는 표본 수를 전체 장기 경로의 표본 수나 신뢰구간으로 설명하지 않는다. 단순히 같은 진폭의 4년 파동을 미래 끝까지 반복한 경로가 아니다.

관측 자료는 먼저 `asOf` 이하로 자른다. 엔진에 전달하는 `researchAsOf`는 `min(asOf, LONG_HORIZON_REVIEW_DATE)`이며 이 구현의 리뷰 날짜 상수는 2026-10-22다. 연구 발행일을 지난 시점에서 알고 있는 조건을 사용하는 것과, 과거 어느 시점에 모델 자체를 선택했을지 검증하는 것은 다르다. 이 래퍼는 과거 시점의 투자 성과 검증을 제공하지 않는다.

## 3. BMNR: ETH의 조건 기준선과 과거 수익률 블록

### 관측 체제와 최소 자료

[Ethereum 공식 Merge 설명](https://ethereum.org/en/roadmap/merge/)은 2022-09-15에 PoW에서 PoS로 전환했다고 기록한다. [발행 구조 설명](https://ethereum.org/en/roadmap/merge/issuance/)은 발행과 소각이 공급에 영향을 주며 발행량이 스테이킹 규모에 따라 달라짐을 설명한다. 이 사실은 관측 체제를 나누는 근거다. ETH 가격에 특정 4년 주기나 730일 평균회귀가 존재한다는 증거로 사용하지 않는다.

모듈은 2022-09-15 이후의 연속된 일별 종가를 사용한다. 9월 15일 종가를 포함할 수 있지만 그 이전 종가와 연결한 수익률은 포함하지 않는다. 적어도 366개의 완료된 관측이 필요하며 이 구간에 누락일이 있으면 오류를 반환한다. 누락일 보간, BTC 경로 대입 또는 임의의 전망으로 대체하지 않는다.

원본 Coinbase archive에서는 바깥 객체와 `dailyHistory` 양쪽의 출처가 `Coinbase Exchange`, 상품이 `ETH-USD`여야 하며 `dailyHistory.completedOnly`가 `true`여야 한다. 배열 또는 파싱된 종가 입력도 허용하지만, 그 형식만으로 거래소의 원응답 무결성을 새로 입증하지는 않는다. 모든 형식에 날짜 순서·중복·유효한 양의 가격 검사를 적용한다.

### 경제 조건과 출처의 분류

[VanEck의 2024-06-05 ETH 평가](https://www.vaneck.com/us/en/blogs/digital-assets/matthew-sigel-eth-2030-price-target/)는 2030년 약세·기준·강세 조건을 각각 $360·$22,000·$154,000으로 제시한다. 발행사가 ETH·BTC를 보유한다고 밝힌 조건부 평가이며, 현재 시점의 새 전망이나 관측 사실로 소개하지 않는다. Atlas는 다음과 같이 일부 조건을 선택한다.

| 앱 조건 | 2030-12-31 기준선 | 출처와 분류 |
| --- | --- | --- |
| `stress` | $360 | VanEck 2024의 약세 조건 |
| `base` | `asOf`의 관측 ETH 가격 | 앱의 가격 유지 가정 |
| `bull` | $22,000 | VanEck 2024의 **기준** 조건을 앱의 채택 확대 조건으로 사용 |

VanEck의 $154,000 강세 조건은 이 기본 세 경로에 사용하지 않는다. 앱의 `bull`을 VanEck 원문의 강세 조건이라고 부르지 않는다. 톰 리의 ETH 가격 조건과 BMNR 목표 역시 별도의 경영진 주장으로 보존하며 이 경로의 도착 가격을 강제하는 데 사용하지 않는다.

기준선은 현재 관측 가격에서 위 가격 조건까지 로그 보간한다. 2030년 연말 배치는 앱의 달력 규칙이며 원문의 정확한 실현 일자를 뜻하지 않는다. 2030년 이후에는 **기준선만** 고정하고 아래 잔차는 계속 변한다. 자료 발행 전인 `asOf < 2024-06-05`에는 이 조건을 쓰지 못하며, `asOf >= 2030-12-31`에는 새 검토 자료가 필요하다는 오류를 반환한다.

### 재표본과 잔차 계산

1. 선택한 관측의 일별 로그 수익률을 계산하고 전체 관측 수익률의 평균과 표본 표준편차로 표준화한다. 과거의 평균 성장률을 미래로 연장하지 않는다.
2. 같은 관측 수익률에서 28일짜리 연속 블록을 복원 추출한다. 사용한 원본 시작·끝 날짜, 수익률 시작일, 미래에 배치한 시작·끝 날짜를 `training.representativeBlocks`에 기록한다.
3. 표준화한 수익률을 마지막 90일의 관측 일별 로그 수익률 표준편차로 다시 조정한다. 이 변동성 크기를 미래에도 유지하는 것은 앱 가정이다.
4. 잔차 `R`와 모의 가격 `P`는 다음과 같이 계산한다.

```text
R[0] = 0
rho = exp(-ln(2) / 730)
R[t] = rho * R[t-1] + standardizedHistoricalReturn[t] * sigma90
P[t] = baselinePrice[t] * exp(R[t])
```

**730일 잔차 반감기**는 추정하거나 과거 예측 성과로 선택한 계수가 아닌 명시적 앱 가정이다. 미래 변동성 고정, 블록 길이 28일, 관측 창 90일, 2030년 이후 기준선 유지도 같은 수준의 구현 가정이다. 공식 Ethereum 문서나 VanEck가 이 계수들을 제시한 것으로 설명하지 않는다.

세 경제 조건은 같은 seed에서 만든 **하나의 잔차 경로를 공유**한다. 따라서 조건 차이를 비교할 때 서로 다른 우연한 잡음이 추가되지 않는다. 그 대신 세 조건을 독립 표본 세 개로 세거나 신뢰구간을 계산해서는 안 된다. 겹치는 역사 블록의 복원 추출도 독립적인 시장 체제의 수를 늘리지 않는다. 실제 미래는 이 예시보다 큰 급등·급락이나 다른 변동성 구조를 가질 수 있다.

## 4. 재현성과 시간 경계

기본 seed는 `20261022`다. BTC에는 같은 seed를 전달하고 ETH는 `seed XOR 0x455448`로 구분한 결정적 난수열을 사용한다. 입력 관측·방법·seed가 같으면 결과가 같고, 종료 연도만 늘려도 앞 구간의 가격은 그대로다. seed를 바꿔 얻는 다른 예시는 검증된 확률표본이 아니다.

| 경계 | 처리와 의미 |
| --- | --- |
| 주식 마지막 세션 | 호출자가 실제 주식의 마지막 관측 날짜를 `asOf`로 전달한다. |
| 코인 관측 | 해당 날짜의 정확한 종가가 필요하다. 이후 날짜의 가격을 끌어오지 않는다. |
| 미래 행 | 유효한 날짜 순서로 제공된 이후 가격은 관측·추출에서 제외한다. 입력 전체의 날짜 구조 오류까지 묵인하는 것은 아니다. |
| ETH 과거 블록 | 원본 블록의 끝 날짜가 `asOf`를 넘지 않는다. |
| 재무 계산 | 달력 날짜의 코인 경로를 사용한다. 주식 거래 세션에 맞춘 표시 방식은 별도 계층이다. |
| 종가 시각 | 같은 날짜의 UTC 일말 코인 관측과 뉴욕 주식 종가는 동시 시각이 아니다. |

마지막 행의 시각 차이 때문에 이 연결을 장중 동시 매매 가격이나 엄밀한 과거 시점 투자 검증으로 표현하지 않는다. 관측 날짜 자르기는 미래 달력 날짜의 가격 유입을 막지만, 모델 설계·연구 선택의 과거 빈티지까지 복원하지 않는다. 반환값은 `historicalVintageBacktest=false`, `calibrated=false`, `probability=null`, `ohlcClaim=false`로 그 범위를 표시한다.

## 5. 연구 식별자와 보존 범위

현재 연구 카탈로그에서 다음 식별자가 모두 실제 항목으로 해석되는지 확인했다. 원본 방법 기록의 위치는 [research-methods.js](../dist/research-methods.js)이며 생성된 읽기 화면 자료와 구분한다.

| 경로 | 식별자 | 연결되는 근거 |
| --- | --- | --- |
| BTC | `long-wisdomtree-2030`, `long-wisdomtree-2050` | 기존 BTC 엔진의 조건별 장기 평가 출처 |
| MSTR | `mstr-model-method` | BTC 경로를 재무 상태에 연결하는 자체 방법 |
| ETH | `model-eth-valuation` | VanEck 2024의 평가 조건과 앱 분류 차이 |
| ETH | `eth-merge-eip-3675` | PoS 전환에 관한 프로토콜 자료 |
| BMNR | `bmnr-model-method` | ETH 경로·스테이킹·비용·희석을 구분하는 자체 방법 |

이 문서는 외부 문서의 짧은 사실 요약과 링크, 앱의 계산·가정을 보존한다. Ethereum 설명 페이지나 VanEck 보고서 전체, 이미지, 동영상을 새로 복제하지 않는다. 저장소의 별도 CC0 원문 보존 절차와 이 방법 문서의 외부 요약은 서로 다른 범위다.

## 6. 이 모듈에서 확인한 검사

2026-10-24에 다음 명령으로 **13개 개별 검사 통과, 0개 실패**를 확인했다. raw archive의 상품·출처 충돌 반례를 보강한 뒤 다시 실행한 기록이다.

```sh
node tests/treasury-asset-paths.test.mjs
```

[검사 파일](../tests/treasury-asset-paths.test.mjs)은 BTC 세 조건과 원본 엔진의 날짜·가격·기준선 일치, ETH의 정확한 시작점과 연속일, 공유 잔차와 기준선 구분, 블록 출처 날짜, 미래 관측 불변성, Merge 이전 가격 제외, seed 재현성, 긴 종료 연도의 앞 구간 보존, 누락·부족 자료 거부, 정확한 기준일 요구, 잘못된 날짜·중복·순서·시간 충돌, 비양수·무변동 가격 거부, archive 정체성, 공개 입력 범위를 확인한다.

이 기록은 모듈의 계산 계약과 입력 경계 검증이다. 전체 저장소 테스트, 재무 통합·화면·배포의 완료 기록이나 미래 가격 예측 성능으로 확대해서 읽지 않는다. 재무 수지의 독립 검증과 출시 상태는 해당 작업 문서에서 별도로 확인한다.
