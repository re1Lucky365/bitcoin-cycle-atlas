## 원인과 변경

### 1. 일별 페이지 이동이 숨김 월별 표를 매번 생성

`paintDetail`은 `일별 상세`가 열려 있어도 월별 비교표를 만들었다. 실제 자료로 재현한 별도 CPU 프로파일에서 `formatDailyPercent`가 가장 큰 자기 시간을 차지했고, 대부분의 추가 값은 현재 보이지 않는 월별 heatmap 셀을 만들기 위해 포맷되었다. 숫자 포맷 자체를 바꾸기 전에 사용하지 않는 생성 작업부터 제거했다.

`state.detail === 'monthly'`일 때만 `renderMonthlyDataTable`을 호출한다. 월별 보기를 여는 경로는 매번 최신 선택 자산·연도·지표·데이터로 `paintDetail`을 수행하므로, 일별 보기에서 바뀐 설정이 나중에 이전 월별 표로 보이는 문제를 만들지 않는다. 로딩 실패의 빈 상태 처리는 유지한다. 별도의 행렬 캐시나 무효화 키를 추가하지 않았다.

### 2. 비교뷰가 완성된 분석 결과를 다시 계산

`analyzeMarketStructure`는 현재 threshold의 일별·주별 국면과 전환점을 이미 모두 반환한다. `structure()`는 이 분석을 데이터 객체와 threshold에 맞게 재사용하지만 `drawStructure`는 같은 자료로 `computeRollingStates`와 `detectDirectionalChanges`를 다시 호출했다. 따라서 범위·정렬·주기 전환은 계산 입력이 달라지지 않은 경우에도 전체 관측을 재분석했다.

`drawStructure`에서 주기에 맞는 `a.dailyStates`/`a.weeklyStates`와 `a.pivots[state.structureFrequency]`를 선택한다. 차트·타임라인·표의 생성은 계속 수행한다. 기존 데이터 교체 및 threshold 변경의 분석 무효화 규칙을 그대로 사용하며, 추가 전역 캐시를 만들지 않는다.
