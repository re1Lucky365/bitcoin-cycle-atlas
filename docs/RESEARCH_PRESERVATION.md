# 리서치 보존과 열람 안내

검토 기준: **2026-10-24**. 이 문서의 수량은 생성된 [자료 카탈로그](../dist/research-library-data.js)와 [보존본 명세](../dist/research/manifest.json)를 기준으로 한다.

현재 BTCUSD·ETHUSD·MSTR·BMNR의 **488개 연구 글**을 Markdown으로 보존한다. 카탈로그의 **492개 ID 연결**은 정식 자료 488개의 자기 연결과 기존 주소를 유지하는 별칭 4개로 구성된다. 492개의 독립된 증거를 뜻하지 않는다. 분류별로 공시·재무 25개, 원자료·관측 46개, 모델·검증 방법 157개, 경영진·기관 전망 23개, 반론·정책·위험 237개다.

이 보존본은 **Atlas가 직접 작성한 요약·분석·검토와 출처 기록**이다. 외부 원문이나 영상이 사라져도 이 연구 기록은 읽을 수 있다. 사라진 원문 전체, 모든 게시물, 이미지·영상 파일까지 복원할 수 있는 완전한 웹 아카이브는 아니다.

## 1. 보존하는 내용과 범위

| 항목 | 현재 보존하는 내용 |
|---|---|
| 제목·작성자 | 연구 글 제목, 확인한 원제, 작성자·발행자, 원문 주소 |
| 날짜·위치 | 확인된 발행일, 검토 기록, 원문의 표·문단·페이지 위치와 접근 한계 |
| 본문 | 직접 작성한 요약, 주장별 판정·평가, 대조 자료, 반대 조건과 미확인 사항 |
| 푸터 | 권리 귀속·접근 가능성·보존 범위를 설명하는 Atlas 고지 |
| 이미지·동영상 | 확보한 제목·종류·URL과 링크만 보존했다는 표시 |
| 검증 정보 | 정식 자료 ID, 별칭, 원문 URL, Markdown 바이트 수와 SHA-256 |

외부 글의 전체 본문·댓글·전사, 원문 페이지의 전체 푸터와 화면 구성, 이미지·동영상 원본 파일은 이번 보존 대상에 포함하지 않는다. 별도 미디어 URL을 확보하지 못했다는 표시는 원문에 미디어가 없다는 뜻도 아니다. 현재 카탈로그에는 `completeSourceText: false`, `mediaBytesArchived: false`가 명시되어 있다.

공개 열람 가능한 자료라는 사실만으로 전체 복제·재배포 허락을 받은 것으로 취급하지 않는다. 원문·사진·차트·영상의 권리는 각 권리자에게 있으며, 이 프로젝트는 출처를 연결하고 자체 요약을 보존한다. 향후 권리자가 제공한 재배포 허락이나 명확한 라이선스에 따라 원본 파일을 추가한다면, 허용 범위·버전·권리 표시·파일 출처를 별도로 기록해야 한다. 현재 아카이브에 그러한 원본이 모두 포함되어 있다고 설명해서는 안 된다.

프로젝트가 작성한 모델 설명, 연구 보고서, 코드와 자료 구조는 저장소에서 함께 관리한다. [모델 범위](MODEL_SCOPE.md), [재무 기반 모델](TREASURY_MODEL.md), [MSTR 연구](research/mstr-2026-10-24.md), [BMNR 연구](research/bmnr-2026-10-24.md)를 통해 요약을 실제 계산·판단과 연결할 수 있다.

## 2. 앱에서 읽고 출처로 이동하기

앱의 **리서치 읽기 순서**에서 제목이나 **읽기**를 누르면 연구 글이 열린다. 종목과 분류로 범위를 좁히고, 제목·글쓴이·요약·주장·평가 문장으로 검색할 수 있다. 공시·원자료를 먼저 읽고 모델 가정, 경영진 전망, 반대 근거를 대조하면 보유량 같은 관측과 가격 목표 같은 조건부 주장을 구별하기 쉽다.

열람 경로는 다음과 같다. 주소의 필터는 선택 변경 시 갱신되므로 공유하거나 새로 열 때 같은 검색 조건을 사용할 수 있다.

```text
?page=evidence
?page=evidence&research-asset=BMNR
?page=evidence&research-asset=MSTR&research-category=filing
?page=evidence&research-asset=BMNR&research-q=2.58%25
?page=evidence&article=bmnr-2026-q3-10q
```

`research-asset`은 종목, `research-category`는 `filing`·`data`·`method`·`leadership`·`risk`, `research-q`는 검색어다. `article`은 연구 글의 ID다. 원문 URL이 같은 자료는 정식 글 하나에 연결될 수 있으며, 기존 ID도 별칭을 거쳐 그 글을 연다. 재전파·별칭을 독립 출처 여러 개로 세지 않는다.

글 안의 **함께 대조할 자료**는 연결된 연구 글을 열고, **원문 열기**는 원 발행자의 외부 페이지를 연다. 외부 페이지와 미디어에는 네트워크가 필요하다. **MD 저장**은 현재 읽는 Atlas 보존본을 내려받는다. 저장소에서는 [전체 읽기 순서](TREASURY_RESEARCH_INDEX.md)와 `dist/research/<자료 ID>.md`로 직접 읽을 수 있다. 미래 차트의 근거 표시는 해당 모형·출처로 연결되며, 그 표시 날짜 자체가 예정된 시장 사건이나 목표가 실현일을 뜻하지 않는다.

## 3. 날짜와 접근 상태를 읽는 방법

**발행일, 자료 기준일, 검토일은 서로 다르다.** `publishedAt`은 출처가 발행된 날짜이고, `reviewedAt`은 기록을 검토·정리한 날짜다. 발행일을 확인하지 못했으면 `null`과 ‘미확인’을 유지한다. 검토일로 발행일을 대신하지 않는다. 기존 자료에 남은 UTC·추정 날짜 표기도 정확도를 높여 쓰지 않는다.

재무 스냅샷의 `asOf`는 재무 상태의 기준일이다. 예를 들어 BMNR의 2026-05-31 재무 자료는 2026-07-14 공시와 구분된다. 가격 관측일, 모델 발행일, 향후 목표 연도도 따로 기록한다. 최신 연구 검토일이 오래된 재무 상태를 현재 재무 상태로 바꾸지는 않는다. 이전 BTC·ETH 조사에서 가져온 자료에는 이전 검토 내역과 재검토 범위에 대한 고지가 남아 있다.

| 접근 표기 | 해석 |
|---|---|
| `verified-primary` | 원 발행자의 자료에서 기재된 내용을 확인했다. 모든 문단·미디어를 보존했다는 뜻은 아니다. |
| `verified-excerpt` | 확인 가능한 발췌 범위가 있다. 원문 전체·전체 영상·편집 이력까지 확인했다고 확대하지 않는다. |
| `metadata-only` | 계정·제목·주소 같은 메타데이터만 확인했다. 본문 주장에 대한 증거로 사용하지 않는다. |
| `retrieved-provider-data` | 가격 등 제공자 자료를 수신·기록했다. 개별 자료의 시점·정의·검산 범위를 함께 읽는다. |
| `original-research` | 프로젝트가 작성한 방법·해석이다. 외부 기관이 검증한 결과로 표시하지 않는다. |
| `prior-primary-review` / `prior-secondary-review` | 기존 조사에서 보존한 1차·2차 출처 기록이다. 이번 변경에서 원문을 모두 다시 읽었다는 뜻은 아니다. |
| 기존 한국어 접근 기록 | 403, 공개 도입부만 확인, 유료 본문 미열람 등 개별 설명을 그대로 따른다. |

주장의 `fact`는 기록 확인, `conditional`은 조건부 주장, `unverified`는 검증 보류, `contradicted`는 반대 증거 확인을 뜻한다. 접근 상태나 판정 하나만으로 출처 전체를 신뢰·불신으로 단정하지 않는다. 바로 아래 평가와 한계를 함께 읽어야 한다. 회사의 보유량 공시를 확인하는 것과 그 회사 경영진의 미래 가격 전망이 실현됨을 검증하는 것은 별개다.

### X 접근 실패와 사라진 자료

톰 리의 [X 경로 기록](../dist/research/bmnr-tom-lee-x.md)은 직접 요청이 403으로 차단되어 `metadata-only`다. 개별 게시물을 읽었다고 주장하지 않으며 계정 링크를 가격 목표의 증거로 사용하지 않는다. [세일러 X 발췌 기록](../dist/research/mstr-saylor-x-20260921.md)은 색인에 노출된 발췌와 회사 자료를 대조했지만 X 전체 본문을 확보한 기록은 아니다.

403·일시적인 오류는 삭제의 증거가 아니다. 실제 삭제·접근 불가가 확인되면 확인 날짜와 상태, 이전에 확인한 범위, 독립적으로 남아 있는 출처를 기록한다. 검색 색인이나 당시 보도에서 복원한 발췌는 원문 직접 열람과 구분한다. 사라진 문장을 추측해서 채우거나 전체 스레드·영상 시청을 주장하지 않는다. 보존된 자체 요약은 계속 열람할 수 있지만, 외부 원문의 지속적인 접근과 복원을 보장하지 않는다.

## 4. 다운로드와 SHA-256의 관계

빌드와 브라우저의 **MD 저장**은 [같은 순수 직렬화 함수](../dist/research-format.js), `serializeResearchArticleMarkdown(record, aliases)`를 사용한다. 따라서 동일한 카탈로그 버전에서는 다음 세 대상이 일치해야 한다.

1. `dist/research/<ID>.md`의 UTF-8 바이트
2. 리더에서 내려받는 `<ID>.md`의 UTF-8 바이트
3. `dist/research/manifest.json`의 `sha256`·`bytes`와 리더의 검증 식별자

현재 488개 Markdown 본문의 합계는 **891,455바이트**다. 명세는 각 글의 ID·경로·원문 URL·해시·바이트 수를 보존하며, 파일을 수정하면 해시가 바뀐다. 해시는 Markdown 본문 밖의 명세·카탈로그에 기록하여 자기 자신을 해시에 넣는 순환을 피한다. [리더 테스트](../tests/research-reader.test.mjs)는 표본만 고르지 않고 모든 글의 다운로드·저장 파일·해시·바이트 수와 별칭을 대조한다.

이 해시는 **어느 내용의 보존본인지** 확인하는 수단이다. 외부 원문의 진실성, 저자의 신원, 법적 증명력이나 미래 예측 정확도를 보증하지 않는다. 이전 버전과 비교할 때는 파일과 명세가 같은 Git 커밋·릴리스에서 나온 것인지도 확인한다.

## 5. 유지관리자가 새 자료를 추가할 때

**입력 자료를 수정한 뒤 생성물을 다시 만든다.** 생성된 Markdown이나 `research-library-data.js`만 직접 고치면 다음 빌드에서 변경이 사라지고 명세와 불일치한다.

| 자료 종류 | 수정할 입력 |
|---|---|
| MSTR·BMNR 공시·주장·사건 | `research-data/treasury-mstr.json`, `research-data/treasury-bmnr.json` |
| 공통 방법·가격 자료 설명 | `dist/research-methods.js` |
| 기존 BTC 읽기 순서 | `dist/evidence-index.js` 및 그 자료가 참조하는 출처 기록 |
| ETH 역사 사건 출처 | `research-data/ethereum-*-events.json`의 관련 원본 파일 |

새 기록에는 안정적인 ID, 원제·작성자·발행자·URL, 확인된 발행일, 실제 접근 범위, 직접 작성한 요약, 주장별 판정·대조 ID, 한계, 미디어 링크와 보존 고지를 넣는다. 미확인 이름·날짜·목표 연도를 만들어 넣지 않는다. 각 대조 자료가 같은 회사 발표를 재인용한 것인지도 확인한다. 같은 URL이 이미 있다면 정식 입력 자료를 수정해야 한다. 현재 생성기는 URL 중복을 별칭으로 연결하며, 중복 입력의 새 본문·주장을 자동으로 합치지 않는다.

저작권이 있는 글·영상의 전문을 요약 필드에 붙여 넣지 않는다. 확인에 필요한 짧은 인용과 독자적인 요약을 구분하고, 실제 확인 범위보다 접근 등급을 높이지 않는다. HTML 텍스트와 Markdown 링크의 이스케이프, HTTP(S) 외 URL 차단은 공통 직렬화·리더 경로를 유지한다.

저장소 루트에서 MSTR·BMNR 입력을 반영하는 기본 순서는 다음과 같다. ETH 입력을 바꾼 경우에는 먼저 `node scripts/build-ethereum-events.mjs`를 실행한다.

```sh
node scripts/build-treasury-research.mjs
node scripts/build-research-library.mjs
node scripts/build-treasury-research.mjs --check
node scripts/build-research-library.mjs --check
node tests/research-reader.test.mjs
```

생성된 본문·명세·카탈로그·읽기 순서를 같은 커밋에 포함하고, 브라우저에서 해당 자료의 필터·별칭·교차 링크·다운로드를 확인한다. 자료를 추가·수정했다면 이 문서의 수량도 생성 결과로 갱신한다. 기존 버전의 의미 있는 기록은 Git 이력과 해당 릴리스의 파일로 추적한다.

이번 릴리스에는 보존본을 모은 **`Research_Library.zip`**과 소스 커밋 식별자를 포함할 계획이다. 패키지를 만든 뒤에는 그 안의 명세와 실제 파일이 같은 소스 커밋에 대응하는지 확인해야 한다. 이 문서는 패키지 업로드나 릴리스 게시 완료를 선언하지 않는다. 완료 여부와 제공 파일은 해당 [GitHub 릴리스](https://github.com/twoimo/bitcoin-cycle-atlas/releases)에서 확인한다.
