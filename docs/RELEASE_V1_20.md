# v1.20.0 · MSTR·BMNR의 일별 자산 연동 경로

MSTR·BMNR의 기본 미래 표시를 목표 가격 사이의 보간에서 **코인의 일별 모의 경로를 재무 계산에 전달하는 방식**으로 바꿨다. MSTR는 기존 BTC 엔진의 같은 조건·seed 출력을 사용하고, BMNR는 Merge 이후 ETH 관측으로 별도 경로를 만든다. BTC 엔진의 가격 생성 로직은 이번 변경에서 수정하지 않았다.

이 변경은 더 세밀한 조건부 계산과 그 근거를 제공한다. 주가 예측 정확도, 회사의 최신 NAV, 경영진 목표 달성 가능성 또는 보정된 발생 확률을 입증한 변경은 아니다.

## 사용 방법

1. [MSTR](https://twoimo.github.io/bitcoin-cycle-atlas/?symbol=MSTR) 또는 [BMNR](https://twoimo.github.io/bitcoin-cycle-atlas/?symbol=BMNR)를 연다.
2. 상단의 **가격선 / 관측 캔들·모의 경로봉**, **1D / 1W**, **스트레스 / 기준 가정 / 채택 확대**를 선택한다.
3. 미래 원형 표식이나 **미래 전망과 근거**를 누른다. 선택한 날짜의 코인 가격, 보유량, 현금, 청구권, 주식 수, 시장 프리미엄과 자금 조달을 읽을 수 있다.
4. 근거 창의 날짜 선택은 계약 일정·기준선 조건·모의 고저점 후보를 구분한다. **이 날짜를 차트에서 보기**는 일별 표시로 이동한다. 주말 평가일은 해당 날짜의 값을 가진 가격선으로 전환한다.

## 경로와 재무 계산

| 대상 | 기본 기초자산 경로 | 해석 경계 |
|---|---|---|
| MSTR | BTC `stress / base / accelerated`를 주식 `stress / base / bull`에 대응 | 같은 관측 cutoff·seed에서 BTC 엔진의 날짜와 가격을 그대로 소비한다. 세일러의 별도 목표를 종착값으로 강제하지 않는다. |
| BMNR | Merge 이후 ETH 수익률의 28일 블록과 경제 조건 기준선 | 최근 90일 변동성 유지, 잔차 730일 반감 평균회귀, 2030년 이후 기준선 유지는 앱 가정이다. BTC의 4년 반복을 넣지 않는다. |
| 주식 재무 | 매일 현금 비용·스테이킹·상환·희석·발행·보유 한도를 계산 | 주말에도 평가한다. 연간 발행률의 일별 배분은 실제 주말 증권 발행 기록이 아니다. |
| 음영 | 세 완결된 재무 경로의 같은 날짜 최소·최대 | 통계적 분위수, 신뢰구간, 가능한 손실 전체의 범위가 아니다. |

각 조건은 seed `20261022`의 대표 경로 한 개다. 외부 평가 숫자는 기준선이며 변동이 더해진 경로의 종착값을 그 숫자로 맞추지 않는다. BMNR의 $22,000은 원자료의 2030년 기준 평가 조건을 앱의 채택 확대 조건에 사용한 것이다. 명칭의 차이를 유지하고 발행사의 확정 목표나 실제 도착 가격으로 표시하지 않는다.

금융 전이는 기존 수지 보존 함수를 재사용한다. 부분 발행, 현금 우선 지급, 매도비용, 미지급액, 보유 상한과 초과 스테이킹 보상 매각을 유지한다. 동일 종착 코인 가격이어도 중간 가격에 따라 매도 수량·발행량·잔여가치가 달라진다. 새 일별 회계와 기존 약 30일 회계의 차이는 [재무 경로 문서의 비교표](TREASURY_PATH_MODEL.md#5-저장-관측으로-재현한-비교)에 분리했다.

기존 `buildTreasuryForecast()`의 `assetPaths` 없는 호출은 `target-interpolation` 비교 모드로 남긴다. 기본 화면과 릴리스 JSON은 `buildTreasuryProjection()`의 `asset-linked-daily` 결과를 사용한다. [기존 모델 문서](TREASURY_MODEL.md)의 숫자표는 비교 모드의 고정 예제이며 새 화면의 기본 숫자가 아니다.

## 표시와 근거

미래 가격선은 주말을 포함한 일별 평가값을 연결한다. 빈 모의 경로봉은 선택한 같은 경로의 값만 집계한다. `candle.high/low`와 세 조건 범위 `low/high`는 별개다. 주중 표시 사이의 주말 변화는 다음 표시 구간에 포함한다. 주봉은 같은 모의 일별 구간을 모으며 실제 미국 거래소 휴장 달력이나 장중 체결 OHLC를 예측하지 않는다. 미래 거래량도 만들지 않는다.

고점·저점 표식은 선택 경로의 **12% 반전 규칙으로 사후 구분한 후보**다. 후보 날짜와 경로 안에서의 반전 확인일을 나눠 보여 준다. 실제 미래 사건이나 확정 전환점·확률 신호가 아니다. 잔여가치 소진 후 0을 유지하는 조건은 별도 표식으로 구분하고 로그축에서 가짜 양수로 바꾸지 않는다.

근거 창은 재무 기준일, 주식 가격일, 같은 날짜의 UTC 코인 관측, 코인 수집 시각, 모형 작성·검토일, 이번 화면의 계산 시각을 구별한다. 뉴욕 주식 종가와 UTC 코인 일말 값은 동시 가격이 아니다. MSTR·BMNR의 날짜가 맞는 과거 재무 상태를 계속 사용하며 최신 보유량 보도자료와 과거 주식 수를 섞지 않는다.

세 경로는 자료 로딩 성공 때 한 번 계산한다. 조건 전환·이동·근거 비교에서는 같은 결과를 재사용한다. 주식 자료가 준비되어도 코인 입력 검증이 실패하면 관측 차트를 유지하고 전망 입력 오류와 재시도를 표시한다. 오래된 응답이 새 요청을 덮어쓰지 않게 요청 소유권을 확인한다.

## 검증 범위

독립 검산은 [스크립트](../scripts/verify-treasury-paths.mjs)와 [고정 입력 보고서](data/treasury-path-verification-2026-10-24.json)로 재현한다. 2026-10-23 관측을 고정해 두 종목·세 조건을 2050-12-31까지 검사한다.

- 경로당 8,836개 행, 총 53,010개 일별 재무 전이의 현금·코인·주식·청구권 수지를 별도 대수식으로 대조한다.
- MSTR의 세 코인 경로가 원래 BTC 엔진과 날짜·가격이 완전히 같은지 확인한다.
- ETH의 26,505개 일별 기준선·잔차를 기록된 원래 날짜의 수익률 블록과 별도 계산으로 대조한다.
- 미래 극단 관측을 덧붙여도 고정 cutoff 결과가 바뀌지 않는지, 같은 종착값의 다른 중간 경로가 다른 재무 결과를 만드는지 확인한다.
- 날짜·종목·출처 충돌, 누락·중복 관측, 오래된 코인 앵커, 비유한 값, 조건 간 0 전파를 검사한다.
- 관측 경계, 첫 부분 주봉, 밀집 경로봉, 작은 차트 폭, 선택·복사·자석 측정, 로그축 0 및 자체 연구 문서 중복 제거를 회귀 검사한다.

이 검산은 계산 연결성과 구현 경계를 확인한다. 과거 각 시점의 전체 기업 공시를 복원한 주식 투자성과 백테스트, 주가 예측 우위, 조달 가능성 검증과는 범위가 다르다. 공개 화면의 실제 기기 성능·휴장일·미래 장중 거래를 검증한 것으로 확대하지 않는다.

게시 전 현재 소스의 **93개 테스트 파일**과 아래 검사가 통과했다. 단일 HTML은 **46,006,275바이트·93개 내장 모듈**로 생성하고 정적·내장 자료 검사를 통과했다. 이는 실제 file:// 실행이나 실물 휴대기기 검증 기록은 아니다.

실행 명령은 `npm test`, `npm run verify:treasury-paths`, 연구·정적·사이클·성능·요청 소유권 검사 및 단일 HTML 생성·검사다. 정확한 해당 커밋의 실행 결과와 배포 상태는 [Actions](https://github.com/twoimo/bitcoin-cycle-atlas/actions)에서 확인한다.

## 내려받는 자료와 보존

`TREASURY_SCENARIO_RESULTS.json`은 화면과 같은 여섯 일별 경로, 입력 해시, seed, 기준일과 방법을 담는다. `RELEASE_METADATA.json`과 `SOURCE_COMMIT.txt`는 패키징한 소스 커밋을 기록한다. 단일 HTML에는 코인·주식 관측과 필요한 모듈을 포함하며 연구 ZIP에는 두 새 방법 문서와 독립 검산 보고서를 추가했다.

자체 연구 요약 490개와 식별자 494개, 재무 관련 출처 55개·역사 사건 43건을 유지한다. MSTR와 BMNR 계산법은 서로 다른 본문으로 보존한다. 외부 원문 보관 범위는 기존 CC0 EIP-1559·EIP-3675 두 개이며 이번에 다른 저작물 전문을 추가하지 않았다.

## 작업 방식

기준 커밋은 `0dcc7760d14c93f9038ea5ae26743a4dd9e06f03`이다. pstack의 근거 확인·도메인 경계·병렬 소유권·독립 검토 원칙을 적용했다. 이 세션의 GPT-6 Astra 에이전트 세 명과 주 담당자가 작업했으며 사용할 수 없는 Grok·Opus·Cursor 전용 실행을 했다고 주장하지 않는다. 기존 v1.19.0이나 미확인 Create Tree 요청을 다시 게시하지 않고 별도 변경으로 공개한다.
