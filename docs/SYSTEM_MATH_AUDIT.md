# 수식·재무 상태·해석 일치 감사

검토일은 2026-10-24다. 비교 기준은 `347997f02d3674259d4ad6e1f788419bde4811bd`이며, 이 문서는 수학 담당 작업의 범위를 기록한다. 병렬 성능·요청 상태·입력 경계 점검은 [전체 작업 기록](SYSTEM_AUDIT_WORK.md)에 별도로 정리한다.

초기 수학 작업의 [분리 검산 기록](data/system-math-audit-2026-10-24.json)과 독립 검토 뒤의 [최종 통합 검산](data/system-math-integration-2026-10-24.json)을 구별한다. 초기 기록의 수치 차이 570개는 최종 수치가 아니다. 아래 독립 검토 보완과 최종 비교 결과가 현재 구현을 설명한다.

**재현한 결함 3개 군을 수정했다.** 초과 원금 지급으로 생기는 잔여가치 손실, 선형·로그 되돌림의 불필요한 수치 손실, 흡수 상태를 빠뜨린 주가 공식과 반환값을 다룬다. 기존 저장 관측의 MSTR·BMNR 가격 경로는 바꾸지 않았다. 모든 가능한 입력의 안전성이나 시장 예측 우위를 증명한 것은 아니다.

## 1. 계산 구조와 검토 방법

실제 호출은 `buildTreasuryProjection` → `buildTreasuryAssetPaths` → `buildTreasuryForecasts`다. BTC 또는 ETH의 날짜별 가격을 세 재무 조건에 전달하고, 각 조건의 보유 코인·현금·선순위 청구권·보통주 수를 독립적으로 갱신한다. 세 주가를 모두 계산한 뒤 최소·최대로 범위를 만든다. 범위를 먼저 정해 개별 시나리오에 강제하는 구조가 아니다.

검토한 범위는 다음과 같다.

| 영역 | 확인한 성질 | 근거 |
|---|---|---|
| 지출과 원금 상환 | 미지급액 보존, 원금의 손익 중립성, 매각비용 차감 | [재무 함수](../dist/treasury-model.js), [324개 경계 조합](../tests/treasury-model.test.mjs) |
| 발행·상한·스테이킹 | 순조달액과 코인·현금·희석의 연결, 상한 초과 보상 매각 | [일별 검산기](../scripts/verify-treasury-paths.mjs) |
| 흡수 상태 | 한 조건의 소진이 다른 조건으로 전파되지 않음, 이후 산술 회복과 주가 종료 규칙의 구분 | [연동 검사](../tests/treasury-path-integration.test.mjs) |
| 되돌림 | 선형·로그의 유한한 값, 역방향 대칭, 기존 비율 입력 범위 | [시장 구조 검사](../tests/market-structure.test.mjs) |
| BTC 상세·장기 경로 | 관측 접두 사용, seed 재현, 종점과 중간점의 의미, 통계적 확률 주장 제한 | [상세 검사](../tests/detailed-forecast.test.mjs), [장기 검사](../tests/long-horizon-forecast.test.mjs) |
| ETH 경로 | 실제 날짜의 수익률, 90일 변동성, 730일 잔차 감쇠의 독립 재계산 | [일별 검산기](../scripts/verify-treasury-paths.mjs) |

[pstack 고정 판본](https://github.com/cursor/plugins/tree/9580c23696ac8d7abed0c166f2f9918800afb819/pstack)의 `how`, `principle-model-the-domain`, `principle-fix-root-causes`를 적용했다. 실제 사용 가능한 GPT-6 Astra 작업자로 검토했으며 Grok·Opus가 실행되었다고 주장하지 않는다. 먼저 공개 함수를 호출하는 반례를 만들고, 수정 전 실패와 수정 후 통과를 확인했다. 기존 원문 연구의 모든 주장이나 최신 회사 재무를 다시 실사한 작업은 아니다.

## 2. 확인한 결함

### M1. 잔액보다 조금 많은 원금 지급을 허용함

`repayPrincipal`은 원금이 채무 잔액보다 $0.01까지 많아도 허용했다. 현금 $2, 채무 $1에서 $1.005를 지급하면 현금은 $0.995가 되고 채무는 0이 된다. 매각비용이 없는데도 보통주 잔여가치가 $1에서 $0.995로 감소한다. 원금 상환의 손익 중립성에 어긋나는 실제 함수 반례다.

지급액을 몰래 줄이는 방식과, 잘못된 지급 요청을 거부하는 방식을 비교했다. **잔액 초과를 정확히 거부하는 방식**을 선택했다. 정상 일정 호출부는 이미 `min(남은 채무, 예정 원금)`을 전달하므로 저장 관측의 시나리오 결과를 바꾸지 않는다. 소수 센트와 `1 + Number.EPSILON`도 거부하며 정확한 잔액 상환은 계속 허용한다.

### M2. 유한한 되돌림 값을 0·무한대 또는 크게 틀린 값으로 반환함

로그 되돌림에서 `log(끝 가격 / 시작 가격)`을 계산했다. 시작 `1e-200`, 끝 `1e200`, 비율 0.5에서는 중간 비율만 무한대가 되어 결과가 0이었다. 방향을 바꾸면 결과는 무한대였다. 양 끝 로그의 중간값은 0이므로 올바른 가격은 1이다.

선형 되돌림에도 유효한 입력 반례가 있었다. 같은 끝점에서 비율 `1 − 2^-53`을 넣으면 `끝 − 비율 × (끝 − 시작)`의 큰 수끼리 빼기 때문에 `1.6996415770136547e184`가 반환됐다. 올바르게 반올림된 주된 항은 `1.1102230246251565e184`이고 상대 차이는 약 53.09%다. 반대 방향에서는 문제가 나타나지 않았다.

두 식을 같은 의미의 볼록 결합으로 계산한다.

$$
L_r=(1-r)P_{end}+rP_{start},\qquad
G_r=\exp((1-r)\log P_{end}+r\log P_{start}).
$$

선형식은 비율이 0.5 이하이면 끝점부터, 그보다 크면 시작점부터 남은 차이를 더한다. 두 가중 가격을 따로 반올림해 합하면 가까운 큰 끝점에서 한 ULP를 넘기는 사례도 있어, 가까운 끝점을 기준으로 계산한다. 결과를 임의의 가격 범위로 잘라 문제를 감추지 않는다.

현재 로그 되돌림 비율도 크기 비율이 넘치면 로그 차이를 사용하고, 가까운 값에는 `log1p`를 사용해 로그 차이의 소실을 줄인다. 현재 값이 시작·끝과 정확히 같으면 비율 1·0을 직접 반환한다. 레벨 함수의 기존 입력 계약 **`0 < r < 1`은 유지**한다. 0·1을 새로 허용한 변경이 아니다.

**독립 검토에서 초기 수정의 추가 반례를 발견했다.** `1.7976931348623155e308`과 `Number.MAX_VALUE`, 비율 0.0001에서 가중 로그 항의 반올림이 합쳐져 최대값을 넘는 지수를 만들었다. 유한한 끝점인데 새 식이 예외를 던졌다. 현재 구현은 비율상 가까운 끝점에서 로그 변화를 계산하고, 변화가 작을 때 `base + base × expm1(change)`로 복원한다. 큰 변화만 로그 공간에서 복원한다. 임의의 가격 상·하한 자르기는 사용하지 않는다. 최대 유한값·subnormal을 포함한 3,536개 경계 조합과 독립 검토자의 고정 seed 50,000개 추가 조합에서 양수·유한성·끝점 범위를 확인했다. 이는 유한한 표본 검사다.

이 반례들은 배정밀도 경계의 수치 결함이다. 실제 BTC 가격에서 53% 오류를 관측했다는 주장은 아니다. 저장 BTC 자료의 전체 시장 구조 분석은 되돌림 숫자의 마지막 자리만 달라졌고, 국면·확정일·성과 분류 등 다른 결과는 같았다. 정확한 최종 비교 수치는 [통합 검산 기록](data/system-math-integration-2026-10-24.json)에 남긴다.

### M3. 주가의 흡수 상태를 공식과 반환 행에서 구분하지 않음

기존 재무 엔진은 잔여가치가 한 번 소진되면 운영·발행 계산을 중단하고 주가 가정을 0으로 유지했다. 이는 명시한 청산 스트레스 가정이다. 이후 코인 가격만 오르면 동결한 보유량의 잔여가치는 다시 양수가 될 수 있다. 그때 `components.insolvent`는 `false`, 주가는 0인데, 표시 공식에는 `프리미엄 × 양의 잔여가치 ÷ 주식 수`만 있었다.

재현 사례에서 초기 코인 가격 $2,000이 하루 $0.10으로 내려갔다가 $2,000으로 돌아왔다. 비용 차감 뒤 잔여가치가 약 −$36,892.54가 되어 소진됐고, 다음 날 산술 잔여가치는 약 $1,999,863,107.46로 회복했다. 모델 주가는 0을 유지한다. 산술적 자산가치 회복을 보통주 회복으로 처리하려면 재구조화·조달에 대한 별도 가정이 필요하다.

이 가정을 바꾸어 경영활동을 재개하는 방식은 채택하지 않았다. 각 경로 행에 **`valuationState: 'active' | 'absorbed'`**를 추가하고 공식에 흡수 상태의 0 분기를 명시했다. `components.insolvent`는 그 날짜의 잔여가치가 0 이하인지라는 원래 의미를 유지한다. [분기 식과 데이터 계약](TREASURY_PATH_MODEL.md#4-조건-범위-0-경계와-고저점-후보)을 함께 읽는다.

## 3. 수학적으로 성립하는 것과 검사의 범위

비용 `E`, 현금 사용 `u`, 매각 코인 `x`, 코인 가격 `P`, 매각비용률 `f`, 미지급액 `b`를 둔다. 현금과 코인을 사용한 뒤 미지급액을 청구권으로 남기면 다음 관계가 성립한다.

$$
b=E-u-xP(1-f),\qquad A'=A-u-xP-b=A-E-xPf.
$$

원금 `d`를 상환하면 채무도 `d` 감소하므로 `A'=A-xPf`다. 단, 실제 채무보다 많은 원금을 지급하지 않아야 한다. M1은 이 전제의 구현 오류였다. 162개 입력 상태에서 지출과 원금 상환을 각각 실행한 **324개 항등식 검산**은 현금·코인 부족, 전액 지급, 미지급 원금 재분류를 포함한다. 이 수는 독립 Node 테스트 개수가 아니다.

순조달액 `F=신주 수 × 제시가격 × (1-발행비용률)`이면 코인과 현금의 증가 가치가 `F`다. 따라서 발행 후 주당 잔여가치가 높아지는 조건은 순발행가가 기존 주당 잔여가치보다 높다는 것이다. 주당 코인 수의 증가 조건은 다르며, 코인 투자 비중과 기존 현금·선순위 청구권에 의존한다.

BTC 상세 경로의 종점 잔차 `R(T) − R(T)` 상쇄는 주어진 모델의 항등식이다. 동일한 개별 추출 경로의 변동성 배율은 로그 잔차에 선형으로 작용한다. 그러나 대표 경로 선택은 배율·표본 수에 따라 바뀔 수 있어, 화면에 선택되는 대표 가격끼리 같은 선형성을 주장하지 않는다. 장기 모델의 경제 조건 범위와 상세 모델의 표본 분위 범위도 서로 다르다.

위 항등식은 실수 산술과 명시한 가정에서 도출된다. 실행 검사는 지정한 유한 입력, 배정밀도 오차와 경계 사례를 다룬다. 모든 실수·모든 JavaScript 수에 대한 형식 증명은 아니다. 재표본 블록, 지정한 평균회귀, 재무 구조의 보존이 미래 가격 적중이나 4년 시장 법칙을 증명하지 않는다.

## 4. 실행과 결과

수정 전 새 반례 검사가 실패하는 것을 확인한 뒤, 아래 명령을 실행했다. Node 24의 프로세스 분리 제약이 있는 작업 환경에서는 `--test-isolation=none`을 사용했다. 실제 테스트와 계산 함수는 같다.

```sh
node --test --test-isolation=none \
  tests/treasury-model.test.mjs tests/treasury-path-integration.test.mjs \
  tests/market-structure.test.mjs tests/detailed-forecast.test.mjs \
  tests/long-horizon-forecast.test.mjs tests/treasury-asset-paths.test.mjs \
  tests/treasury-projection.test.mjs
node scripts/verify-treasury-paths.mjs
```

결과와 비교 입력·소스 해시는 [기계 판독 기록](data/system-math-audit-2026-10-24.json)에 있다. 고정 2026-10-23 관측·seed `20261022`에서 2050년까지 여섯 경로의 **53,010개 일별 전이**와 ETH 잔차 **26,505개**를 검산했다. 소진 후 상태도 `valuationState` 계약과 대조한다. 2035년까지 기본 UI 생성기의 여섯 경로 **20,142행**은 새 상태 필드만 제외하면 수정 전 가격·재무 구성·날짜·출처와 정확히 일치했다.

검산기의 부동소수점 허용오차는 계산 항의 크기와 누적값 차감 오차를 포함한다. 이 검토에서 주가·잔여가치·선순위 청구권의 재구성 차이는 0이었고, 누적 큰 수를 빼서 복원하는 자금 조달의 최대 절대 차이는 약 $0.001952 이하였다. 이를 달러 단위 경제 손실이나 계산의 모든 입력에 대한 정확성 증명으로 해석하지 않는다.

최종 통합 소스는 기준 커밋을 새로 추출해 같은 입력으로 다시 실행했다. 여섯 2035년 경로의 **20,142행**은 새 평가 상태 필드를 제외하면 정확히 같다. 상태 필드와 공식 설명을 제외한 전체 반환 객체의 가정·출처·마일스톤·범위도 동일하다. 시장 분석은 되돌림 수치 **1,338개**에서 마지막 자리 차이가 있었으며 최대 정규화 차이는 **1.7719942259452871e-15**다. 정규화는 절대 차이를 `max(1, |이전 값|, |현재 값|)`으로 나눈다. 그 외 모든 필드와 구조는 정확히 같다. 통합 소스의 [2050년 일별 검산](data/system-financial-verification-2026-10-24.json)은 소스·입력 해시로 이 결과와 연결된다. 기본 2035년 여섯 경로에는 흡수가 발생하지 않았으며 흡수 규칙은 긴 검산과 별도 충격·회복 사례로 검증했다.

## 5. 남은 한계

역사 재무 기준, 지출·희석·발행률, 경제 가치평가 조건, 같은 날짜라도 서로 다른 주식·코인 마감 시각은 이전에 공개한 한계로 남는다. 신규 회귀 통과로 현재 NAV, 미래 조달 가능성, 예측 확률 또는 수익성을 주장하지 않는다. TLA+ 상태 전이 검증의 범위도 금융 수식과 별개다. 이 문서의 결과는 전체 브라우저·릴리스 검증을 대신하지 않는다.
