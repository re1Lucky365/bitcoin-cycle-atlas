## 3. 기존 계정/작업 보존

1. 시작 시 기존 MAIN을 확인했다. 새 레이아웃 생성과 복사는 계정 제한으로 막혔다.
2. Autosave가 이미 false임을 읽었다. 켜거나 끄지 않았다.
3. 차트의 Save·템플릿 저장·관심목록 편집·알림 Create·브로커 연결·주문·공개 게시를 실행하지 않았다.
4. 시험 추세선은 Undo로 제거했다. 다른 그림의 일괄 삭제는 하지 않았다.
5. 설정 오표적 창을 포함해 내용 변경 없이 Cancel로 닫았다.
6. 페이지 재로딩 뒤 원래 1W Candles, 접힌 지표 그룹 10/7, 신규 RSI/Bitstamp overlay 없음, All changes saved 비활성, Autosave=false를 확인했다.
7. Watchlist를 원래처럼 열었다. 이후 검색·도움말 보완 촬영은 차트 구성을 바꾸지 않았다.
8. 모든 계정 선호나 최근 검색 기록의 바이트 동일성은 확인하지 않았다. 저장된 레이아웃의 관찰 가능한 복원을 확인했다.
9. 사용자 Atlas 탭에서 발생한 탐색/선택을 에이전트의 테스트로 세거나 원래 URL로 덮어쓰지 않았다.

## 4. 차단과 실패를 해석한 방식

### CSV

- Download 버튼은 한 번 실제 클릭했다. 앞선 한 번은 닫힌 대화상자의 stale ref 오류로 클릭 자체가 수락되지 않았다.
- 실제 클릭 뒤 download 이벤트 대기는 시간 초과였으나, 이를 곧바로 브라우저 고장으로 판정하지 않았다.
- 새 snapshot에서 Basic→Plus export 업그레이드 안내를 확인했다. 해당 시각 이후 browser download search도 빈 목록이었다.
- 결론: **[blocked: 현재 계정 CSV export 권한 없음]**. 다운로드 성공·CSV 열/범위/내용 검증은 주장하지 않는다. 결제·계정 변경·동일 기능 재시도 없음.

### 레이아웃

- Create new layout와 Make a copy 모두 저장 레이아웃 한도 안내였다.
- 결론: **[blocked: 현재 계정의 추가 저장 레이아웃 권한 없음]**. 새 저장 성공으로 기록하지 않는다. 기존 MAIN은 수동 저장하지 않았다.

### Replay

- 기존 진행을 이어갈지 묻는 UI가 나타났다.
- 결론: **보존 때문에 새 진행·전진을 실행하지 않음**. 플랜으로 막혔다고 단정하지 않는다. 기존 진행이 삭제됐다고 주장하지도 않는다.

### 캡처 도구와 검색 지연

- 검색어 입력 직후 이전 검색 결과가 남아 있었던 T05는 결과 갱신 후 재촬영했다.
- 단축키 두 장의 최초 locator/clip 촬영은 잘못된 위치를 잘랐다. 파일이 생성됐다는 이유로 성공 처리하지 않고 폐기한 뒤 전체 화면 방식으로 다시 찍고 내용을 직접 확인했다.
- T62는 펼친 차트 단축키 목록의 첫 화면, T63은 magnet 필터 결과다. 단축키 전체가 두 이미지에 모두 나온다고 설명하지 않는다. 전체 차트/그림 목록 텍스트는 Markdown에 별도 정리했다.
- T40은 도형 생성이 확인되지 않은 메뉴 단계의 시도다. 성공 영수증은 T41과 T42다.

## 5. 코드 조사와 실제 실행의 경계

- 읽기 전용 코드 조사자는 지정 SHA의 호출자·구현·관련 테스트를 확인했고, 원격 개선 후 변경된 코드/테스트를 다시 대조했다.
- 조사자가 읽은 테스트의 존재·검사 내용과 부모가 실제 실행한 npm test는 별개다.
- 부모 실행: Node v26.5.0, package engine >=24. `npm test` exit 0, node:test 469개 pass, fail/cancelled/skipped/todo 0.
- custom console 검사와 과거 보고서의 수를 더해 임의 총계를 만들지 않았다. 이 결과는 실제 브라우저·물리 기기·예측 수익률 검증이 아니다.
- 기존 원격 개선의 508 등 수치와 실제 PNG 다운로드 기록은 그 문서 작성 당시 보고다. 이 세션의 새로운 테스트 수로 변환하지 않았다.
- 앱 코드·자료·설정 변경은 이번 문서 커밋에 포함하지 않는다. main push에 연결된 기존 CI/Pages workflow는 그대로 두며, 문서 push가 별도 코드 개선이나 새 배포 기능을 의미하지 않는다.

## 6. 문서·증거 파일 검사

- PNG 70개 전부 검수 시트 6장으로 시각 검토. 결함 3장은 재촬영 후 원본 확인.
- manifest의 파일마다 실제 byte 수, PNG width/height, SHA-256을 계산한다.
- 공식 source ID 24개/고유 URL 24개, 32개 절차, 12개 후보를 확인한다.
- Markdown 상대 경로와 이미지 참조 대상의 존재를 검사한다. 표기된 SHA는 조사 대상 버전이지 미래 main의 동작 보장이 아니다.
- 공개 저장소에는 정리한 문서/공식 출처 색인/캡처와 manifest만 넣는다. 원시 접근성 snapshot·로컬 세션 경로·가상 ref·기존 개인 레이아웃 URL은 넣지 않는다.
- 캡처는 제품 UI/차트 사용 예시다. 지표 소스 코드·자격증명·개인 메시지·실주문/계좌 내역은 수집/커밋하지 않았다.

## 7. 다음 검증을 위한 고정 조건

새 비교 실험에서는 반드시 다음을 먼저 맞춘다.

1. 거래소/자료 source, 정확한 ticker, 현물/파생, USD/USDT.

3. 표시 기간·로드 범위·첫 가용일·빠진 봉.

5. 자동/수동 Y축, X범위·오른쪽 여백, pane 크기/상태.

7. 기대 동작, 실패 상태, undo/저장/재탐색으로 관찰할 최종 수락.
