# TradingView Supercharts 단계별 사용법과 실제 관찰

조사일: 2026-10-23 KST. 데스크톱 웹, 영문 UI, 1440×900 화면. 아래 **32개 작업 흐름**은 Supercharts의 주요 영역을 순회하는 순서다. TradingView의 모든 상품·플랜·기기·개별 지표를 전수 시험했다는 뜻은 아니다.

## 읽는 방법

- **실행 확인**: 조작 뒤 달라진 UI/캔버스 또는 Undo 항목을 확인했다.
- **메뉴 확인**: 대화상자와 옵션은 열었지만 저장·생성·적용은 하지 않았다.
- **문서 절차**: 공식 설명으로 정리했으며 이번 실행의 성공 영수증은 없다.
- **제한/보존**: 플랜 제한 또는 기존 작업 보존 때문에 해당 단계 이후는 진행하지 않았다.
- T01–T69는 [전체 캡처 색인](CAPTURES.md)의 ID다. A01은 조사 시작 당시 Atlas 화면이다.
- 공식 출처 TV01–TV24의 URL·짧은 원문 인용·주의사항은 [공식 문서 조사](03-official-docs.md)와 [JSON 색인](official-sources.json)에 있다.
- 화면 속 시세는 **촬영 당시 예시**다. 현재 시세·투자 권고·매매 신호가 아니다.

## 01. 화면의 네 영역과 작업공간 이해

**절차**
1. Supercharts를 연다.
2. 상단의 종목, 봉 간격, 차트 유형, 지표, 알림, Replay, 레이아웃을 확인한다.
3. 왼쪽의 커서·그리기·측정 도구, 오른쪽의 관심목록·알림·객체/데이터·제품 패널을 구분한다.
4. 하단의 표시 기간·Go to·시간대를 확인한다.

**관찰:** 기존 MAIN 레이아웃의 BINANCE:BTCUSDT, 1W, Candles가 열렸다. 지표 제목 목록은 접혀 있었고 가격·거래량·보조 그래프는 남아 있었다. 개인 계정의 기존 차트를 연구용 새 저장본으로 오인하지 않았다.

**Atlas 참고:** 도구 위치만 흉내 내기보다 ‘자료 선택 → 읽기 → 분석 → 복구/저장’ 경로를 설계한다. 기간선·연구 설명은 Atlas만의 역할이므로 유지해야 한다.

근거: TV01. 캡처: T01, T03, A01.

## 02. 종목 검색: 자산명보다 거래소·상품·통화 확인

**절차**
1. 상단 BTCUSDT 또는 종목명을 누른다.
2. Symbol search에서 Crypto 등 분류를 사용한다.
3. 검색 결과의 종목명, spot/futures/swap 등 유형, 거래소를 읽는다.
4. 특정 자료가 필요하면 `BITSTAMP:BTCUSD`처럼 거래소 접두어를 입력한다.
5. 결과가 검색어에 맞게 갱신된 뒤 선택한다. 입력 직후 남아 있는 이전 결과를 현재 결과로 해석하지 않는다.

**관찰:** 같은 BTCUSDT에도 Binance·OKX·Bybit 등 여러 결과가 나타났다. Bitstamp 지정 검색의 실제 갱신 결과를 재촬영했다. 메인 심볼 자체는 변경하지 않았다.

**주의:** BTCUSD와 BTCUSDT는 같은 호가 통화가 아니다. 거래소가 다르면 고저가·거래량·극값 날짜도 달라질 수 있다. Atlas의 Coin Metrics 일말 가격, Bitstamp 일·주 캔들, Coinbase 분·시간봉을 하나의 거래소 시리즈로 비교하지 않는다.

근거: TV02, TV04, TV20. 캡처: T04, T05.

## 03. 비교 심볼 추가와 축 소유권

**절차**
1. 상단 Compare symbols를 연다.
2. `BITSTAMP:BTCUSD`를 검색한다.
3. 결과 위에 포인터를 올려 **Same % scale / New price scale / New pane**를 확인한다.
4. 비교 목적에 맞는 배치를 선택한다.
5. 새 범례·거래소·축 단위와 Undo 항목으로 실제 추가 여부를 확인한다.

**실행 확인:** Same % scale을 선택하자 Bitstamp의 Bitcoin / U.S. Dollar가 추가되고 `Undo insert Overlay`가 생겼다. 비교 시리즈가 가격 위에 겹쳐졌고 백분율 축으로 바뀌었다. 종료 때 저장하지 않고 원래 MAIN을 재로딩했다.

**Atlas 참고:** ‘두 선을 그린다’만으로 비교 기능이 완성되지 않는다. 기준 날짜, 기준 가격, 단위, 동일 축/다른 축, 누락 정렬 정책을 알려야 한다. 최근값=100과 시작값=100을 혼동하지 않는다.

근거: TV01–TV04. 캡처: T56–T59.

## 04. 봉 간격 선택과 즐겨찾기

**절차**
1. 상단 D/W 등의 버튼 또는 Chart interval을 누른다.
2. Minutes, Hours, Days 등 그룹과 선택된 간격을 확인한다.
3. 자주 쓰는 간격은 별표로 관리할 수 있다. 이번에는 개인 즐겨찾기를 수정하지 않았다.
4. `1 day`를 선택한다.
5. 상태줄의 1D, 선택된 D, 일봉 캔버스로 수락 여부를 확인한다.

**실행 확인:** 1W→1D 전환과 `Undo change resolution`을 확인했다. 목록에는 ticks·seconds·분·시간·일·주·월·range가 있었지만 각 옵션의 계정별 이용 가능성을 모두 시험하지 않았다.

**Atlas 참고:** 지원 자료가 있는 8개 간격을 유지한다. 선택지만 늘리고 자료 없는 봉을 생성하면 안 된다. 간격 변경 시 날짜 중심·확대 폭·선택을 얼마나 보존할지가 별도 개선 후보다.

근거: TV01, TV08. 캡처: T06, T07.

## 05. 표시 기간과 Go to / Custom range

**절차**
1. 하단 1D·5D·1M·1Y·All은 화면에 볼 기간이라는 점을 확인한다.
2. Go to를 연다.
3. Date 또는 Custom range를 고른다.
4. 시작 `2024-01-01`, 종료 `2024-12-31`을 입력하고 Go to를 실행한다.
5. 시간축과 봉 간격을 다시 읽는다. 범위 프리셋은 봉 간격도 바꿀 수 있다.

**실행 확인:** 입력이 수락되고 2024년 구간으로 이동했으며 `Undo change date range`가 생겼다. 실제 화면에는 앞뒤 문맥과 여백도 보였다. 입력 경계와 스크린의 최외곽 픽셀이 정확히 일치한다고 주장하지 않는다.

**Atlas 참고:** 봉 간격, 보이는 시간 범위, 실제 로드된 범위는 세 상태다. 일·주 날짜 이동과 분봉의 시각 이동, 두 날짜 직접 입력을 분리해 비교한다.

근거: TV01, TV08, TV19. 캡처: T19, T20.

## 06. 캔들·선과 비표준 차트 유형

**절차**
1. Candles 메뉴를 연다.
2. Candles, Bars, Line과 Renko·Heikin Ashi 등의 유형을 구분한다.
3. Line을 선택하고 상태줄과 그래프가 바뀌는지 확인한다.
4. Candles로 복귀한다.
5. 유형별 Settings → Symbol의 옵션이 달라지는지 확인한다.

**실행 확인:** 선 차트로 바뀌고 `Undo change series style`이 표시됐다. 선 설정에는 price source가, 캔들 설정에는 body/borders/wick 등이 나타났다.

**주의:** 비표준 차트를 실제 체결 OHLC나 같은 시간 길이의 봉으로 취급하지 않는다. Renko 등 각 유형의 개별 설정·계산 정확도·재도색 특성을 이번에 전수 실행하지 않았다.

근거: TV03, TV04, TV24. 캡처: T08–T10, T67.

## 07. 십자선, 상태줄, 봉 변화율 읽기

**절차**
1. 차트 위 포인터를 움직여 날짜·축 가격·상태줄의 선택 봉을 읽는다.
2. 커서의 세로 가격과 해당 봉의 O/H/L/C를 구분한다.
3. 직전 동일 간격 종가 대비 변화와 현재 봉 시가 대비 변화를 구분한다.
4. 가격선/캔들, 실시간 매수·매도 호가, 선택한 과거 봉의 값이 서로 다른 시점을 나타낼 수 있음을 확인한다.

**관찰:** 과거 위치에서 상태줄 OHLC와 지표 값이 변하는 반면 Sell/Buy 호가는 현재 값을 유지했다. 시세 스트림의 수치 정확도를 외부 거래소와 독립 대조한 시험은 아니다.

**Atlas 참고:** 최신 v1.12.0은 전봉 종가 기준 변화와 시가 대비 변화를 분리한다. 이전 버전의 문제를 현재 결함으로 다시 적지 않는다. 관측→가정 경계, 출처 변경, 직전 봉 누락에서는 값을 만들어 넣지 않아야 한다.

근거: TV03, TV20, 최신 Atlas 소스. 캡처: T07, T27, T43.

## 08. 가격축: Regular / Log / Percent / Indexed to 100

**절차**
1. 가격축에서 우클릭한다.
2. Auto, Lock price to bar ratio, Scale price chart only, Invert scale을 확인한다.
3. Regular, Percent, Indexed to 100, Logarithmic를 구분한다.
4. 이번 조사에서는 Alt+L, Percent, Indexed to 100을 차례로 적용했다.
5. 축 숫자와 단위, Undo 항목을 확인한다.

**실행 확인:** `Undo toggle log scale`, `Undo toggle percentage scale`, `Undo toggle indexed to 100 scale`과 실제 축 변화를 확인했다. Auto/축 반전/가격만 자동 맞춤은 메뉴 확인이며 모두 적용 시험한 것은 아니다.

**의미:** 선형축은 절대차, 로그축은 비율, Percent는 기준점 대비 수익률이다. Indexed to 100과 Atlas ‘최근 관측값=100’의 기준은 다르다. pan/zoom 때 TradingView 기준값이 언제 재설정되는지는 이번에 통제 실험하지 않았다.

근거: TV03, TV09. 캡처: T17, T18, T44–T46.

## 09. 확대·이동·초기화와 축 조절의 차이

**문서 절차**
1. 배경 드래그로 시간 구간을 이동한다.
2. 휠/키보드로 확대하고, Shift+휠로 이동한다.
3. 기본 차트 보기 복원과 가격축만 Auto로 복귀하는 동작을 구분한다.
4. 패널 배경 더블클릭은 pane 최대화가 될 수 있으므로 가격축·도형·배경의 hit target을 확인한다.

**이번 실행 범위:** 범위 입력·축 모드·pane 더블클릭은 실행했다. 모든 휠 조합·팬 감도·핀치·축 드래그를 TradingView에서 정량 비교한 것은 아니다. 단축키 목록은 실제 도움말로 읽었다.

**Atlas 참고:** 최신 버전에는 수동 가격축과 Auto 복귀가 이미 있다. 시간축 직접 드래그, 감도·anchor 유지, 접근성은 독립 요구로 검토한다.

근거: TV03, 실제 단축키 도움말. 캡처: T26, T44, T61–T63.

## 10. 임시 Measure와 날짜·가격 범위 도형

**절차**
1. 왼쪽 Measure를 선택한다.
2. 시작 위치에서 끝 위치로 드래그한다.
3. 가격차·변화율·봉 수·경과일·거래량 등 표시되는 항목을 읽는다.
4. 임시 측정과 Forecasting and measurement tools의 Date/Price range 도형을 구분한다.
5. 저장할 분석에는 시작·끝의 정확한 좌표와 의미를 기록한다.

**실행 확인:** 파란 측정 영역과 수치 라벨이 나타났다. 이 임시 측정이 저장 레이아웃의 영속 도형이라고 가정하지 않았다. 표시 수치의 모든 산식을 독립 재계산하지 않았다.

**Atlas 참고:** 단일 임시 측정은 이미 분·시간봉에도 있다. 다음 후보는 반복 측정 보존·편집·정확 좌표·관측/가정 포함 표시이지 측정 기능의 재구현이 아니다.

근거: TV06, TV23. 캡처: T35, T43.

## 11. 왼쪽 도구의 전체 분류 탐색

**절차**
1. 도구 아이콘에 hover한다.
2. 마지막으로 사용한 도구 아이콘과 별도의 작은 그룹 화살표를 구분한다.
3. 화살표로 메뉴를 열고 필요한 도구를 선택한다.
4. 즐겨찾기 별표와 도구 실행을 구분한다.

**메뉴 확인:** Trend tools(선·채널·피치포크), Gann and Fibonacci tools, Patterns(차트 패턴·Elliott·Cycles), Forecasting/measurement(포지션·거래량·측정), Geometric shapes, Annotation tools를 열었다. 커서 메뉴도 별도로 확인했다.

**범위:** 각 그룹의 목록을 읽은 것이며 모든 도형을 그려 정확도를 시험한 것은 아니다. 아이콘/스티커 선택 전체는 별도 미검증이다.

근거: TV01, TV06. 캡처: T32–T38.

## 12. 추세선 2점 생성과 Undo

**절차**
1. Trend tools 메뉴에서 Trendline 행을 명시적으로 선택한다.
2. 차트 안 첫 점을 클릭한다.
3. 둘째 점을 클릭해 완성한다.
4. 두 핸들·도형·Undo create trendline을 확인한다.
5. Undo를 누르고 도형 제거와 Redo create trendline을 확인한다.

**실행 확인:** 실제 새 추세선과 Undo/Redo 전환을 확인했다. 기존 그림을 지우는 Remove all은 실행하지 않았다. 처음 메뉴 선택 전 클릭은 생성이 확인되지 않아 T40을 시도 기록으로만 남기고, 성공은 T41로 구분했다.

**주의:** 도형을 열려던 더블클릭이 겹친 기존 지표의 설정 창을 열기도 했다. 내용을 바꾸지 않고 Cancel했다. 여러 객체가 겹칠 때 정확한 선택과 객체 관리가 필요한 이유다.

근거: TV06. 캡처: T40(미확인 시도), T41(생성), T42(되돌림).

## 13. Magnet: 약함·강함·임시 전환

**절차**
1. Magnet 아이콘과 그룹 화살표를 구분한다.
2. Magnets 메뉴에서 Weak magnet / Strong magnet을 확인한다.
3. 지원되는 상황에서 Snap to indicators 가용 여부를 읽는다.
4. 도형 기준점을 이동할 때 Cmd로 임시 전환한다는 단축키 안내를 확인한다.

**메뉴 확인:** Weak/Strong과 비활성 Snap to indicators를 확인했다. 강도별 모든 OHLC 스냅이나 임계 거리의 수학적 검증은 하지 않았다.

**Atlas 참고:** Atlas 자석은 일반 커서 전체가 아니라 측정 앵커에 적용된다. 메뉴가 비슷하다는 이유로 스냅 대상을 같다고 설명하지 않는다.

근거: TV06, 실제 도움말. 캡처: T39, T63, T66.

## 14. Lock / Hide / Remove / Sync의 구분

**문서 절차**
1. 대상 도형을 선택한다.
2. Lock으로 오이동을 방지한다.
3. Hide로 임시 감춘다. Remove는 객체 자체의 삭제다.
4. 동기화는 대상 심볼과 local/layout/global 범위를 확인한다.

**이번 범위:** 왼쪽 도구 버튼과 Object tree의 잠금·눈 아이콘은 확인했다. 기존 객체의 lock/hide/remove/sync를 변경하지 않았다. 모든 그림 제거는 자료 손실 위험 때문에 실행하지 않았다.

**Atlas 참고:** 자동 사이클 표식과 사용자가 편집하는 그림 객체는 다른 종류다. 일반 드로잉을 도입한다면 객체 ID·기준점·잠금·숨김·선택·undo·저장 계약이 필요하지만, 아직 확정 아키텍처는 아니다.

## 28. Quick search와 단축키 도움말

**Atlas 참고:** M은 Atlas 측정, H는 Atlas 이동이다. TradingView의 키와 의미가 다르므로 동일 조작처럼 안내하지 않는다.

## 29. 이미지 snapshot과 공개 게시 구분

**절차**
1. Take a snapshot을 연다.
2. Download image, Copy image, Copy link, Open in new tab, Post image를 구분한다.
3. 파일 저장이면 다운로드 완료·파일 내용을 확인한다.
4. 공개 공유는 별도 공개 범위 확인 후 실행한다.

**메뉴 확인:** 위 항목을 열람했다. TradingView snapshot 파일 다운로드·클립보드 복사·호스팅 링크 생성·게시를 실행하지 않았다. 본 조사에 제공한 PNG는 브라우저 캡처 도구로 만든 실제 UI 증거이며, TradingView 내보내기 기능의 성공 영수증이 아니다.

**Atlas 최신 상태:** v1.12.0에 주 차트 PNG 저장이 이미 추가됐다. 이미지 clipboard·호스팅 URL은 별도 미지원이다. 현재 화면 전체 연구 창까지 출력하는지는 별도 계약이 필요하다.

근거: TV13. 캡처: T51.

## 30. CSV: 메뉴 도달과 실제 수신은 다르다

**절차**
1. Manage layouts → Download chart data를 연다.
2. 대상 `BINANCE:BTCUSDT, 1D`를 확인한다.
3. Time format의 ISO time / UNIX timestamp와 표시 시간대 UTC+9를 확인한다.
4. Download를 누른다.
5. 실제 파일의 행·열·자료 출처·시간대를 검사한다.

**제한 확인:** 4단계에서 Basic→Plus 업그레이드 안내가 나타났다. 다운로드 이벤트는 오지 않았고 해당 시각 이후 브라우저 다운로드 목록도 비어 있었다. **CSV 수신·스키마·내용 검증은 [blocked: 현재 계정 export 권한 없음]**이다. 재결제·계정 전환·같은 다운로드 재시도는 하지 않았다.

**Atlas 참고:** 공식 문서는 로드된 symbol/indicator 자료 export를 설명한다. Atlas는 관측 전용 CSV이며 일·주 화면에서도 Coin Metrics daily 원가격, 분·시간은 조회된 Coinbase 완료 OHLCV다. TV의 UTC+9 옵션과 Atlas UTC 열을 조용히 합치면 안 된다.

근거: TV19. 캡처: T52–T55.

## 31. 우측 제품과 거래 연결의 경계

**절차**
1. Watchlist의 심볼·가격·변화 열과 Add symbol 등 진입점을 확인한다.
2. Products에서 Screeners, Calendars, News Flow, Portfolio, Yield Curves, Options, Macro Maps 등을 확인한다.
3. Trade에서 Paper Trading과 브로커 목록을 확인한다.
4. 실제 연결·약관 동의·주문은 별도 승인 작업으로 남긴다.

**메뉴 확인:** 제품 목록과 Trade with your broker 창을 확인했다. 개인 관심목록 편집·브로커 연결·모의/실주문은 하지 않았다. Pine Editor·Copilot·커뮤니티·개인 메시지·알림함의 실제 내용은 수집하지 않았다.

**Atlas 참고:** BTC 사이클 연구 앱에 범용 터미널의 모든 부가상품을 복제할 필요는 없다. 서버 알림·주문·Pine 실행·다자산 관심목록은 별도 제품/데이터/보안 범위다.

근거: TV01. 캡처: T01, T03, T64, T65.

## 32. 종료·복원·미검증 범위 남기기

**실제 종료 절차**
1. 생성한 시험 추세선은 Undo로 제거했다.
2. 설정 창은 Cancel로 닫았으며 기존 레이아웃의 Save를 누르지 않았다.
3. 페이지를 재로딩해 저장된 MAIN을 다시 열었다.
4. 원래 1W Candles, 접힌 지표 목록 10/7, 신규 RSI/Bitstamp 비교 시리즈 없음, All changes saved 비활성 상태를 확인했다.
5. Watchlist를 원래처럼 다시 열고 Autosave=false를 재확인했다.
6. 이후 검색·도움말 보완 캡처만 진행했고 차트 구성은 변경하지 않았다.

**범위 한계:** 저장 레이아웃의 관찰 가능한 구성 복원을 확인한 것이다. 최근 검색 기록·마지막으로 연 설정 탭 같은 모든 계정 선호가 바이트 단위로 같다는 주장은 아니다. 사용자가 보던 Atlas 탭의 이동·선택은 덮어쓰지 않았다.

**모바일:** 이번 호스트의 Page에는 setViewportSize가 제공되지 않았고 TradingView 모바일 앱/실기기 작업을 수행하지 않았다. 모바일 long-press·pinch·가로모드·스크린리더·실기기 FPS는 별도 검증 항목이다. SDK 동작을 Supercharts 모든 계정의 실험 결과로 대체하지 않는다.

**완료 범위:** 공식 문서와 실제 데스크톱 주요 UI 조사·캡처·현재 코드 대조 문서화. 제한 기능은 단계별로 명시했다. 앱 개선 구현·예측 성능 향상·전 제품 전수 기능 시험은 이번 결과가 아니다.
