# v1.10.4 · 지표 값, 모바일, 자석, 과거 봉 조회

작성: 2026-10-22 UTC. 현재 구현과 자동 검증, 실제 브라우저에서 확인한 버전별 결과를 기록한다. v1.10.4의 배포 커밋과 `app.js?v=1.10.4`를 확인한 뒤 모바일 세 가지 CSS viewport와 데스크톱에서 제목 줄 제거·대표 지표 개수·겹침·인디케이터 창 조작을 검수했다. 해당 수치와 화면은 아래 v1.10.4 증거 절에 연결한다. 이전 버전의 검수와 발견한 문제는 버전을 명시해 보존한다.

## 화면과 표시 계약

첫 접속의 가격 창은 최신 완료 일말 관측의 과거 24개월과 미래 24개월이다. 2026-10-21 자료라면 **2024-10-21–2028-10-21**을 보여 준다. 이는 표시 범위이며, 2050년까지 계산한 조건부 미래 경로는 보존한다. 4년/기본 범위 복원, 명시적인 장기 전망/전체, 사용자가 확대·이동한 범위를 구분한다. 기존 공유 URL의 `span`을 존중한다.

좌측 지표 값은 차트 위에 이름과 나란히 표시한다. 데스크톱은 추가한 지표 목록을, 모바일은 거래량을 우선한 대표 지표 최대 1개를 보여 준다. `Vol 2.22k BTC`처럼 가격·수익률·거래량을 읽고, 숫자가 적절하지 않은 자료 출처·범례·사건은 출처명·표시 상태·사건/라벨 수를 보여 준다. 미래 거래량은 `가정`과 `BTC/일` 또는 `BTC/주`로 구분한다. 조회하지 않은 봉이나 과거 근거가 없는 지표에 0이나 미래 값을 대입하지 않는다. 최근 전환은 선택 시점까지 **확인된** 전환만 표시한다.

차트 위에는 별도 상자 없이 이름과 값을 표시하며, **‘지표 9’ 개수·접기·추가 조작 줄은 만들지 않는다.** 목록 표시는 상단 **인디케이터** 창 하단의 **‘차트에 지표 값 표시’** 체크박스에서 바꾼다. 체크를 해제해도 추가한 지표와 연구 창의 표시 상태는 유지한다. 같은 창의 **‘모두 숨김 / 모두 표시’** 버튼은 추가한 지표 자체의 표시 상태를 함께 바꾼다. 목록은 기본 표시하며, 값을 숨긴 공유 URL에는 기존 `indicator-list=closed` 상태를 보존한다. 이전 `indicator-list=open` 링크도 표시 상태로 연다. [지표 목록 구현](../dist/indicator-workbench.js), [상태 계약](../dist/indicator-state.js)

행마다 이름과 값을 이어 표시한다. 데스크톱의 개별 숨김·제거 조작은 행에 마우스를 올리거나 키보드 초점을 옮기면 나타난다. 모바일의 차트는 대표 지표 최대 1개로 제한하고 나머지 지표의 현재 값·개별 눈 아이콘·추가와 삭제는 인디케이터 창에서 관리한다. [지표 창](../dist/indicator-workbench.js), [표시 스타일](../dist/analysis-dock.css)

D-day는 `다음 하락 D-87 / 가정 2027.01.18`처럼 두 줄로 정리했다. 검수 중 한국 달력 날짜가 2026-10-23인 화면에서 D-87을 확인했으며 일수는 현재 날짜에 따라 바뀐다. 7일 유지 조건, 현재 상태 유지 범위, 자료 기준일은 접근성 설명·툴팁·사용자가 직접 연 근거 패널에 남긴다. 실제 시장의 확정 일정으로 표현하지 않는다.

## 모바일

620 CSS px 이하에서 고정 좌우 레일을 접어 가격 차트가 화면 전체 폭을 사용한다. 8개 시간 간격은 네이티브 선택 메뉴로 유지한다. 상단의 **차트 도구**와 **정보와 설정**에서 기존 기능을 연다. 정보 트레이는 **통합 차트 · 리서치 자료 · 원자료**를 이름과 아이콘으로 표시한다. 리서치 자료·원자료 화면에는 통합 차트 복귀 버튼이 있다. 상세와 지표 라이브러리는 작은 화면에 맞는 패널이며, 화면 안전 영역과 가로 방향도 고려한다.

**폭 620 CSS px 이하, 또는 폭 950px 이하이면서 높이 500px 이하인 작은 가로 화면에서는 차트 지표를 자동으로 최대 1개만 표시한다.** 표시 중인 거래량을 우선하고, 거래량이 없거나 숨겨졌다면 현재 간격에서 사용할 수 있는 다른 표시 중 지표를 고른다. 표시할 지표가 모두 없거나 ‘차트에 지표 값 표시’를 끄면 0개다. 상단 **인디케이터** 창을 열면 다른 지표의 현재 값과 개별 숨김·추가·삭제를 사용할 수 있다. 창을 닫으면 차트는 다시 최대 1개를 유지하며, 차트 위에 ‘지표 9’ 제목 줄이나 전체 목록을 펼치는 조작을 만들지 않는다. [대표 지표와 창의 동작](../dist/indicator-workbench.js)

헤더의 가격·OHLC·거래량을 줄바꿈하고 실제 높이를 관찰해 출처와 지표를 배치한다. **폭 620px 이하의 좁은 모바일 화면**에서는 대표 지표를 왼쪽, D-day를 같은 높이의 오른쪽에 두고 서로의 공간과 가격축 여백을 나눈다. 글자 주변에만 작은 어두운 바탕을 두며, 추가한 연구 창은 대표 지표와 D-day 중 **더 큰 실제 높이** 아래에서 시작한다. **폭 621–950px·높이 500px 이하인 짧은 가로 화면**에서는 대표 지표 최대 1개 제한을 적용하고 기존 레이아웃을 유지한다. 긴 이름·값은 화면 폭에 맞춰 줄바꿈할 수 있다. 여러 지표를 읽는 스크롤은 인디케이터 창에서 처리한다. 작은 화면의 배경 블러·큰 그림자는 줄였다. [모바일 스타일](../dist/mobile-workspace.css)

TradingView의 [공식 모바일 값 안내](https://www.tradingview.com/support/solutions/43000502564-i-can-t-see-ohlc-indicator-values-and-the-crosshair-cursor/)는 기본적으로 최근 가격과 일간 변화를 표시하고, 봉을 길게 누르면 OHLC·지표 값을 읽는 동작을 설명한다. [Android 지표 숨김 안내](https://www.tradingview.com/support/solutions/43000506679-how-do-i-hide-display-an-indicator-in-the-android-app/)는 범례의 눈 아이콘 또는 Object Tree의 개별 표시 설정을 제시한다. 이를 작은 화면의 간결한 읽기와 별도 관리 조작의 참고로 삼았다. **거래량 우선 대표 지표 1개와 창을 닫은 뒤 자동 축소는 사용자의 요청을 반영한 Atlas의 설계다.** TradingView의 모든 모바일 화면이 같은 대표 지표 1개 규칙을 쓴다고 해석하지 않는다.

차트에서 한 손가락으로 좌우 이동하고 두 손가락으로 시간축을 확대·축소한다. 제스처마다 금융 모델을 재계산하지 않는다. 축소 후 과거 데이터가 필요하면 같은 간격으로 조회한다. 일반 탭은 값을 고정하며 상세 패널을 자동으로 열지 않는다. 차트 밖의 텍스트/입력과 데스크톱 Ctrl+휠은 브라우저 기본 조작을 유지한다. 구현은 [Pointer Events](https://www.w3.org/TR/pointerevents/latest/)와 [MDN pinch](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events/Pinch_zoom_gestures)의 취소·포인터 추적 계약을 따른다.

모바일 도구 트레이는 Escape/배경 탭으로 닫히고, 열린 동안 키보드 Tab 이동을 보이는 조작 안에 유지한다. 자석 하위 메뉴의 포커스와 상세 패널의 포커스 복원은 별도로 처리한다. 화면 크기 확인용 [미리보기](../dist/mobile-preview.html)는 동일한 실제 페이지를 지정한 CSS viewport의 iframe에 표시한다. 실제 휴대전화 CPU·GPU·터치 장치의 대체 측정은 아니다.

## 자석과 SVG

TradingView의 실제 차트 왼쪽 메뉴에서 약한/강한 자석과 아이콘을 확인하고 [공식 OHLC 도움말](https://www.tradingview.com/support/solutions/43000472715-drawing-points-don-t-snap-to-ohlc-values-correctly/) 및 [임시 Ctrl/Command 동작](https://www.tradingview.com/support/solutions/43000722509-magnet-mode/)과 대조했다. Atlas는 지원하는 두 지점 측정에 실제 OHLC 붙임을 적용한다. 모든 간격에서 쓰며, 선·미래 가정에 없는 OHLC를 만들지 않는다. 세부 임계값과 구현 범위는 [MAGNET_MODE.md](MAGNET_MODE.md)에 명시했다.

도구 SVG는 동일한 viewBox, currentColor, 약 1.7 선 굵기와 둥근 선 끝을 사용한다. 강한 자석은 작은 화살표로 구별한다. SVG 저장은 명시적인 크기, 차트 제목·선택값·출처·관측/가정 설명을 포함하며 일시적인 십자선·자석 미리보기를 제외한다. 외부 CSS 없이 열 수 있고 휴대전화 폭에서는 텍스트를 줄바꿈한다. TradingView의 [스냅샷 문서](https://www.tradingview.com/charting-library-docs/latest/ui_elements/Snapshots/)는 이미지 저장 동작의 참고 자료이며, Atlas의 SVG 구현이 TradingView의 내부 렌더러와 같다는 주장은 하지 않는다.

## 성능 변화와 한계

- 보이지 않는 기존 비교·타이밍·원자료 페이지는 처음 가격 화면에서 미리 계산하지 않는다. 분석 창도 해당 모드의 설정이 바뀔 때만 다시 그린다.
- 주 차트의 크기 관찰을 한 곳으로 모아 같은 resize 이후 중복 그리기를 제거했다.
- 포인터 이동과 지표 텍스트는 화면 프레임당 한 번 처리한다. 새 날짜가 같으면 값을 다시 포맷하지 않으며, 지표 행 DOM을 매번 만들지 않는다. 표시를 끈 값 목록은 텍스트 갱신을 미룬다.
- 날짜→UTC 일수 변환은 검증한 불변 날짜만 최대 32,768개 캐시한다. 가격·모델 결과를 이 캐시에 넣지 않는다.
- 분·시간 확대 구간 조회는 `O(log N + V)`. 밀집 캔들·거래량은 제한된 SVG 경로로 묶고, 실제 선택값은 원본에서 읽는다. 한 화면 최대 6,000개 봉 간격, 간격별 캐시는 최근 창 12,000개 간격과 초기 180개 봉이다. 더 과거로 이동하면 추가 조회하며, 빈 거래 시간은 채우지 않는다. [API 교차 검증과 구현](INTRADAY_HISTORY.md)

같은 자료와 옵션을 별도 Node 프로세스에서 실행한 계산 결과:

| 작업 | 변경 전 | 변경 후 |
|---|---:|---:|
| 128개 샘플 장기 모델 | 798.52 ms | 560.42 ms |
| 거래량 모델 적합 | 192.39 ms | 104.23 ms |
| 기존 타이밍 분석 | 130.37 ms | 48.62 ms |

장기 모델·거래량 적합·거래량 전망의 전체 JSON SHA-256이 변경 전후 같았다. 따라서 계산량을 줄이려고 샘플 수·가격·미래 경로를 바꾸지 않았다. 이 값은 **CPU 계산 단일 실행**이며 실제 기기의 FPS, 페인트 시간, 터치 지연 또는 통계적인 반복 성능 평가가 아니다. [원 기록](data/mobile-calendar-cache-profile.json), [재현 스크립트](../scripts/profile-startup-computation.mjs)

실제 Coinbase 응답으로 1m 180→727봉, 4h 180→363봉 확장을 확인했다. 요청 시각·URL·상태·표본 OHLCV는 [API 검증 기록](INTRADAY_HISTORY_LIVE_VERIFICATION.json)에 있다. API 제한·장애 시 이미 받은 자료를 유지하고 다시 조회할 수 있으며, 무한한 봉을 한꺼번에 내려받는 구조는 아니다.
