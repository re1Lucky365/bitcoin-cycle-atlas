# 통합 변경 독립 검토

검토일: 2026-10-24. 판정은 **검토한 범위에서 PASS**다. 작성자의 통과 보고를 그대로 승인하지 않고 실제 공개 함수의 반례, 테스트 실행, 모델과 코드의 대응, 측정 원본과 소스 해시를 대조했다. 추가로 발견한 로그 보간 회귀와 테스트 런타임 호환성 문제는 통합 코드에서 수정되었다. 아래 범위에서 남은 기능 차단 결함은 재현하지 못했다. 이 판정은 시장 예측 정확도나 프로그램 전체의 무결성 증명이 아니다.

## 독립 검토에서 추가로 발견한 사항

### R1. 로그 보간 수정이 최대 유한값 부근에서 새로운 예외를 만듦 — 중간 심각도, 수정됨

첫 수정본의 가중 로그 합은 일반적인 극단 비율 문제를 해결했지만, 서로 가까운 큰 로그를 따로 반올림한 뒤 더하면 최댓값의 로그를 한 단계 넘을 수 있었다. 실제 공개 함수로 재현했다.

```js
import { fibonacciLevels } from './dist/market-structure.js';

fibonacciLevels(1.7976931348623155e308, Number.MAX_VALUE, {
  ratios: [0.0001],
  scale: 'log',
});
```

공개 기준 코드는 유한값을 반환했지만 첫 통합 수정본은 `RangeError`를 냈다. 양 끝은 모두 유효하고 비율도 기존 계약 안에 있으므로 게시 전에 고쳐야 할 실제 회귀였다. 일상적인 BTC 시세에서 같은 크기의 오류가 관측되었다는 뜻은 아니다.

수정된 함수는 가중치가 가까운 끝점을 기준으로 삼는다. 작은 로그 변화에는 `log1p`와 `expm1`, 큰 범위에는 로그 공간을 사용한다. 출력을 임의 범위로 잘라 반례를 숨기지 않는다. 위 사례의 반환 레벨 가격은 현재 `Number.MAX_VALUE`다. 최종 코드에서 시장 구조 테스트 **16개**를 직접 실행해 통과했다. 그중 경계 검사 한 개는 정규·비정규 작은 값, 최대 유한값과 가까운 끝점을 포함한 **3,536개 조합**을 검사한다. 조합 수를 독립 테스트 개수로 세지 않았다. [수치 구현](../dist/market-structure.js) · [회귀 검사](../tests/market-structure.test.mjs)

### R2. 새 패키징 테스트가 선언한 Node 최소 버전보다 늦게 추가된 API를 사용함 — 중간 심각도, 수정됨

패키지 계약은 Node `>=24`인데, 새 테스트 helper가 `SourceTextModule.moduleRequests`를 순회했다. 공식 문서상 이 속성은 **v24.4.0 / v22.20.0**에 추가되어 Node 24.0–24.3에는 없었다. [Node 공식 API 이력](https://nodejs.org/api/vm.html#sourcetextmodulemodulerequests)

실제 `module.link(resolve)`가 같은 정적 연결 검사를 이미 수행하므로 중복 사전 순회만 제거했다. 지원 최소 버전을 올리거나 검사 실패를 무시하지 않았다. 이 문제는 제품 가격 계산 오류가 아니라 지원 런타임에서 검증이 시작되지 못하는 회귀였다. [수정된 helper](../tests/helpers/standalone-runtime.mjs)

### R3. 검증 소스와 공개 이력의 추적성 — 중간 심각도, 기록 정정

검증 스킬에 로컬 작업자 커밋만 적은 상태에서 API로 새 공개 커밋을 만들면 그 SHA를 GitHub에서 읽을 수 없을 수 있다. 공개 코드 커밋을 먼저 읽어 확인하고, 후속 메타데이터 커밋이 그 공개 코드를 가리키도록 하는 게시 절차를 요청했다. 이 검토 자체가 게시 성공을 확인했다는 주장은 하지 않는다.

또한 기존 캔들 검증 스킬의 `780a33c` 이후 드리프트는 import 버전 변경만이 아니었다. `2ea9a54`의 ETH 확장이 제품별 인자·스냅샷 경로를 추가했다. 해당 변경을 직접 대조하고 아래와 같이 모델 의미가 유지됨을 확인했다. 후속 문서는 이를 명시한다. [갱신된 대응 설명](formal-state/README.md)

최종 주식 gate가 기록한 소스 해시는 이 문서의 `0e9cd421…`와 정확히 같다. 반례 탐색은 첫 위반에서 의도적으로 멈추므로 남은 큐를 완전 탐색 성공으로 해석하지 않았다. 재현 명령과 전체 결과는 [주식 검증](formal-equity/README.md), [주식 JSON](formal-equity/verification-summary.json), [캔들 검증](formal-state/README.md), [캔들 JSON](formal-state/verification-summary.json)에 있다.

캔들 ETH 확장에서는 `marketProduct`가 반환한 frozen 제품이 컨트롤러 수명 동안 고정된다. 요청 슬롯·캐시·snapshot promise는 인스턴스별이다. 기존 동기화 이후 모델 범위의 `load`·`cancel`에 새 `await`, 공유 writer 또는 publication guard 이동이 없어 제품을 고정 환경 인자로 다루는 기존 모델을 유지할 수 있다. ETH 9개 실행 검사를 다중 제품 전체의 TLA+ 증명으로 확대하지 않았다. 모델 주석은 함수·동작 이름을 참조하므로 추가된 코드의 행 수가 가드 출처를 무효화하지 않는다.

주식 모델은 세 요청 세대, 일·주 간격, 자동·지정 구간에 한정한다. 실제보다 많은 복원·정지 콜백 순서를 허용하는 과대근사를 읽고, 실제 스케줄러 관측과 구별했다. 계산은 `await`가 없는 동기 구간으로 추상화한다. 실제 fixture가 생산 초기화 코드를 읽되 import·HTTP·DOM·RAF·차트·계산 경계를 주입한다는 점도 확인했다. 따라서 유한 요청 안전성 검사가 DOM 화소, 실제 브라우저 시간, 결국 완료된다는 생존성 또는 주가 계산 타당성 증명은 아니다.

상태 전이도 PNG 세 개를 직접 열어 글자와 분기를 확인하고 모델 해시와 manifest의 여덟 결과물 해시·크기를 대조했다. 전체 요약은 보이는 상태 9개와 선택된 전이 11개이며 모든 내부 전이를 그린 그림이 아니다. 두 모델의 출처 없는 가드 목록은 비어 있다. 부팅 공개 지연은 실제 코드 결함이고, 정지 중 늦은 초기화 콜백은 방어 강화용 적대적 재생이라는 문서의 구분을 확인했다. [그림과 생성 요약](formal-equity/comparison/summary.json)

## 성능 증거와 검사 수의 해석

[성능 원본](data/treasury-performance-2026-10-24.json)의 전후 모듈 여섯 개와 입력 두 개의 해시를 해당 Git blob과 대조했다. 일곱 쌍의 표본으로 중앙값·최솟값·최댓값을 독립 재계산했고, 측정 스크립트를 읽어 준비 실행 각 두 번, 교대 측정, 타이머 밖의 전체 결과 동등성 검사를 확인했다. 933.308815 → 699.941297 ms는 MSTR 세 조건과 첫 SVG 문자열 생성, 97.106032 → 12.737635 ms는 90일 구간의 20회 다시 그리기다. 네트워크·DOM layout·paint·사용자 입력 지연의 측정값으로 보고하지 않는다.

그 측정은 보존된 격리 패치에 대한 결과다. 뒤의 수치·UI 수정까지 포함한 전체 최종 코드의 동일한 속도 개선이라고 새로 측정한 것은 아니다. [보존된 성능 패치](data/treasury-performance-isolated.patch)가 재현 범위를 구분한다.

## 판정의 한계

실수 산술의 재무 항등식, 배정밀도 경계 검사의 유한 표본, 유한 상태 모델, 실제 브라우저와 미래 시장은 서로 다른 검증 대상이다. 이번 검토는 다음을 입증하지 않는다.
