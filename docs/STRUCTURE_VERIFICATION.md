## 2. 자동 검증

Node.js 24 환경에서 다음을 실행했다.

```sh
npm test
npm run verify:static
npm run build:standalone
node scripts/verify-static.mjs --standalone build/Bitcoin_Cycles_Comparison.html
```

- **9개 테스트 파일 모두 통과**, 실패 0. 이 개수는 Node의 파일 단위 집계이며 내부 검사항목 수와 다르다.
- 신규 시장 구조 파일의 검사항목 **10개**: 알려진 경로의 MDD, 윤년·부분 주, 피벗 발생일/확인일 구분, 미래 정보 불변성, 피보나치 확인 전 교차 제외, 완전 추적 조건 등.
- 신규 세부 경로 파일의 검사항목 **14개**: 과거 자료만 학습, seed 재현, 가격 단위 불변성, 주간 집계, 첫 전환 분포의 독립 구현 대조, 평가 자료와 학습 자료 분리, 누락된 평가 구간 제외 등.
- 정적 검사: **28개 파일, 42개 참조** 확인. GitHub Pages 하위 경로에서 해석할 수 있는 상대 경로를 사용한다.
- 단일 HTML: **17개 모듈·5,939개 관측값·스타일** 포함. 기본 생성물 2,366,665바이트. 가격 갱신과 외부 원문 열기를 제외한 분석 기능은 외부 요청 없이 동작하도록 묶었다.

최종 감사에서 평가창 내부의 누락일이 실제·모의 MDD 종료일을 달리 만들 수 있는 경계 사례를 수정했다. 해당 창을 명시적으로 제외하며, 동봉 원자료에는 누락일이 없어 발표 수치는 변하지 않았다.

독립 UI 감사에서 발견한 두 표시 문제를 수정했다. 전망의 국면 띠는 주봉 가격 표시에서도 일별 분류 간격 1일을 사용하여 겹침을 없앴다. 역사 주봉 분류는 별도 7일 간격을 사용한다. 상승 구간 내부 국면 일수 표는 항상 일별 분류라는 설명도 추가했다.

이번 검수는 데스크톱 브라우저에서 시행했다. 반응형 CSS는 포함했으나 별도 실제 모바일 기기 검수를 했다고 주장하지 않는다.

## 4. 모형 검증의 결과와 한계

새 경로는 128개 조건부 모의 경로에서 대표선을 고른다. 경로의 세부 움직임을 실제 과거 잔차 블록으로 만든다는 사실만으로 예측력이 생기지는 않는다.

- 과거 9개 기점·3개 거시 회차에서 **모든 기한의 MAPE가 가격 고정 기준 및 같은 거시 달력의 단순 연결 기준보다 컸다**.
- 2년·3년 평균 절대 로그오차는 가격 고정보다 작았지만 같은 거시 가정의 단순 연결 기준보다 컸다.
- 3년 평가는 6기점·2회차이며, 모의 10–90% 범위 안에 실제값이 든 사례는 2/6이다.
- 모형·평가 시점·매개변수 선택은 사후적이다. 기점의 겹침과 시장 구조 변화가 남는다.
- 전환 날짜 범위는 모의 경로의 경험 분위수다. 확률 보정된 구간이나 시장의 확정 일정이 아니다.
- 변동성 가정 0.75~1.25배에서 첫 고점 중앙일이 73일 달라진다.
- 48개월 달력, 거시 상승 구간의 내부 단계 비율, 표시창 밖 다음 저점 가격의 연결 조건은 설계 가정이다.

따라서 첫 화면에는 **“조건부 경로 · 예측 우위 미확인”**을 표시하고, 상세 검증을 접힌 영역에서 제공한다. 검증 실패를 숨기거나 미래 고저점의 수학적 증명이라고 명명하지 않았다.

## 5. 릴리스·배포의 확인 경로

공개 배포 대상은 [GitHub 저장소](https://github.com/twoimo/bitcoin-cycle-atlas)와 [GitHub Pages](https://twoimo.github.io/bitcoin-cycle-atlas/)이다. 원격 실행 결과는 [Actions](https://github.com/twoimo/bitcoin-cycle-atlas/actions), 태그의 정확한 소스와 산출물은 [Releases](https://github.com/twoimo/bitcoin-cycle-atlas/releases)에서 확인할 수 있다.

`main` 갱신은 CI와 Pages 빌드를 실행한다. `v*` 태그 또는 릴리스 발행은 테스트·정적 검사 뒤 HTML, PNG, 통합 연구 문서, 두 결과 JSON, 소스 ZIP, 메타데이터, 체크섬을 생성한다. 소스 ZIP은 UTC 시간대로 생성하여 실행 환경의 시간대 차이가 파일 바이트에 영향을 주지 않도록 했다. 동일 태그의 기존 산출물과 내용이 다르면 덮어쓰지 않고 실패한다.

배포 성공 여부는 위 실행 결과에서 확인해야 한다. 이 문서의 로컬 검증 기록 자체가 원격 작업 성공을 보증하지는 않는다.
